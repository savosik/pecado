# Клиентские сегменты

**Область:** Управление клиентской базой + синхронизация + ЛК

## Сегменты

| Уровень | Название | `client_status` | Скидка |
|---|---|---|---|
| 1 | Silver | `silver` | 10% |
| 2 | Gold | `gold` | 15% |
| 3 | Diamond | `diamond` | 20% |
| 4 | Индивидуальный | `individual` | Разная |

!!! note "Открытый вопрос"
    Окончательные названия уровней — открытый вопрос (отв.: Лена)

## Механизм синхронизации (v11)

Сегмент передаётся через `partner.created` (без нового события `partner.updated`).

### Сторона 1С

1. При записи/изменении типового соглашения → `partner.created` с `client_status`
2. Значение = наименование соглашения (lowercase, латиница)
3. Нет соглашения → `client_status = null`
4. Массовая выгрузка включает актуальный `client_status`

### Сторона сайта

1. Обработчик получает `client_status` из payload
2. Не `null` → ищет `ClientStatus` по `external_id`
3. Найден → привязывает к `user.client_status_id`
4. `null` → сбрасывает `client_status_id`
5. Не найден → логирует предупреждение, не меняет текущий статус

### Подготовка данных

Перед первоначальной выгрузкой создать в админке:

| Название | `external_id` |
|---|---|
| Silver | `silver` |
| Gold | `gold` |
| Diamond | `diamond` |
| Индивидуальный | `individual` |

## Отображение в ЛК

Плашка со статусом (название + изображение из `ClientStatus`)

## Критерии приёмки

- [ ] 1С отправляет `client_status` в `partner.created` при изменении соглашения
- [ ] Сайт резолвит через `ClientStatus.external_id`
- [ ] `null` → сброс статуса
- [ ] Неизвестный `client_status` → предупреждение
- [ ] Плашка статуса в ЛК
