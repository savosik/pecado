> **AsyncAPI:** [Полная спецификация](/docs/erp/spec.yaml)  
> **Задание разработчику 1С:** [Себестоимость: что сделать в 1С](../guides/cost-price-for-1c.md)

## Себестоимость товара (cost.updated)

**Направление:** 1С → Сайт | **Очередь:** `erp_in.prices` | **Routing key:** `cost.updated`

Себестоимость нужна сайту для отчётов по прибыли и марже и для контроля продаж ниже
себестоимости. Клиенту она не показывается никогда.

### Бизнес-правила

- Себестоимость приезжает **отдельным событием** `cost.updated`. Через `product.updated`
  и `price.updated` она не обновляется — так же, как цена не обновляется через
  `product.updated` (см. [Цены](prices.md)).
- Товар ищется по `product_uuid` (`products.external_id`). Если товар не найден —
  событие игнорируется без ошибки.
- Скрытые товары (снятые с публикации) себестоимость получают наравне с остальными:
  она нужна для отчётов по уже отгруженным документам.
- Сайт **не** отправляет себестоимость в 1С.
- Событие идемпотентно по `message_id`: повторная доставка того же сообщения ничего
  не меняет.

#### ⚠️ Только рубли

Сайт хранит себестоимость в рублях, поле валюты у товара отсутствует (базовая цена
тоже рублёвая). Поле `currency_code` можно не присылать; если оно присутствует
и отличается от `RUB`, сообщение отбрасывается с предупреждением в лог и значение
в БД **не записывается** — молча пересчитывать по курсу сайт не будет, иначе
себестоимость «поплывёт» вместе с курсом задним числом.

#### ⚠️ Себестоимость присылается агрегатом, без разреза по организациям и складам

**Требование контракта** (зафиксировано в v15.13.0).

Сообщение `cost.updated` содержит одно значение на товар. Раздельная себестоимость
по организациям, складам или партиям **не передаётся**: сайт хранит одно значение
и перезаписывает его каждым сообщением, поэтому второе значение молча затёрло бы первое.

То же ограничение действует для цен — см. [Цены](prices.md) — и для остатков —
см. [Остатки](stocks.md). Разрез по организациям существует только в документах
и взаиморасчётах, см. [Организации](organizations.md).

### Фиксация в реализациях

Себестоимость меняется во времени, а реализация — исторический документ. Поэтому
в момент создания строки реализации сайт **сам** копирует текущее значение
`products.cost_price` в строку документа (снимок). Дальнейшие `cost.updated`
уже проведённые реализации не переписывают — отчёт за прошлый месяц остаётся
таким же, каким был.

Тот же механизм, что у снимков наименования товара и бренда — см.
[Реализации](shipments.md).

**Следствие для исторических документов:** у реализаций, проведённых до внедрения
v15.13.0, снимок себестоимости пуст и останется пустым — восстанавливать его не из чего,
истории себестоимости не существует ни на сайте, ни в контракте. Прибыль по ним
не считается.

### Кто видит себестоимость

| Канал | Видимость |
|---|---|
| Админка `/admin` — карточка товара | Только с правом `product-costs.view` (супер-админ, закупщик) |
| CRM `/crm` | Пока нигде. Руководитель отдела продаж получит себестоимость вместе с отчётом по марже — отдельным правом `crm-product-costs.view`: роль `sales-head` намеренно CRM-only, и админский ресурс `product-costs` открыл бы ей вход в `/admin` |
| Личный кабинет клиента, каталог, поиск | **Нет** |
| Выгрузки товаров, фиды маркетплейсов, клиентские API | **Нет** |
| Аналитический MCP (`bi_agent`) | **Нет** — колонка скрыта вьюхой |

### Критерии приёмки

- [ ] Сайт принимает `cost.updated` и обновляет себестоимость товара по UUID
- [ ] Если товар не найден — событие игнорируется без ошибок
- [ ] Себестоимость в валюте, отличной от `RUB`, не записывается
- [ ] Отрицательная себестоимость отклоняется валидацией схемы
- [ ] Повторная доставка сообщения с тем же `message_id` ничего не меняет
- [ ] При создании строки реализации себестоимость фиксируется снимком
- [ ] Последующие `cost.updated` снимок в проведённой реализации не меняют
- [ ] Себестоимость не попадает в каталог, поиск, выгрузки и клиентские API
