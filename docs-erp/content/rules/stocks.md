# Остатки

> **JSON Schema:** [`stock.updated.json`](/docs/erp/schemas/stock.updated.json)  
> **AsyncAPI:** [Полная спецификация](/docs/erp/spec.yaml)

**Направление:** 1С → Сайт | **Очередь:** `erp_in.stock`

## Бизнес-правила

- `quantity` = ВНаличии − КОтгрузке. Отрицательные значения приводятся к 0
- Склады заводятся в админке сайта вручную с привязкой к UUID
- Пользователь привязан к региону; склады делятся на «для заказа» и «для предзаказа»
- 1С отправляет остатки по всем организациям в разрезе складов
- Клиент не может заказать больше свободных остатков на доступных складах

## ⚠️ Остаток присылается агрегатом по складу

**Требование контракта, а не деталь реализации** (зафиксировано в v15.8.0, подтверждено
стороной 1С).

Одно сообщение `stock.updated` содержит **суммарный** остаток товара на складе по всем
нашим организациям. Раздельные сообщения по организациям на один и тот же склад
**недопустимы**.

Причина: сайт пишет остаток **перезаписью** по ключу (товар, склад). Если по одному складу
придут два сообщения — по одной организации в каждом, — второе затрёт первое, и наличие
на витрине окажется занижено. Ошибка при этом будет молчаливой: сообщения валидны,
в логах чисто, а товар просто не продаётся.

Того же требования придерживаются и цены — см. [Цены](prices.md). Организация как разрез
существует только в документах и взаиморасчётах, см.
[Организации](organizations.md).

## Критерии приёмки

- [ ] Сайт принимает `stock.updated` и обновляет остаток товара на складе
- [ ] Склады привязаны к регионам через `region_warehouse`
- [ ] Если товар или склад не найдены — событие игнорируется
