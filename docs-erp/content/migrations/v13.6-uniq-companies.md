# Миграция v13.6: устранение дублей контрагентов

> **Контекст:** регрессия инцидента 2026-04-25 — 3093 дубля контрагентов
> на dev из-за того, что 1С присылала `order.created` без UUID контрагента,
> а сайт безусловно создавал новую `Company` без проверки уникальности.

## Что меняется

### Контракт API (BREAKING)

| Событие | Было | Стало |
|---|---|---|
| `order.created` | `partner_uuid` optional, `contractor` nullable | `partner_uuid` required, `contractor` required (с `uuid`, `tax_id`) |
| `shipment.created` | `contractor_uuid` optional | `contractor_uuid` required |
| `shipment.updated` | `contractor_uuid` optional | `contractor_uuid` required |

### Структура БД

- `companies.tax_code` теперь `NOT NULL DEFAULT ''` (раньше nullable).
- Добавлен `UNIQUE(tax_id, tax_code, deleted_at)` — защита от дублей
  на уровне БД.
- `deleted_at` в составном UNIQUE компенсирует особенность MySQL: NULL в
  индексе считается distinct, поэтому soft-deleted Company не блокируют
  пересоздание.

### Алгоритм матчинга в обработчиках

- Fallback по `tax_id + tax_code` **без** фильтра `user_id` (ИНН/КПП
  юридически уникальны). Это позволяет найти Company даже если она ещё
  не привязана к партнёру.
- Поиск выполняется внутри `DB::transaction` с `lockForUpdate()` —
  защита от race-condition при параллельной обработке.
- Soft-deleted Company восстанавливается (`restoreQuietly`), а не
  дублируется при повторном получении события.

## План применения

### 1. Pre-flight: проверить отсутствие дублей

```bash
# Найти все ИНН с дублями (среди активных Company):
docker exec pecado-app php artisan tinker --execute="DB::table('companies')->select('tax_id','tax_code',DB::raw('COUNT(*) as cnt'))->whereNull('deleted_at')->whereNotNull('tax_id')->groupBy('tax_id','tax_code')->having('cnt','>',1)->get()->dd();"
```

Если результат не пустой — нужен cleanup перед миграцией.

### 2. Адресный cleanup дублей

Для каждого ИНН с дублями (если их немного):

```bash
# Сначала dry-run — посмотреть что будет удалено:
docker exec pecado-app php artisan erp:cleanup-contractor-by-tax-id {ИНН} --dry-run

# Применить:
docker exec pecado-app php artisan erp:cleanup-contractor-by-tax-id {ИНН} --force
```

Команда удаляет **все** Company с указанным ИНН (включая soft-deleted)
и каскадно удаляет связанные Order через FK `orders.company_id ON DELETE CASCADE`.
`shipments.company_id` и `contractor_balances.company_id` имеют `SET NULL` —
останутся, просто отвязанные.

### 3. Применить миграцию

```bash
docker exec pecado-app php artisan migrate
```

Миграция:

1. Backfill `tax_code` NULL → `''`.
2. Pre-flight check — если остались дубли, миграция падает с подсказкой.
3. `tax_code` → NOT NULL DEFAULT ''.
4. Добавление UNIQUE-индекса.

### 4. Согласовать с 1С новый контракт

После применения миграции 1С **обязана** слать:

- `order.created` с заполненным `partner_uuid` и блоком `contractor` (с `uuid` и `tax_id`).
- `shipment.created` / `shipment.updated` с заполненным `contractor_uuid`.

Сообщения без обязательных полей будут отклонены валидатором (`ErpMessageValidator`)
и записаны в `erp_validation_errors` без обработки.

## Откат

```bash
docker exec pecado-app php artisan migrate:rollback --step=1
```

Откат снимает UNIQUE-индекс и возвращает `tax_code` в nullable. Удалённые
дубли восстановить нельзя — но это и не нужно, они были ошибочными.
