    Тест-план: Заказы в резерве (v16.9.0)¶

    Критерии приёмки режима резерва. Обязательные интеграционные прогоны перед включением (раскатка за флагами обеих сторон, см. правила: Заказы в резерве).

    Р-1. Создание резерва¶

    • [ ] order.created с reserve: true, reserved_until (в пределах 24 ч) → в 1С документ со строками «Резервировать на складе», статус «К выполнению»; ответный order.updated несёт reserve: true, тот же reserved_until, items_version.
    • [ ] reserved_until дальше предела 1С → удержание до предела, в ответе фактический (урезанный) reserved_until.
    • [ ] reserve: true по партнёру-неучастнику (reserve_allowed: false) → обычный заказ, ответ с reserve: false.
    • [ ] reserved_until в прошлом → обычный заказ (reserve: false).
    • [ ] reserve: true без reserved_until → сообщение не проходит валидацию схемы на сайте, в шину не публикуется.
    • [ ] Остаток: после постановки в резерв stock.updated уменьшает публикуемый остаток на зарезервированное количество.

    Р-2. Правка состава¶

    • [ ] order.updated (сайт → 1С) с уменьшением количества и актуальным base_items_version → состав в 1С заменён, ответный order.updated с новым items_version.
    • [ ] Удаление строки → строка исчезает из документа, резерв по ней освобождён.
    • [ ] Отставший base_items_version (менеджер успел изменить состав в 1С) → правка НЕ применена, ответ с актуальным составом, items_version и conflict.rejected_message_id = message_id отклонённого сообщения.
    • [ ] Повторная доставка того же order.updated (тот же message_id) → состояние не меняется повторно.

    Р-3. Отмена¶

    • [ ] order.deleted с reason: client_cancelled → строки отменены, статус «Закрыт», пометки удаления НЕТ, резерв освобождён, остаток вернулся в stock.updated.
    • [ ] order.deleted с reason: reserve_expired — то же, причина отмены строк различима в 1С.
    • [ ] Повтор order.deleted по отменённому заказу → успех без изменений.

    Р-4. Подтверждение¶

    • [ ] order.confirmed → строки «Отгрузить», статус «К отгрузке», заказ уходит в обычный конвейер (при включённом авто-оформлении — расходный ордер).
    • [ ] Повтор order.confirmed по подтверждённому заказу → успех без изменений.
    • [ ] order.confirmed по заказу, уже отменённому по таймауту (гонка) → заказ остаётся отменённым, сайт получает актуальное состояние ответным сообщением.

    Р-5. Гейты и аварийные пути¶

    • [ ] Авто-оформление отгрузки НЕ подхватывает резервный заказ до order.confirmed (контрагент с включённым авто-оформлением).
    • [ ] Ручной перевод резервного заказа менеджером в 1С → сайт получает order.updated с reserve: false, убирает заказ из раздела резервов, клиентские правки закрыты.
    • [ ] Страховочный регламент 1С: заказ с reserved_until + 6 ч в прошлом и без отмены от сайта → резерв снят регламентом, сайт получает order.deleted или order.updated с reserve: false.

    Р-6. Охват¶

    • [ ] partner.updated с reserve_allowed: true → сайт открывает выбор резерва в чекауте партнёру; с false — закрывает (висящие резервы доживают штатно).
    • [ ] Поимённая сверка: список uuid от сайта → 1С размечает реквизит → сайт получил partner.updated по каждому размеченному партнёру.
