    AsyncAPI: Полная спецификация

    Направления обмена¶

    Событие Направление Очередь
    category.created 1С → Сайт erp_in.catalog
    category.updated 1С → Сайт erp_in.catalog
    product.created 1С → Сайт erp_in.catalog
    product.updated 1С → Сайт erp_in.catalog

    Категории¶

    Бизнес-правила¶

    • Родительская категория создаётся до дочерней (BFS-обход по уровням)
    • Фильтрация по ВыгружатьНаСайт вида номенклатуры — если Ложь, товары этого вида не выгружаются
    • (v12) is_active (boolean) — управление активностью категории из 1С. Если false — категория и её товары скрыты на сайте
    • (v12) is_group удалён из протокола обмена — это внутренний атрибут сайта, не передаётся из 1С

    Критерии приёмки¶

    • [ ] При записи вида номенклатуры с ВыгружатьНаСайт = Ложь событие category.created/updated не отправляется
    • [ ] При массовой выгрузке товары с ВыгружатьНаСайт = Ложь пропускаются
    • [ ] (v12) При is_active = false категория не отображается на сайте
    • [ ] (v12) При is_active = true категория отображается на сайте
    • [ ] (v12) Поле is_group из payload не влияет на обработку (игнорируется)

    Товары (product.created)¶

    Бизнес-правила¶

    • brand содержит поле label (дублирует name)
    • model — nullable. Источник — доп. реквизит из настройки СвойствоМодель
    • (v10) hidden = true → товар не отображается (ни в каталоге, ни в поиске)
    • (v12.9) is_marked (boolean) — признак маркированного товара («Честный знак»). Сохраняется в products.is_marked. Строго true/false, строки "Да"/"Нет" отклоняются JSON-парсером
    • (v13) attributes — полный актуальный список атрибутов товара (семантика full-replace). При создании 1С всегда передаёт полный набор; атрибуты, отсутствующие в массиве, у товара не будут созданы
    • (v13.1) description — краткое/plain-text описание, сохраняется в products.description
    • (v13.1) description_html — HTML-версия описания (rich-text), сохраняется в products.description_html. Полностью перезаписывает поле; null или пустая строка очищают его. Используется на карточке товара и в выгрузках (приоритет description_html > description)
    • (v13.3) Габариты, вес и классификация — восемь опциональных полей (см. раздел «Габариты, вес и классификация (v13.3)»). Если поле не передано — пишется null
    • (v13.10) Опциональные аудит-метки erp_created_at / erp_updated_at (ISO-8601 datetime с TZ) — момент создания/изменения номенклатуры в 1С. Сохраняются в products.erp_created_at / products.erp_updated_at и отображаются в админке товара. Поля не required: payload без них принимается, существующие колонки не перезаписываются. Подробнее: «Аудит-метки 1С: erp_created_at / erp_updated_at»

    Критерии приёмки¶

    • [ ] Товар создаётся с привязкой к категории по category_uuid
    • [ ] Бренд создаётся/обновляется по uuid
    • [ ] Атрибуты создаются из attributes[]
    • [ ] Товары с hidden = true не видны на сайте
    • [ ] (v12.9) При is_marked = true товар помечен как маркированный в БД сайта (products.is_marked = 1)
    • [ ] (v12.9) При is_marked = false флаг снимается (products.is_marked = 0)
    • [ ] (v13) 1С передаёт полный список атрибутов; сайт сохраняет их и удаляет прежние связи товара с атрибутами, отсутствующими в массиве
    • [ ] (v13.1) Поле description_html сохраняется в products.description_html; null/пустая строка очищают поле

    Товары (product.updated) — частичное обновление¶

    Бизнес-правила¶

    • Отправляет только изменённые поля. Обязательны: event, message_id, uuid
    • Цена не обновляется через product.updated — используйте price.updated
    • (v12.9) is_marked обновляется только если поле присутствует в payload. Отсутствие поля сохраняет текущее значение
    • (v13.1) description_html обновляется только если поле присутствует в payload. Если передано (включая null или пустую строку) — products.description_html перезаписывается; отсутствие поля оставляет текущее значение нетронутым
    • (v13.3) Поля габаритов, веса и классификации (weight_gross, weight_net, width, height, depth, hs_code, abc_xyz, turnover) обновляются по тому же принципу частичного обновления: отсутствие поля в payload оставляет текущее значение, передача null очищает поле
    • (v13.10) Опциональные аудит-метки erp_created_at / erp_updated_at. При обновлении достаточно передавать только erp_updated_at — erp_created_at уже зафиксирован в момент product.created. Поля не required, отсутствие в payload не перезаписывает существующие значения. Подробнее: «Аудит-метки 1С: erp_created_at / erp_updated_at»
    • (v13) attributes — особая семантика full-replace, отличающаяся от остальных полей:
      • отсутствие поля attributes в payload → состав атрибутов не трогаем (например, обновление только name)
      • attributes: [] → удалить все атрибуты у товара
      • attributes: [...] → полная замена: атрибуты, отсутствующие в массиве, удаляются у товара
      • если обновление затрагивает состав/значения атрибутов, 1С обязана передавать полный актуальный список, а не только изменённые

    Критерии приёмки¶

    • [ ] Частичное обновление — неизменённые поля сохраняются
    • [ ] При изменении hidden отправляется product.updated с полем hidden
    • [ ] (v12.9) При изменении признака маркировки отправляется product.updated с полем is_marked, сайт применяет новое значение к products.is_marked
    • [ ] (v13.1) При изменении HTML-описания отправляется product.updated с полем description_html, сайт применяет новое значение к products.description_html
    • [ ] (v13.1) Если поле description_html в payload отсутствует — products.description_html не изменяется
    • [ ] (v13) Если поле attributes в payload отсутствует — product_attribute_values товара не изменяются
    • [ ] (v13) Если attributes: [] — все связи товара с атрибутами удаляются
    • [ ] (v13) Если attributes содержит полный список — записи в product_attribute_values, отсутствующие в массиве, удаляются

    Габариты, вес и классификация (v13.3)¶

    В версии 13.3.0 в события product.created / product.updated добавлены восемь опциональных системных полей, описывающих физические характеристики товара (для расчёта стоимости доставки и выгрузок на маркетплейсы) и аналитические показатели (для отчётности и приоритизации поставок).

    Поля payload¶

    Поле Тип Источник 1С Колонка БД Единицы Пример
    weight_gross number, nullable Упаковки.Вес (первая непомеченная упаковка) products.weight_gross decimal(10,3) кг 1.250
    weight_net number, nullable Номенклатура.ЕдиницаИзмерения.Вес products.weight_net decimal(10,3) кг 1.000
    width number, nullable Упаковки.Ширина products.width decimal(10,2) м 0.32
    height number, nullable Упаковки.Высота products.height decimal(10,2) м 0.12
    depth number, nullable Упаковки.Глубина products.depth decimal(10,2) м 0.08
    hs_code string, nullable, ≤20 Номенклатура.КодТНВЭД.Код products.hs_code varchar(20) — "6204620000"
    abc_xyz string, nullable, ≤5 Классификация ABC/XYZ products.abc_xyz varchar(5) — "AX"
    turnover number, nullable Коэффициент оборачиваемости products.turnover decimal(12,4) — 14.7500

    Примечание: legacy-поле tnved (varchar) сохраняется в БД для обратной совместимости со старыми сценариями выгрузок. Новый нормализованный код обмена живёт отдельно в колонке hs_code.

    Бизнес-правила¶

    • Все восемь полей опциональны в обеих событиях (product.created и product.updated)
    • Числовые значения должны быть ≥ 0. Отрицательные значения отбрасываются и сохраняются как null
    • В product.created отсутствующее поле → пишется null
    • В product.updated действует семантика частичного обновления (см. правила выше): отсутствие поля → не трогаем, передача (включая null) → перезаписываем

    Критерии приёмки¶

    • [ ] (v13.3) Поля weight_gross, weight_net, width, height, depth сохраняются в соответствующие decimal-колонки products с заявленной точностью
    • [ ] (v13.3) hs_code, abc_xyz сохраняются в строковые колонки и обрезаются по максимальной длине (20 / 5)
    • [ ] (v13.3) turnover сохраняется как decimal(12, 4)
    • [ ] (v13.3) Если поле не передано в product.created — соответствующая колонка null
    • [ ] (v13.3) В product.updated отсутствие любого из восьми полей сохраняет текущее значение
    • [ ] (v13.3) В product.updated передача null очищает соответствующее поле
    • [ ] (v13.3) В админке товара (/admin/products/{id}/edit) есть вкладка «Габариты и логистика» с тремя секциями: «Вес», «Габариты упаковки», «Классификация»

    Аудит-метки 1С (v13.10)¶

    В версии 13.10.0 в события product.created / product.updated добавлены два опциональных поля erp_created_at и erp_updated_at — момент создания/изменения номенклатуры в 1С (ISO-8601 datetime с TZ). До v13.10 на сайте была только локальная products.created_at (момент первой обработки сообщения от 1С), что не позволяло отделить «когда товар создали в 1С» от «когда он впервые приехал на сайт» — особенно после массовой первичной выгрузки, где у тысяч товаров created_at оказывался одной датой.

    Поля payload¶

    Поле Тип Источник 1С Колонка БД Пример
    erp_created_at string ISO-8601, nullable Номенклатура.Дата (или регистр версионирования) products.erp_created_at timestamp NULL "2024-09-15T11:42:00+03:00"
    erp_updated_at string ISO-8601, nullable Дата последней регистрации изменения объекта products.erp_updated_at timestamp NULL "2026-04-26T14:08:33+03:00"

    Бизнес-правила¶

    • Оба поля опциональны в обеих событиях (product.created и product.updated)
    • В product.created отсутствие поля → колонка остаётся null
    • В product.updated действует семантика частичного обновления: отсутствие поля → колонка не трогается; передача (включая null) → перезаписываем
    • В product.updated достаточно передавать только erp_updated_at — erp_created_at уже сохранён при product.created
    • TZ-нормализация: cast App\Casts\ErpDatetime приводит любой ISO-8601 (+03:00, Z, +05:00) к app.timezone (Europe/Moscow) и сохраняет в БД как Y-m-d H:i:s без TZ-маркера. Стенограмма в БД и в админке совпадает с тем, что менеджер видит в 1С
    • Колонки в админке товара отображаются read-only — это аудит-метки 1С, сайт ими не владеет

    Критерии приёмки¶

    • [ ] (v13.10) Если product.created содержит erp_created_at / erp_updated_at — значения сохраняются в products.erp_created_at / products.erp_updated_at
    • [ ] (v13.10) Если поля отсутствуют в product.created — колонки products.erp_* остаются null
    • [ ] (v13.10) В product.updated отсутствие поля сохраняет текущее значение колонки
    • [ ] (v13.10) В product.updated передача null очищает соответствующее поле
    • [ ] (v13.10) Любая входящая TZ нормализуется к Europe/Moscow без потери стенограммы
    • [ ] (v13.10) В админке товара (/admin/products/{id}/edit) на вкладке «Основные данные» отображаются read-only поля «Создано в 1С» / «Изменено в 1С». Если значение null — выводится «—»
