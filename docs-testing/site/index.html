    Ручной тест-план сайта Pecado (B2B-клиент)¶

    Версия: 2.0 (переход на MkDocs) Дата последнего обновления: 2026-04-21 Среда тестирования: http://dev.pecado.ru

    О чём этот документ¶

    Это пошаговый план ручного тестирования сайта Pecado глазами реального B2B-клиента — оптового закупщика, владельца секс-шопа, маркетплейс-селлера. Тестировщик играет эту роль от первого знакомства с сайтом до повторных закупок, возвратов и автоматических выгрузок.

    Документ собирается из отдельных markdown-файлов в docs-testing/content/ и публикуется автоматически при каждом деплое в dev. Если в коде что-то меняется — правится соответствующий .md, и через несколько минут актуальная версия доступна по тому же URL.

    Структура¶

    Раздел Назначение
    Порядок работы Как проходить план: обозначения, замечания, приёмы
    Багрекер Встроенный виджет — главный способ подавать замечания
    Обмен с 1С Почему иногда «задержка» — это не баг
    Устройства и браузеры На чём проходим план
    Подготовка Доступы к сервисам, тестовые данные, инструменты
    Этапы тестирования Жизненный путь B2B-клиента, пошагово
    Edge-кейсы Нестандартные сценарии и регрессия
    Итоги Сводка, дефекты, подпись тестировщика

    С чего начать¶

    1. Прочитать порядок работы и инструкцию по багрекеру.
    2. Собрать доступы и тестовые данные — это займёт 10 минут и сэкономит час.
    3. Начать с ЭТАП 0. Гость — это лёгкий вход, без логина.
    4. Идти последовательно: каждый следующий этап опирается на результат предыдущего.

    Связанные ресурсы¶

    Ресурс URL Для кого
    Публичный API (Scramble) /docs/api Документация REST-эндпойнтов сайта
    ERP-интеграция (гайд) /docs/erp-guide/ Бизнес-правила обмена с 1С
    AsyncAPI (интерактивная) /docs/erp/ Payload-ы очередей RabbitMQ
    Mailpit localhost:8025 через SSH-туннель Все письма, которые отправляет сайт. Подробности — в подготовке
    RabbitMQ Management localhost:15672 через SSH-туннель Проверка сообщений в очередях. Подробности — в подготовке
    Health-check /health Жив ли сайт, БД, Redis, Horizon

    Для разработчика¶

    Исходники этого документа — в директории docs-testing/content/. Правки принимаются обычными PR. Локальная сборка:

    docker exec pecado-app mkdocs build -f mkdocs-testing.yml --strict

    Деплой — автоматический через .github/workflows/deploy-dev.yml при пуше в ветку dev.
