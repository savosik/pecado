# ЭТАП 8. Оформление заказа

!!! abstract "Сценарий"
    Клиент готов купить. Пусть в корзине **есть и товары в наличии, и на предзаказ** — это нужный тест-кейс.

## 8.1. Страница оформления

URL: `/checkout`

- [ ] Хлебные крошки: Главная → Корзина → Оформление заказа
- [ ] **Две отдельные таблицы**: «Товары со склада» (зелёная) и «Товары по предзаказу» (оранжевая). Если в корзине есть оба типа — обе должны отобразиться
- [ ] Итоговая сумма крупным шрифтом, «Ваша выгода» (при скидке)
- [ ] **Выбор компании**:
    - [ ] Выпадашка со всеми компаниями клиента
    - [ ] Если компания одна — выбрана автоматически
    - [ ] Кнопка «Создать компанию» — inline форма (название, ИНН) или модальное окно
- [ ] **Выбор адреса доставки**:
    - [ ] Радио-кнопки со всеми адресами клиента
    - [ ] Опция «Использовать новый адрес» — раскрывается поле ввода
- [ ] **Комментарий к заказу** (textarea)
- [ ] Кнопки «← Вернуться в корзину» и **«Оформить заказ»**

## 8.2. Валидация оформления

- [ ] Без выбора компании → ошибка «Выберите компанию»
- [ ] Без выбора адреса → ошибка
- [ ] Пустой комментарий — допустим

## 8.3. Успешное оформление

- [ ] Нажать «Оформить заказ»
- [ ] **[!]** Заказ создался, произошёл редирект на `/cabinet/orders/{id}` или аналогичную
- [ ] Видно: номер заказа, статус (обычно «Ожидает»), тип (Заказ / Предзаказ), дата, сумма, компания, адрес, комментарий
- [ ] В таблице товаров — все позиции с ценами и скидками
- [ ] Timeline / история статусов — минимум одна запись «Создан»
- [ ] Активная корзина **очищена** или **удалена** (если была создана под заказ)

!!! info "Проверка в RabbitMQ (опционально)"
    После оформления заказа в очередь `erp_out.orders` должно попасть сообщение — сайт отправляет заказ в 1С. Проверка — через SSH-туннель на RabbitMQ Management (см. [Подготовка → RabbitMQ](../intro/prep.md#rabbitmq-management-ui)).

## 8.4. Конфликт остатков

Смоделируйте ситуацию: тестовый партнёр списал остатки перед оформлением.

- [ ] Попробовать оформить заказ, когда на складе меньше, чем в корзине
- [ ] Ожидается тост / ошибка: «Товар … больше недоступен в требуемом количестве»
- [ ] Клиент может уменьшить количество и повторить
