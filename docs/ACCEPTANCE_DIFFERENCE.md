## US-01: Активация и деактивация пользователей

| # | Что изменилось | Текущий файл | Новая версия |
|---|---|---|---|
| 1 | Схема обмена | Менеджер создаёт партнёра в 1С → 1С отправляет `partner.created` на сайт (1С → Сайт) | Новая схема: Сайт → Битрикс24 (API) → менеджер аппрувит → Битрикс24 webhook → Сайт активирует → Сайт → RabbitMQ → 1С (`partner.created`) |
| 2 | Направление `partner.created` | 1С → Сайт | **Сайт → 1С** (инвертировано!) |
| 3 | Формат `partner.created` | `{ event, uuid, login }` | `{ event, uuid, login, name, phone, email }` — добавлены поля `name`, `phone`, `email` |
| 4 | Критерий: обработка `partner.created` | Сайт принимает, находит по логину, активирует, сохраняет UUID | 1С принимает, находит по логину, если не найден — создаёт |
| 5 | Новый критерий | Отсутствует | Сайт ловит webhook из Битрикс24 и переводит пользователя в статус «Активен» |
| 6 | Новый критерий | Отсутствует | Анкета при регистрации — опциональная |
| 7 | Новый критерий | Отсутствует | Один пользователь = одна компания (мультипользовательство — в следующем скопе) |
| 8 | Примечание | Нет | Добавлено: Партнёр в 1С = физическое лицо; Контрагент = юридическое лицо |

> ⚠️ **КРИТИЧНО:** Принципиальное изменение архитектуры. `partner.created` теперь Сайт → 1С (а не 1С → Сайт). Весь текущий код обработчика входящего события нужно переделать в публикатор исходящего события.

## US-11, US-12, US-13 — Новые разделы (отсутствуют в текущем файле)

| **US-11** | Синхронизация сегментов номенклатуры | События: `product_segment.created/updated/deleted`. Сегменты товаров many-to-many. Используются для расчёта скидок. |

## Инфраструктура RabbitMQ — изменения

Новая версия указывает «без изменений», однако при реализации US-11, US-12, US-13 потребуется добавить новые очереди/routing keys для:
- `product_segment.*`
- `partner_segment.*`
- `category.*`, `product.*` (для каталога)

Текущий файл не содержит этих очередей — **обновление инфраструктуры RabbitMQ обязательно**.
