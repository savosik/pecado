## 2. `settled_amount` — вариант 1, с явным правилом

Принимаем ваш выбор. Формализуем, чтобы не было разночтений при реализации.

**По реализациям** — как договорились: `settled_amount` по каждой строке графика, источник
`РасчетыСКлиентамиПоСрокам`. Сайт ничего не раскладывает.

**По заказам** — `payment_schedule.updated` с `document_kind: "order"`:

- в `lines[]` только плановые суммы и даты, `settled_amount` **не передаётся**;
- в шапке новое поле **`document_settled_amount`** — сколько оплачено по заказу целиком
  (ресурс `Оплачивается` / остаток по объекту расчётов). Это авторитетная величина.

Правило на нашей стороне, записываем в документацию:

> Оплаченная сумма заказа берётся из `document_settled_amount` и **никогда не вычисляется**.
> Разнесение этой суммы по этапам графика — только для отображения календаря, помечается
> производной величиной и **не участвует ни в балансе, ни в сверке**.

Почему это не возврат к прежней болезни. Прошлое FIFO раскладывало платежи **между документами**:
аванс по заказу гасил строки графика чужих реализаций, ошибка накапливалась и дала 5,53 млн
вместо 478 тысяч. Здесь раскладывается авторитетное число **внутри одного заказа**, обычно
по одному-двум этапам. Итог по заказу всегда верен по построению; неточной может быть только
дата внутри заказа, и на баланс это не влияет вовсе.

Вариант 2 (поэтапный остаток по заказам) не берём: новая учётная логика в 1С ради уточнения
даты внутри документа не окупается.
