## Главное про волну 1

Волна 1 работает **только в режиме показа**. Ни одна промо-позиция не попадает в корзину
и не уходит в 1С. Если во время теста товар «в подарок» окажется в корзине или в заказе —
это баг, а не успех.

Режим «Выдавать промо-позиции» намеренно заблокирован: он включится в волне 2 вместе со
складским учётом промо.

## Подготовка

### П1. Данные для правила

Понадобятся:

- **2–3 товара одного бренда** с ненулевой ценой — они станут условием акции;
- **1 товар** — он станет наградой (промо-позицией). Важно: **он не должен входить в
  условие**, иначе правило не сохранится (это осознанная проверка);
- клиент с индивидуальными ценами — на нём проверяется, что порог считается по цене
  клиента, а не по базовой.

Запишите артикулы, они понадобятся почти во всех кейсах:

| Роль | Артикул | Название | Цена клиента |
|---|---|---|---|
| Условие 1 | | | |
| Условие 2 | | | |
| Награда | | | |

### П2. Учётные записи

База боевая, поэтому логины и пароли — боевые. На стенде есть три super-admin:
`savosik@pecado.ru`, `info@oootlk.ru`, `buyimp@pecado.ru`.

| Роль | Что должно быть доступно |
|---|---|
| super-admin | весь раздел «Правила акций» |
| контент-менеджер | только просмотр списка правил, без кнопки «Создать» |
| обычный клиент | корзина и каталог, админка недоступна |

Для проверки прав (кейс А3) удобнее не заводить нового пользователя, а временно снять
у своей учётки роль super-admin — либо взять существующего контент-менеджера из базы.

## Блок Б. Конструктор правила

### Б1. Создание правила «сумма по бренду → подарок»

Под super-admin: **Правила акций → Создать правило**.

**Вкладка «Основное»:**

1. Название: `ТЕСТ: подарок за 10 000 ₽`.
2. Акция-лендинг: `Без привязки`.
3. Режим: убедиться, что **«Выдавать промо-позиции» задизейблен**, под ним — пояснение
   про складской учёт. Оставить «Только показывать».
4. Приоритет: `10`. «Правило включено» — **включить**.

**Вкладка «Условия»:** → «Добавить условие».

5. «Вся корзина» — выключено.
6. В «Товары» найти и добавить товары **Условие 1** и **Условие 2** из таблицы П1.
7. Под селектором должна появиться подсказка **«Сейчас под условие подходит товаров: 2»**.
8. «Считать» → **Сумму**. Сравнение → «не меньше (≥)». Порог → `10000`.

**Вкладка «Награды»:** → «Добавить награду».

9. «Что выдаём» → **Конкретный товар**, выбрать товар **Награда**.
10. Количество `1`, цена промо-позиции `0`.
11. Вид → **Подотчётная**. Склад-источник → любой обычный склад.
12. Кратность → **Один раз при достижении порога**.
13. Проверить: при цене `0` переключателя **«Клиент может отказаться» нет**, вместо него
    текст, что бесплатную позицию отклонить нельзя.
14. Поставить цену `40` → переключатель **появился**. Вернуть `0` → **исчез**.

15. Сохранить.

**Ожидаем:** правило создано, тост об успехе, в списке — строка с человекочитаемым
условием вида «Сумма товаров «…», «…» ≥ 10 000 ₽» и наградой «… × 1 за 0 ₽».
Статус — **«Активно»**, режим — **«Только показ»**.

- [ ] Пройден

- [ ] Пройден

### В2. Порог достигнут

1. Увеличить количество в корзине так, чтобы сумма перевалила порог.
2. Повторить предпросмотр.

**Ожидаем:** «Правило сработало», в «Что было бы выдано» — товар-награда, количество 1,

## Блок Д. Корзина: прогресс акции

### Д1. Блок появляется только когда клиент «в теме»

1. Под клиентом положить в корзину **посторонний** товар (не из условия).

2. Добавить **Условие 1** на сумму меньше четверти порога (менее 2 500 ₽ при пороге 10 000 ₽).

**Ожидаем:** блока по-прежнему нет (порог показа — 25 % от цели).

3. Добавить ещё, чтобы набралось больше четверти порога.

**Ожидаем:** появился блок с прогресс-баром: заголовок правила, текст
«Наберите акционных позиций ещё на X ₽ — и получите: …», строка «X ₽ из 10 000 ₽».

- [ ] Пройден

### Д2. Один запрос на серию нажатий

1. Открыть DevTools → Network, отфильтровать по `promotions`.
2. Быстро нажать «+» у товара 10 раз подряд.

- [ ] Пройден

### Д3. Порог достигнут

### Д4. Прогресс переживает все способы менять корзину

просто не показывается.

## Блок Ж. Мобильная ширина

Открыть в режиме мобильного устройства (или на телефоне):

- [ ] каталог: стопка бейджей не закрывает картинку, значки в правом углу не наезжают;
- [ ] каталог: шторка фильтров, блок «Акции» доступен;
- [ ] корзина: блок акций компактный, прогресс-бар и текст читаются, ничего не уезжает;
- [ ] админка: таблица правил скроллится по горизонтали, а не ломает вёрстку;
- [ ] админка: вкладки конструктора переключаются, поля не наезжают друг на друга;
- [ ] админка: свёрнутые карточки условий и наград читаются, подпись не рвётся;
- [ ] админка: группировка списка по акции не ломает вёрстку, таблица внутри группы
      скроллится по горизонтали.

## Известные ограничения (не баги)

- Промо-позиции не выдаются нигде и никак — это волна 1.
- Режим «Выдавать промо-позиции» заблокирован и в интерфейсе, и на бэкенде.
- Колонка «Выдано» в списке правил — прочерк, учёт появится в волне 2.
- Список складов для пробников пуст: склад «Москва реклама» заводится в 1С в волне 3.
- Кэш активных правил живёт до 60 секунд: после включения/выключения правила витрина
  может отставать на минуту.
- Группировка списка правил по акции работает по **текущей странице**: пагинация
  серверная, и счётчик в заголовке группы так и подписан — «правил на странице».
