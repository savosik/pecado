# 11. Проверка макетов реальностью

## Назначение

Сверка кликабельных макетов с фактическими данными: сколько строк будет на самом деле, какие
колонки нечем заполнить, что из нарисованного нужно убрать до начала вёрстки.

## Область

Входит: разбор восемнадцати экранов макетов и пятнадцати форм. Не входит: спецификация экранов
(разделы 05–06) — здесь только расхождения.

## Основания

Макеты [interface/menedzher.html](../interface/menedzher.html) и [interface/rop.html](../interface/rop.html);
[формы отчётов](../formy-otchetov-i-raschetov.md); [профиль данных](prilozhenie-profil-dannyh.md).

## Зачем это нужно

Экран, спроектированный под двадцать строк и получающий ноль или шестьсот, переделывается уже
после разработки. Все расхождения ниже найдены запросами к боевой базе, а не рассуждением.

## 1. Расхождения по объёму

| Экран макета | В макете | На самом деле | Что делать |
|---|---|---|---|
| Кого разбудить | полный список | **58 и 50** партнёров без единой покупки (по принятому определению новизны) плюс 19 молчащих дольше трёх месяцев отдельной вкладкой | пагинация 50; две вкладки, смешивать группы нельзя |
| Свободные клиенты | 618, из них 556 без покупок | 618, из них **614** без покупок; покупали когда-либо **4** | поправить числа; фильтр по умолчанию даёт 4 строки — это управленческий сигнал, а не поломка |
| Здоровье базы, строка про пул | «618, из них 62 когда-то покупали, прежний оборот 4,8 млн ₽/мес» | покупали **4**; оборота, о котором стоит говорить, нет | **исправить**: цифра ошибочна, обоснование найма на неё опираться не может |
| Премия отдела за квартал | 13 кандидатов, 9 засчитано | **58 кандидатов, засчитано 13** за II квартал 2026; 62 и 11 за III | список на 30–60 строк с пагинацией; ступень достигается, экран показывает и разрыв до следующей |
| Мои новые клиенты | несколько строк | 1–3 на работника | помещается, пагинация не нужна |
| Долги | плоский список накладных | 198 накладных у 16 партнёров | двухуровневый список: партнёр, накладные внутри |
| Моя база | 113 строк | 113 и 103, из них 58 и 50 никогда не покупали | отдельная вкладка для непокупавших |
| Кто выпал из ритма | список | 9 и 17 при фильтрах, до 80 без них | пагинация включается при снятых фильтрах |
| Фокус-товары | перечень | 83 позиции, 24–30 партнёров | перечень сворачивается |
| Очередь разметки | — | 196 и 44 за квартал | сортировка по влиянию на расчёт |

## 2. Колонки, которые нечем заполнить

| Колонка | Где | Причина | Решение |
|---|---|---|---|
| Закупки партнёра у других поставщиков | «Фокус-товары», блок «кому предложить» | таких данных у нас нет и не будет | заменено на «какие категории берёт у нас, где перечень представлен» |
| Доля нашего кошелька у партнёра | «Моя база» | то же | заменено на разрыв к лучшему месяцу партнёра |
| Обещал заплатить | «Долги» | поля нет | задача CRM с датой; фиксируется менеджером |
| Ценовая категория партнёра | «Скидки на визе» | понятия нет в системе | форма вне периметра |
| Согласование скидки | там же | таблиц согласований нет | вне периметра |
| Обратный отсчёт до статуса «новый» | «Кого разбудить» | данные есть | **убрано намеренно**: иначе выгодно придержать возврат партнёра ради повышенной ставки |
| Средняя покупка на партнёра | «Премия отдела» | данные есть | **убрано намеренно**: зачёт поклиентный, средняя создаёт ложное представление |
| План по партнёру | «Моя база» | данные есть | **убрано намеренно**: план ставится одной суммой на работника |

Различие принципиальное: первые пять убраны, потому что данных нет; последние три — потому что
показывать их вредно. И то, и другое зафиксировано, чтобы при следующем пересмотре они не вернулись.

|---|---|---|

| B5 «Здоровье базы» | Здоровье базы | покрыта; одна цифра в макете ошибочна |
| B6 «Трекер премии» | Квартальная премия | покрыта; объём вчетверо меньше нарисованного |

реализуется как постконтроль, поскольку процесса визирования до отгрузки не существует.

## 4. Экраны, которых в макетах нет

Появились при проработке и в макетах не нарисованы:

| Экран | Почему нужен |
|---|---|
| **Параметры мотивации** | без него ни одну ставку нельзя изменить без разработчика |
| **Фокус-перечень** | признака фокусности в данных нет; перечень надо вести |
| **Мастер планов на квартал** | действующие планы поставлены по другой методике и вдвое расходятся с формульными |
| Очередь разметки накладных | существует в действующей системе, переиспользуется |
| Параллельный расчёт | требование пункта 12.2 Положения |

Первые три — обязательные: без них система работает только руками разработки.

---

## 5. Что сделать с макетами

1. Исправить ошибочную цифру про партнёров с историей покупок в пуле: покупали 4, а не 62.
2. Поправить разбивку свободных партнёров: 614 из 618 без единой покупки.
3. Привести объём экрана квартальной премии к факту: 58 кандидатов, 13 засчитаны (II квартал 2026).
4. Экран «Кого разбудить» показать в пустом состоянии — это его основной вид на ближайший год.
5. Дорисовать три недостающих экрана либо явно пометить, что они спроектированы текстом ТЗ.

Пункты 1–3 выполнены. Пункты 4–5 выполняются при следующем пересмотре макетов; на решения по ТЗ
они не влияют.
