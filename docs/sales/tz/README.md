# Техническое задание: блок CRM «Мотивация 2.0»

Техническое задание на разработку разделов CRM, обслуживающих систему оплаты труда отдела продаж
редакции 2.2. Нормативная часть — [Положение о мотивации и об оплате труда](../polozhenie-ob-oplate-truda.md);
настоящее ТЗ описывает, как Положение исполняется информационной системой.

**Эпик:** `mot-00` — [docs/tasks/backlog/2026-09-08_mot-00-epic.md](../../tasks/backlog/2026-09-08_mot-00-epic.md)
**Статус:** ТЗ написано; все шестнадцать вопросов реестра закрыты 08.09.2026, разработка не блокирована
**Основание архитектуры:** расширение действующего домена зарплаты `sal-00`, не второй движок расчёта

## Принятые решения

| Вопрос | Решение |
|---|---|
| Новый партнёр | норма 12 месяцев на доступной истории; партнёр без отгрузок — Новый при первой покупке |
| Квартальная премия | ступени 8 / 15 / 22, порог квалификации 100 000 ₽ |
| Просроченная задолженность | ставка 0,05 % в день без ограничения; база расчищается до старта |
| Фокус-товары | ставка 1 %; перечень охватывает все собственные марки, состав утверждается отдельно |
| Возвраты | учитываются в мотивации |
| Планы | формульная методика с первого квартала действия; снижение плана ограничено 20 % за квартал; планы на партнёра остаются на «Планах продаж», из оплаты исключены |
| Ценовая дисциплина | постконтроль журналом скидок; пункт 9.3 приостановлен до появления визирования |
| Пул | 618 ничейных партнёров раздаются пакетами, приоритет — те, у кого есть история покупок |
| Передача партнёра | переход действует с первого числа следующего расчётного периода |
| Знаменатель дней | рабочие дни везде, «Планы продаж» приводятся к тому же |
| Квартальная премия | распределение фиксируется в системе, попадает в расчётный лист отдельной строкой |
| Ограничение К1 | потолка долей от суммы показателей нет; смягчение на первый квартал даёт гарантия перехода |
| Отдельная должность | новой сущности нет: пониженный оклад и повышенная ставка П2 — персональные отклонения параметров |
| Прогрессивная ставка П1 | не вводится; работа вширь оплачивается П2 и квартальной премией |
| Фиксация расчёта | напоминание 5-го числа, утверждение руководителем; автоматической заморозки нет |

## Шаблон документа

Каждый файл ТЗ построен одинаково:

2. **Область** — что входит и что явно не входит.
3. **Основания** — пункты Положения и файлы кода, на которые опирается документ.

## Принципы, которым подчинено всё ТЗ

1. **Второго движка расчёта нет.** Выручку считает только `ShipmentAnalyticsService`, план и темп —
   `PlanProgressService`. Расхождение цифр между разделами CRM — дефект по определению.
2. **Формулы живут в классах, числа — в данных.** Новый показатель = новый компонент-класс; новая
   ставка = значение в приказе. Редактора формул и движка правил в системе нет намеренно.
3. **Фронт ничего не считает.** Все величины приходят с сервера вместе с объяснением, как получены.
4. **Снимок неизменяем.** Утверждённый расчёт не меняется от новых данных и от изменения параметров;
   пересмотр — новая версия.
5. **Каждая цифра проверяема.** Любое число в ТЗ сопровождается запросом, которым оно получено
   ([prilozhenie-profil-dannyh.md](prilozhenie-profil-dannyh.md)).
6. **Интерфейс проектируется под фактический объём данных**, а не под макет: для каждого списка
   указано, сколько строк в нём на живой базе сегодня и сколько будет через год.

## Порядок изменений

1. Числовые параметры меняются приказом через Приложение № 1 Положения и вводятся руководителем
   на экране «Параметры мотивации». ТЗ при этом не правится: в нём значения не дублируются,
   указывается только слой хранения и правила валидации.
2. Изменение структуры показателей (новое слагаемое, изменение порядка) правит Положение,
   раздел [02-raschet-i-formuly.md](02-raschet-i-formuly.md) и требует нового компонента-класса.
3. Изменение экрана правит соответствующий раздел UX и, если меняется состав данных,
   [04-kontrakty-api.md](04-kontrakty-api.md).
4. Любая правка отражается в истории редакций документа с указанием основания.
