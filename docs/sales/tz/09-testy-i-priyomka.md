# 09. Тесты и приёмка

## Назначение

Чем проверяется, что система считает и показывает правильно.

## Область

Входит: контрольные расчёты, инварианты, сценарии приёмки, чек-лист руководителя.
Не входит: методика тестирования проекта в целом.

## Основания

Контрольные примеры — [раздел 02](02-raschet-i-formuly.md); объёмы —
[профиль данных](prilozhenie-profil-dannyh.md); действующее покрытие домена зарплаты
(`tests/Feature/Crm/Payroll/`).

## 1. Контрольный расчёт

Восемь примеров раздела 02 реализуются одним тестом расчёта, не требующим базы данных: параметры
задаются явно, входные величины — руками. Тест проверяет сумму до копейки и, отдельно, разложение
на показатели.

| Пример | Что проверяет |
|---|---|
| 1 | базовый порядок исчисления, все четыре показателя |
| 2 | прекращение начисления вычета со дня оплаты |
| 3 | непревышение порога и одновременное срабатывание нижнего ограничения |
| 4 | предельный размер переменной части |
| 5 | уменьшение плана при отсутствии предшествует вычислению порога |
| 6 | доплата до гарантии переходного периода |
| 7 | поклиентный зачёт в квартальной премии |
| 8 | сквозной расчёт на живых данных августа |

Пример 7 существует именно потому, что ошибка здесь правдоподобна: деление совокупного объёма
на количество партнёров даёт девять «квалифицированных» вместо четырёх и приводит к ошибочному
начислению премии.

**Контрольный тест действующей формулы остаётся зелёным.** Он опирается на значения по умолчанию
в конфигурации, поэтому новая схема заводится записью в базе, а умолчания не подменяются.

## 2. Инварианты

Проверяются автоматически; нарушение любого — дефект, а не расхождение методик.

| Инвариант | Почему важен |
|---|---|
| Отгрузки в расчёте равны отгрузкам на «Планах продаж» **с точностью до возвратов периода** | второго движка выручки нет; возвраты в мотивации вычитаются, на «Планах продаж» — нет, и это единственное допустимое расхождение |
| План квартала не ниже плана предыдущего квартала, уменьшенного на предел снижения, кроме случаев передачи партнёров и прекращения их деятельности | защита от намеренного провала квартала |
| Партнёр без единой отгрузки в истории при первой покупке признаётся Новым | принятое определение новизны |
| Партнёр с отгрузкой в пределах двенадцати месяцев Новым не признаётся | там же |
| Сумма вычета по партнёрам на экране «Долги» равна показателю К1 в расчёте | экран и расчёт читают одно и то же |
| Сумма вознаграждений по партнёрам в раскрытии П1 равна показателю П1 | раскрытие не приблизительное |
| Сумма строк расчётного листа равна итогу | |
| Партнёр с несколькими юрлицами считается один раз во всех списках и показателях | пункт 2.5 |
| Отгрузки партнёра в Периоде новизны не входят в П1 | пункт 6.3.3; группы не пересекаются |
| Отгрузки фокус-позиций входят в П3 независимо от того, в П1 или П2 учтён документ | пункт 6.4.2; эта группа пересекается с обеими |
| Утверждённый расчёт не меняется при изменении параметров, отгрузок, платежей, закрепления | пункт 11.2 |
| Расчёт периода использует приказ, действовавший в этом периоде | |
| Состав фокус-перечня в утверждённом периоде не меняется при правке правил | |
| Переменная часть не отрицательна и не превышает предельного размера | пункт 6.6 |
| Квартальная премия не входит в месячный доход ни в одном представлении | пункты 3.4, 7.6 |
| Таблицы домена не выдаются аналитическому агенту | персональные данные |

## 3. Сценарии приёмки по экранам

Проверяются руками, на данных стенда, до выкладки.

**Мой месяц.** Доход совпадает с расчётным листом до копейки · сумма пяти строк равна итогу ·
раскрытие каждой строки показывает состав · на утверждённом месяце изменение параметров не меняет
показанные числа · скрытая вкладка не опрашивает сервер.

**Моя база.** Сумма колонки «взял в этом месяце» сходится с отгрузками базы с учётом партнёров
в Периоде новизны · партнёр с двумя юрлицами — одна строка · вкладка «никогда не покупали»
содержит 58 партнёров у одного работника и 50 у другого.

**Кто выпал из ритма.** Величина «что это стоит вам» меняется при изменении ставки в приказе ·
партнёр, купивший сегодня, уходит из списка после пересчёта.

**Долги.** Сумма вычета по партнёрам равна К1 · оплата долга останавливает начисление с даты
оплаты, а не с начала месяца · накладные без восстановленной даты помечены явно.

**Кого разбудить.** В списке 58 и 50 партнёров без единой покупки · партнёр, купивший впервые,
уходит из списка и появляется в «Моих новых клиентах» с повышенной ставкой · молчащие дольше трёх
месяцев вынесены отдельной вкладкой и повышенной ставки не дают.

**Мои новые клиенты.** Сумма вознаграждений равна П2 · партнёр с истекшим Периодом новизны уходит
из списка, и его отгрузки в следующем месяце попадают в П1.

**Фокус-товары.** Начисленный П3 равен сумме по позициям перечня · позиции, добавленные в перечень
задним числом, не влияют на утверждённые периоды.

**Свободные клиенты.** 618 строк с пагинацией · по умолчанию включён фильтр «есть история покупок» ·
для партнёров без истории оценка не показывается, а помечается как неопределимая.

**Параметры мотивации.** Каждая строка Приложения № 1 имеет поле · предпросмотр изменения ставки
вычета даёт ту же величину, что и расчёт после сохранения · утверждённый месяц после издания
приказа показывает прежние числа · убывающие ступени премии отклоняются с объяснением.

**Планы на квартал.** Расчётная база сходится с медианой, посчитанной вручную запросом ·
блок сравнения с действующим планом показывает расхождение · попытка повысить план с обоснованием
«перевыполнил прошлый месяц» блокируется.

**Ведомость.** Утверждение замораживает снимок · переоткрытие создаёт новую версию, прежняя
доступна · корректировка сверх предела отклоняется.

**Квартальная премия.** Средняя покупка на партнёра не выводится нигде · при 12 кандидатах
и пороге 100 000 ₽ засчитаны 4.

## 4. Проверка на объёмах

Тяжёлых ответов в разделе нет, но три места проверяются на живых объёмах:

| Место | Объём | Ожидание |
|---|---|---|
| Помесячная выборка отгрузок по позициям перечня | 45 946 строк отгрузок, соединение с товарами | приемлемое время; при замедлении — материализация |
| Список свободных партнёров | 618 строк | пагинация работает, фильтр по умолчанию применён |
| Раскрытие вычета | 327 накладных за месяц | группировка по партнёрам, не плоский список |

## 5. Чек-лист руководителя перед закрытием месяца

1. Все накладные с оплатой размечены либо помечены как неразобранные осознанно.
2. Табель за месяц заполнен.
3. План на месяц утверждён.
4. Возражения работников рассмотрены и отвечены.
5. Разовые корректировки внесены с основаниями.
6. Ведомость сверена: сумма к выплате по каждому работнику совпадает с его расчётным листом.
7. В переходный период — параллельный расчёт доведён до работников.

Экран ведомости показывает этот список с отметками и ссылками туда, где невыполненное закрывается.

---

## 6. Что проверяется до разработки

Три проверки выполняются на этапе ТЗ, а не после:

1. **Против данных.** Каждый контракт раздела 04 прогоняется запросом по боевой базе: реальное
   число строк и реальные значения. Расхождение с макетом — правка макета.
2. **Против форм.** Каждая из пятнадцати форм либо разложена в экран, либо отклонена с причиной
   в [11-proverka-maketov.md](11-proverka-maketov.md).
3. **Против денег.** Теневой расчёт [03a](03a-tenevoy-raschet.md) должен сходиться с описанием
   формулы в разделе 02; расхождение означает ошибку в описании, а не в расчёте.
