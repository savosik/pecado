# Локальная разработка

Этот документ описывает, как поднять локально весь стек Pecado так, чтобы:

- приложение открывалось по `http://loc.pecado.ru:8085`;
- БД содержала те же данные, что на dev-сервере;
- товарные изображения подгружались из dev MinIO;
- Vite с HMR запускался автоматически вместе со стеком.

> ⚠️ **У dev свой IP `93.94.150.74` и стандартные порты** (см. [DEV_SERVER_CREDENTIALS.md](./DEV_SERVER_CREDENTIALS.md)).
> `93.94.150.16` — это **prod**, туда локальные скрипты ходить не должны.
>
> Что это значит для локальной разработки:
> - `make db-pull` ходит на `ladmin@dev.pecado.ru` (переопределяется `DEV_DB_SSH_HOST` в `.env`).
>   ⚠️ Если в старом локальном `.env` осталось `ladmin@93.94.150.16` — скрипт утянет **боевую** базу.
> - `MEDIA_DISK=s3_dev_readonly` ссылается на MinIO dev, но порт `9000` наружу закрыт.
>   Нужен SSH-туннель: `ssh -L 9000:localhost:9000 ladmin@dev.pecado.ru`. Либо `MEDIA_DISK=public`.
> - **Не использовать prod MinIO/БД** напрямую — там реальные пользовательские данные.

## Один раз: первичная настройка

### 1. /etc/hosts

```bash
sudo sh -c 'echo "127.0.0.1 loc.pecado.ru" >> /etc/hosts'
```

Проверить: `getent hosts loc.pecado.ru` → `127.0.0.1 loc.pecado.ru`.

### 2. SSH-доступ к dev-серверу

Скрипт `db-pull.sh` ходит по SSH. Проверить:

```bash
ssh ladmin@dev.pecado.ru echo ok
```

Если ключа нет — положить в `~/.ssh/`. Креды из [docs/DEV_SERVER_CREDENTIALS.md](DEV_SERVER_CREDENTIALS.md).

### 3. .env

```bash
cp .env.example .env
docker compose run --rm app php artisan key:generate
```

В `.env` уже подставлены значения для локального dev на `loc.pecado.ru:8085`. Проверить, что есть:

- `APP_URL=http://loc.pecado.ru:8085`
- `SESSION_DOMAIN=loc.pecado.ru`
- `SANCTUM_STATEFUL_DOMAINS=loc.pecado.ru`
- `VITE_HMR_HOST=loc.pecado.ru`
- `MEDIA_DISK=s3_dev_readonly` (в `.env.example` стоит `public` — чтобы CI не лез в закрытый dev MinIO; локально форсит `make setup`)
- `DEV_S3_*`, `DEV_DB_SSH_HOST`

### 4. Поднять стек

```bash
make up          # docker compose up -d
make db-pull     # стянуть обе БД с dev (займёт минуты)
```

Открыть `http://loc.pecado.ru:8085` — должна показаться витрина с реальными товарами.

## Повседневный workflow

| Команда                   | Что делает                                                       |
|---------------------------|------------------------------------------------------------------|
| `make up`                 | Поднять стек (Vite внутри `pecado-node` стартует автоматически)  |
| `make dev`                | `up` + tail логов node/nginx (видно HMR в реальном времени)      |
| `make down`               | Остановить всё                                                   |
| `make restart`            | down + up                                                        |
| `make logs S=app`         | Tail логов сервиса (S=имя; пусто — все)                          |
| `make ps`                 | Статус контейнеров                                               |
| `make sh`                 | bash в `pecado-app`                                              |
| `make tinker`             | `php artisan tinker`                                             |
| `make restart-vite`       | Перезапустить контейнер `node` (если HMR завис)                  |
| `make db-pull`            | Стянуть обе БД с dev                                             |
| `make db-pull DB=main`    | Только `pecado` (без тяжёлой `pecado_prices`)                    |
| `make db-pull DB=prices`  | Только `pecado_prices`                                           |
| `make db-pull-prod`       | Стянуть **боевую** БД (реальные персональные данные клиентов)    |

## Проверка перед пушем

Раньше вся верификация была вынесена на CI: ошибка обнаруживалась через 8–9 минут
(deploy-dev) или 15 минут (deploy-prod). Теперь проверки идут локально под потолком
в 6 из 12 потоков — машина не уходит в троттлинг, а цикл сокращается до секунд.

| Команда              | Что делает                                                     |
|----------------------|----------------------------------------------------------------|
| `make verify`        | Полная проверка перед релизом: Pint + ESLint + тесты + сборка  |
| `make test`          | Весь test suite последовательно                                |
| `make lint`          | Pint по изменённым файлам + ESLint                             |
| `make build`         | Сборка Vite (раньше вешала машину — теперь ограничена)         |
| `make release`       | `verify` → push в dev → ожидание CI → push в main → проверка 200 |

Git-хуки (`.githooks/`, подключены через `core.hooksPath`):

- **pre-commit** — Pint и ESLint по изменённым файлам, доли секунды.
- **pre-push** — тесты только по затронутым классам. Если тронуты миграции,
  `config/` или `composer.lock`, хук требует полного `make verify`.
- Обойти любой из них: `--no-verify`.

> **`make release` вместо двух `git push`.** Скрипт ждёт зелёного dev-прогона перед
> пушем в main (именно это включает пропуск тестов на проде) и не завершается, пока
> `pecado.ru` не ответит 200 — иначе упавший деплой оставит сайт под maintenance.

**Когда `make verify` нужен, а когда нет.** С тех пор как прод доверяет dev-прогону,
полную проверку выполняет CI на dev — локальный `make verify` её дублирует и добавляет
к релизу ~8 минут. Он окупается, только если правки рискованные: поймать поломку за
8 минут локально дешевле, чем за 9 минут dev-круга. Для обычных правок хватает
pre-push по затронутым классам, а релиз можно гнать так:

```bash
SKIP_VERIFY=1 make release
```

### Параллельные тесты: почему выключены

`brianium/paratest` установлен, но `make verify` использует последовательный прогон.
Причина: соединение `prices` в тестах смотрит на **настоящую MySQL** `pecado_prices`
(в `config/database.php` у него жёстко `'driver' => 'mysql'`, а `phpunit.xml`
переопределяет только соединение по умолчанию). При `--parallel` процессы
одновременно выполняют `migrate:fresh` на одной общей БД и мешают друг другу.

Замер 2026-08-09 на `tests/Unit/Models`: последовательно — 21 тест за 6,5 с;
параллельно на 2 процессах — 17 ошибок `Table 'pecado_prices.individual_prices'
doesn't exist`. Тесты, не трогающие `prices`, параллелятся нормально
(`tests/Unit/Services` — 528 тестов за 45 с).

Чтобы включить параллель, нужно изолировать `prices` по процессам через
`ParallelTesting::setUpProcess()` (своя БД `pecado_prices_test_{token}` на процесс).
Пока это не сделано, `make test-parallel` доступен, но часть тестов в нём упадёт.

## Ресурсы локальной машины

Стеки других проектов (`abcurd-*`, `hcsimple-*`, `laravel_*`) живут на той же машине.

| Команда         | Что делает                                                      |
|-----------------|------------------------------------------------------------------|
| `make audit`    | Что зря занимает место и память в Docker                        |
| `make clean`    | Вычистить безопасный docker-мусор (volumes не трогает)          |
| `make focus`    | Погасить стеки других проектов, оставить только Pecado          |
| `make unfocus`  | Вернуть их обратно                                              |

Разовая системная настройка (root): `sudo scripts/local-tune.sh` — ротация docker-логов,
общий потолок `docker.slice` на 6 потоков, `vm.swappiness`, сжатие свопа, отключение
`thermald`. Скрипт идемпотентный, каждый изменённый файл бэкапится.

Раз в неделю мусор Docker чистится автоматически (`systemctl --user list-timers`).

### Как именно ограничивается нагрузка

Три независимых уровня, и путать их не стоит:

1. **`docker-compose.override.yml`** — потолок на отдельный контейнер. Применяется
   только при **пересоздании** (`docker compose up -d --force-recreate`), не при рестарте.
   Изменить на лету: `docker update --cpus=N --memory=Mg <контейнер>`.
2. **`docker.slice`** (`CPUQuota=600%`) — общий потолок на **все** контейнеры всех
   проектов. Требует root, ставится через `local-tune.sh`. Без него сумма лимитов
   отдельных контейнеров легко превышает 12 потоков.
3. **`scripts/with-cap.sh`** — то, что доступно без root: на время тяжёлой команды
   приглушает фоновые контейнеры (`worker`, `meilisearch`, `mysql` → 1 ядро) и
   возвращает лимиты обратно, в том числе при Ctrl+C.

> ⚠️ **`systemd-run --scope` вокруг `docker exec` не работает.** Он ограничивает процесс
> docker-клиента, а работа идёт внутри контейнера — в своей cgroup под `dockerd`.
> Ограничить контейнер можно только через `docker update` или cgroup-parent.

Тесты запускаются с `memory_limit=2G` (`PHP_TEST_MEM` в Makefile): дефолтных 512 MB
полному suite не хватает — процесс падает `Fatal error` примерно на 2150-м тесте.
Лимит приходит из `docker/php/uploads.ini`, а тот монтируется и на dev, и на prod —
поэтому правится не он, а вызов: цели зовут `vendor/bin/phpunit` напрямую, потому что
`artisan test` форкает дочерний процесс и переданный ему `-d memory_limit` теряется.

### Vite и `usePolling` — главный источник нагрева

В `vite.config.js` стоял `server.watch.usePolling: true`. Polling нужен на macOS и
Windows, где inotify не проходит через bind-mount, но **на Linux он не нужен** —
проверено: `fs.watch` внутри контейнера получает события с хоста нормально.

Цена включённого polling (замер 2026-08-09): процесс Vite за 3 дня 9 часов аптайма
накрутил **6 дней 4 часа процессорного времени** — в среднем ~180 % CPU непрерывно,
круглые сутки. Это и держало машину на 82 °C «в простое»; тесты и сборки лишь
добавляли сверху. После отключения показатель `C` в `docker top` упал с 99 до 8.

Если разработка ведётся с macOS/Windows — включайте polling переменной
`VITE_USE_POLLING=true`, не правкой конфига.

### Картинки товаров — фолбэк на прод

База приезжает с прода (`make db-pull-prod`), а 50 тысяч медиафайлов — нет, поэтому
локальный MinIO почти пуст и каталог показывал бы битые картинки. Настроено так:

```
браузер → /storage/… → nginx → MinIO (локальный)
                                  ↓ 404/403
                              https://pecado.ru/storage/… → кэш на диске
```

- `AWS_URL=http://loc.pecado.ru/storage` в `.env`. Без него Laravel строил ссылки от
  `AWS_ENDPOINT=http://minio:9000` — внутреннего docker-имени, которое браузер не
  резолвит, поэтому **все** картинки были битые независимо от наличия файлов.
- `location ^~ /storage/` в `docker/nginx/default.conf` проксирует в MinIO, а по
  `404/403` уходит в `@media_from_prod`. Прод отдаёт те же пути публично
  (у него `AWS_URL=https://pecado.ru/storage`).
- Ответы прода кэшируются на диск (`proxy_cache`, до 2 GB, 30 дней) — иначе каждый
  скролл каталога заново тянул бы мегабайты: картинки весят 0,5–3 MB.
  Замер: MISS 0,012 с → HIT 0,0037 с.

Диагностика по заголовкам ответа:

| Заголовок | Значение |
|---|---|
| нет `X-Media-Source` | файл нашёлся в локальном MinIO |
| `X-Media-Source: prod-fallback` | добрано с прода |
| `X-Media-Cache: HIT` / `MISS` | взято из локального кэша / скачано заново |

Локальные загрузки при этом продолжают работать нормально: они попадают в MinIO и
отдаются оттуда, до фолбэка дело не доходит. Файл `default.conf` на серверы не едет —
у прода свой `docker/nginx/prod.conf`.

### Адрес сайта и HMR

Работают **оба** адреса: `http://loc.pecado.ru` и `http://loc.pecado.ru:8085`.

Раньше был проброшен только 8085, из-за чего короткий адрес в браузере не открывался
вовсе, хотя `APP_URL=http://loc.pecado.ru` (без порта) — то есть Laravel генерировал
ссылки и редиректы на адрес, которого не существовало. Порт 80 добавлен в
`docker-compose.override.yml`; на машине он свободен, остальные проекты сидят на
8080/8000/8081/8088.

Vite 7 отклоняет запросы с незнакомым заголовком `Host` (защита от DNS-rebinding) и
отдаёт **403**. HMR-сокет настроен на `VITE_HMR_HOST=loc.pecado.ru`, поэтому без
`server.allowedHosts` горячая перезагрузка молча не работала: страница грузилась
(ассеты шли с `localhost:5174`), а правки не долетали. Список хостов задан в
`vite.config.js` — при добавлении нового локального домена дописывайте туда.

Проверить HMR из терминала, без браузера:

```bash
# 1. прогреть граф модулей — без запроса Vite не следит за файлом
curl -s -o /dev/null http://localhost:5174/resources/js/Pages/Welcome.jsx
# 2. в другом окне: docker logs pecado-node -f
# 3. тронуть файл → в логе появится «hmr update /resources/js/Pages/Welcome.jsx»
```

## Архитектура локального стека

```
браузер → nginx(8085 → :80) → app(php-fpm 9000)
                            ↘ (HMR WS) → node(5174→5173)

storage чтения (Spatie media) → s3_dev_readonly → dev MinIO :9000/pecado (через SSH-туннель)
storage записи (контент upload) → s3 → локальный MinIO (createbuckets)

БД: pecado-mysql (3308), pecado-mysql-prices (3309) — наполняются db-pull.sh
```

## Troubleshooting

### `loc.pecado.ru:8085` не открывается

1. `getent hosts loc.pecado.ru` — должен возвращать `127.0.0.1`. Если нет — см. шаг 1 выше.
2. `make ps` — в списке должен быть `pecado-nginx`. Если нет — `make up`.
3. `docker logs pecado-nginx` — ищем ошибки.
4. `curl -sI http://loc.pecado.ru:8085` — должен вернуть 200/302.

### HMR не работает / WebSocket падает

1. В DevTools → Network проверить, что `@vite/client` грузится с `loc.pecado.ru:5174`.
2. Если порт другой — проверить `VITE_HMR_HOST` и `VITE_HMR_CLIENT_PORT` в `.env`.
3. `make restart-vite` — иногда контейнер залипает после `npm install`.
4. `docker logs pecado-node --tail=100` — Vite должен сказать `ready in N ms`.

### Картинки товаров не грузятся

1. Открыть DevTools → Network, найти запрос на `…:9000/pecado/...`.
2. Если CORS/блокировка — проверить, что `MEDIA_DISK=s3_dev_readonly` в `.env` и `php artisan config:clear`.
3. Если 403 — bucket `pecado` на dev должен быть public; проверить через консоль MinIO (`ssh -L 9001:localhost:9001 ladmin@dev.pecado.ru` → `http://localhost:9001`).

### `db-pull` падает на SSH

```
Permission denied (publickey)
```

— положить SSH-ключ в `~/.ssh/`, добавить `Host 93.94.150.74` (он же `dev.pecado.ru`) в `~/.ssh/config` или прокинуть через `ssh-agent`.

### `db-pull` падает на mysqldump (большая БД)

`pecado_prices` может быть несколько ГБ. Варианты:
- запускать только основную: `make db-pull DB=main`;
- увеличить таймаут SSH: добавить `ServerAliveInterval 60` в `~/.ssh/config`;
- запустить ночью.

### OAuth-логины

Google/Yandex redirect-URL зарегистрированы на prod-домен. На локалке социальный логин не работает — это нормально, тестируем на dev/prod.

## Боевая база локально

`make db-pull-prod` тянет копию прод-БД, чтобы фичу можно было посмотреть на реальных
объёмах до деплоя. Скрипт перед импортом:

- требует явного подтверждения (или `--yes` для автоматических запусков);
- проверяет, что локальный `.env` не смотрит на боевой RabbitMQ, MinIO и SMTP —
  иначе локальный worker мог бы отправить сообщения в 1С или письма клиентам;
- после импорта обнуляет `personal_access_tokens`.

Переиндексация Meilisearch по умолчанию **выключена** (на боевом объёме она долгая и
греет CPU) — добавьте `--reindex`, если нужна.

### Почему пул занимает 30 секунд, а не часы

Боевые базы весят `pecado` **6,6 GB** и `pecado_prices` **8,7 GB**, но локально
приезжает **177 MB за полминуты**. Разбор боевой базы (2026-08-09) показал, что
**96 % её объёма — мусор мониторинга**, бесполезный на локальной машине:

| Таблица | Размер | Что это |
|---|---|---|
| `pulse_aggregates` | 4536 MB | метрики Laravel Pulse |
| `pulse_entries` | 1323 MB | они же |
| `erp_bus_messages` | 454 MB | лог сообщений шины 1С |
| `erp_processed_messages` | 82 MB | дедупликация входящих ERP |
| **всё остальное** | **~240 MB** | собственно бизнес-данные |

`individual_prices` в БД цен — отдельные 8,7 GB реальных данных, локально нужные редко.

Поэтому дамп идёт **в два прохода**: сначала полная структура (`--no-data`, чтобы все
таблицы существовали и приложение не падало на запросах к ним), затем данные с
`--ignore-table` для перечисленного выше. Список — в `SKIP_DATA_TABLES` внутри скрипта.
Нужна точная копия? `scripts/db-pull.sh all --from=prod --full`.

### Грабли, которые скрипт обходит сам

- **`ERROR 1227: you need SYSTEM_USER privilege`** — в дампе прода есть объекты с
  `DEFINER=` от привилегированного пользователя. `DEFINER` вырезается из потока,
  импорт идёт под локальным `root`, а не под `pecado`.
- **`ERROR 1045` на БД цен** — учётка прода заведена как `` `user`@`%` ``, и подключение
  через unix-сокет отдаёт `@'localhost'`. Спасает `-h 127.0.0.1`: TCP попадает под `%`.
- **Остатки от прошлого импорта.** `mysqldump` кладёт `DROP TABLE` только для таблиц из
  дампа; всё лишнее пережило бы загрузку. Схема пересоздаётся целиком.

> ⚠️ В базе — реальные телефоны, адреса и заказы клиентов, а диск локальной машины
> не зашифрован. Анонимизации скрипт не делает: это осознанное решение, а не упущение.

Ночная автосинхронизация подготовлена, но **выключена** до проверки SSH к проду:

```bash
systemctl --user enable --now pecado-db-pull.timer   # включить (05:00 ежедневно)
systemctl --user list-timers 'pecado-*'              # посмотреть расписание
```

## Не делать

- **Не загружать на локалке "тестовые" изображения и не ожидать, что они будут на dev.** Локальные uploads уходят в локальный MinIO (createbuckets bucket `pecado`), не в shared dev-bucket.
- **Не редактировать `docker-compose.yml` под себя.** Вместо этого использовать `docker-compose.override.yml` (gitignored).
- **Не коммитить `.env`** — он в `.gitignore`.
- **Не запускать `npm run build` и `composer test` напрямую** — используйте `make build`
  и `make test`: они ограничены шестью потоками. Прямой вызов забирает все 12 и
  роняет отзывчивость рабочего стола.
