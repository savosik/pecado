# res-04 · Кнопка «Отменить заказ» в кабинете

**Приоритет:** высокий
**Создано:** 2026-09-02
**Эпик:** [res-00](2026-09-02_res-00-epic.md)
**Зависимости:** res-03
**Волна:** 1

## Описание

Отказ — самый частый повод звонка менеджеру. Даём клиенту отменить заказ самому,
пока 1С не начала сборку. Работает для **всех** заказов, не только резервных, — поэтому
волна 1 приносит пользу ещё до появления статуса «Резерв».

- Кабинет сейчас read-only (`app/Http/Controllers/User/OrderController.php`: index, show,
  repeat, export). Добавить экшен отмены + маршрут в `routes/user.php` с проверкой
  владельца заказа (policy).
- Отмена доступна в статусах до начала сборки (раньше `ready_for_shipment`; точная
  граница — по resolution res-01). В остальных — кнопки нет, при гонке (статус уехал
  между рендером и запросом) — понятная ошибка на русском.
- Отмена → исходящий `order.deleted` в 1С (канал res-03) + запись в `order_change_logs`
  через `OrderChangeLogger`.
- UI: кнопка в деталях заказа, подтверждение через `ConfirmDialog`
  (`resources/js/shared/Panel/`), в списках — стандарт действий строк
  (глаз/карандаш/корзина), никаких текстовых кнопок в строках.
- Мобильный UX: кнопка и диалог полноценно работают на узком экране; операция —
  один-два тапа, быстрее звонка менеджеру.
- Отменённый заказ не исчезает молча: остаётся в списке с ясным статусом.

## Ход работ

- **03.09.2026** — реализовано за глобальным рубильником `order_reserve.enabled`
  (выключен — эндпоинт 404, кнопка не рендерится; решение после вопроса заказчика
  «а если 1С не умеет»: клиенты ничего не видят до совместных испытаний и включения).
  - `Order::cancellableByClient()`: ранние статусы до `ready_for_shipment` **или**
    активный резерв (резервный заказ приезжает как ready_for_shipment — окно резерва
    и есть окно отмены).
  - `POST /cabinet/orders/{order}/cancel`: владелец (403 чужому), гонка со сборкой →
    422 с русским текстом; публикация `order.deleted` (reason=client_cancelled) через
    `OrderReservePublisher` ДО локального закрытия; локально — `closed` + soft-delete,
    переход ложится в `OrderStatusHistory` с user_id клиента и комментарием
    «Отменён клиентом из кабинета» (менеджер видит источник отмены).
  - Фронт: кнопка «Отменить заказ» (красная, LuBan) в actions страницы заказа +
    `ConfirmDialog` из shared/Panel; при 422 — reload для актуального состояния.
  - Тесты: `ClientOrderCancelTest` (7 шт), Order+Erp — 377 зелёных, ESLint/tsc чистые.
- Визуальная проверка на реальном экране — при включении флага на dev в рамках
  совместных испытаний (кнопка за выключенным рубильником, сейчас её не видно).

## Критерии готовности

- [x] Клиент отменяет свой заказ из кабинета; чужой — 403.
- [x] В поздних статусах отмена недоступна, гонка отбивается понятной ошибкой.
- [x] `order.deleted` уходит в 1С, изменение зафиксировано в истории статусов.
- [x] ConfirmDialog, тексты на русском; мобильная вёрстка — проверить на dev при
  включении флага (испытания).
- [x] Feature-тесты: успешная отмена, запрет по статусу, запрет чужого заказа,
  выключенный флаг, гейт can_cancel, журнал.
