## Описание

Последний пункт задачи заказчика: «а ещё это могут быть емейл рассылки, кампании, акции».

Отличие от остального эпика принципиальное. Всё предыдущее — **реактивное и транзакционное**:
произошло событие, ушло письмо тому, кого оно касается. Кампания — **инициируемая и рекламная**:
человек выбирает аудиторию и жмёт «отправить». Отсюда другие требования: согласие получателя,
`List-Unsubscribe`, отправка порциями.

Прецедент в проекте есть: кампания черновиков OTOUCH (2026-08-18) — 207 персональных писем
через агентское API. Механика оказалась переиспользуемой, но каждый раз собиралась вручную.

## Что делаем

### Миграции

**`notification_campaigns`**: `name`, `segment` (json — фильтры аудитории), `template_key`,
`subject`, `body_html`, `status` (`draft|scheduled|sending|sent|cancelled`), `scheduled_at`,
`started_at`, `finished_at`, `created_by_user_id`, счётчики отправленного и пропущенного.

**`notification_campaign_recipients`**: `campaign_id`, `contact_id` / `user_id` / `email`,
`status`, `delivery_id`, unique `(campaign_id, email)`.

Все столбцы с русскими комментариями, `bi:sync-grants` после миграции.

### Конструктор сегмента

Поверх уже существующих фильтров `/crm/partners` (`ClientListService`, пресеты фильтров
`crm_client_filter_presets`) — не заводить второй язык отбора клиентов. Сегмент сохраняется
как набор тех же фильтров плюс отбор по контактам: роль, наличие согласия.

Предпросмотр аудитории: сколько партнёров, сколько адресов, сколько отсеяно по согласию
и стоп-листу — **до** отправки.

### Тело письма

Из `crm_email_templates` (модель уже есть) с плейсхолдерами через `CrmEmailTemplate::render()` —
`str_replace`, без Blade: шаблонизатор над текстом из БД означал бы выполнение кода из базы.

Набор плейсхолдеров кампании шире: `{{client_name}}`, `{{contact_name}}`, `{{manager_name}}`,
`{{company_name}}`.

### Отправка

Кампания создаёт по сигналу `campaigns.broadcast` на получателя и проходит **тот же**
`DeliveryGuard` — рассылка не обходит стоп-лист по построению, это главное архитектурное
свойство карточки.

`DeliveryGuard` для домена `campaigns.*` дополнительно требует:

- `client_contacts.marketing_consent = true` (для контактов) либо `users.is_subscribed = true`
  (для аккаунтов — флаг существует давно, но при отправке нигде не проверяется);
- отсутствие записи в стоп-листе со `scope in ('all','marketing')`.

Отправка порциями с учётом `max_deliveries_per_minute`, статус кампании отражает прогресс.

### `List-Unsubscribe`

Заголовки `List-Unsubscribe` и `List-Unsubscribe-Post` в письмах домена `campaigns.*`
(в проекте их сейчас нет нигде). Ссылка ведёт на тот же публичный маршрут отписки,
`scope='marketing'` — отписка от рекламы не отключает уведомления о заказах.

Механика заголовков — через `Headers` в Mailable, как уже сделано в `CrmManagerMail`.

### Прочие события домена

- `campaigns.product_back_in_stock` — поверх существующего `crm:back-in-stock-drafts`
  и `CrmBackInStockOffer`;
- `campaigns.promotion_started` — старт акции из `promotions`.

Оба — через тот же гард с проверкой согласия.

## Что НЕ входит

Отчёты открытий и кликов: требуют трекинг-пикселя, редиректов и отдельного решения
по приватности. Отдельная задача, если заказчик попросит.

## Критерии готовности

- [ ] Миграции кампаний с русскими комментариями; `db:comments:audit --strict`, `bi:sync-grants`
- [ ] Конструктор сегмента поверх фильтров `/crm/partners`, без второго языка отбора
- [ ] Предпросмотр аудитории с разбивкой «отсеяно по согласию / стоп-листу» до отправки
- [ ] Тело письма из `crm_email_templates`, плейсхолдеры через `str_replace`
- [ ] Кампания идёт через `DeliveryGuard`; тест: адрес в стоп-листе не получает письма
- [ ] Тест: контакт без `marketing_consent` не получает кампанию
- [ ] `List-Unsubscribe` в заголовках; отписка от рекламы не отключает уведомления о заказах (тест)
- [ ] Отправка порциями с учётом глобального лимита; статус кампании отражает прогресс
- [ ] Права: запуск кампании только под `crm-notifications-all.edit`
- [ ] Весь интерфейс на русском
- [ ] `make lint`, `make test`, `make build` зелёные
