# res-06 · Чекаут: radio «можно отгружать / поставьте в резерв»

## Описание

Текущая галочка подтверждения перед оформлением (из рефакторинга сводки-чека) превращается
в radio из двух вариантов:

- 🔘 **«Подтверждаю — можно отгружать»** (по умолчанию) — текущее поведение;
- 🔘 **«Поставьте в резерв»** — заказ уходит в 1С с признаком резерва. Рядом — срок:
  «Резерв держится N часов, до {дата, время}» (срок из res-05, с учётом индивидуального).

### Бэкенд

- `CheckoutService`/`OrderAssembler`: признак резерва прокидывается в заказ и в исходящий
  `order.created` (поле из res-02). При расщеплении корзины на несколько заказов признак
  применяется ко всем, к которым применим (уточнить: promo/defect/preorder — применим ли
  резерв, по умолчанию — только к типу `order`).
- Партнёр с отключённой опцией (res-05) — radio нет, поведение как сегодня; выбор резерва
  в обход UI отбивается валидацией на сервере.

### Редирект после оформления

- Несколько заказов → раздел «Заказы в резерве» (res-07);
- один заказ → сразу в его детали (там таймер).

### UX

- Radio через обёртки `@/components/ui/*` (Chakra v3), недостающие снипеты — через CLI.
- Мобильный чекаут: крупные тап-зоны, без переносов-огрызков — с учётом свежих мобильных
  дефектов чекаута. Все тексты на русском.

## Ход работ

- **04.09.2026** — реализовано за рубильником:
  - корешок сводки-чека: участнику режима (`config.reserves_enabled` + есть
    складские строки) вместо галочки — radio «Данные проверены — можно отгружать» /
    «Поставьте в резерв — подтвержу отгрузку позже» с подписью срока
    (`config.reserve_hours`, индивидуальный или 24 ч); кнопка меняет подпись на
    «Поставить в резерв»; пульсирующая подсветка и tooltip-подсказки сохранены;
    неучастнику — прежняя галочка без изменений;
  - прокидка: `StoreCheckoutRequest` (`reserve` + withValidator «режим недоступен»),
    `CheckoutService` (защитный гейт по `ReservePolicy` от обхода UI),
    `OrderDraft`/`OrderAssembler` — **резервируется только группа type=order**
    (предзаказ/уценка/промо своим конвейером), `reserved_until` = запрошенный срок;
  - `PublishOrderToErp`: `reserve`/`reserved_until` в исходящем `order.created`
    только по резервным заказам (обычные payload не раздуваются);
  - редирект: один заказ → его страница (плашка с таймером из res-07),
    несколько → раздел `/cabinet/reserves`.
  - Тесты: `CheckoutReserveTest` (5 шт), смежный прогон Order/Services/Erp/Api —
    602 зелёных; ESLint/tsc и Pint чистые.
- Живая мобильная проверка radio — при включении флага на dev (испытания).

## Критерии готовности

- [x] Radio с умолчанием-выбором «можно отгружать»; выбор резерва создаёт заказ с признаком.
- [x] `order.created` уходит в 1С с признаком, интеграционный тест зелёный.
- [x] Редирект: несколько заказов → раздел, один → детали.
- [x] У отключённого партнёра radio нет, серверная валидация отбивает обход
  (плюс защитный гейт в сервисе).
- [x] Мобильная вёрстка свёрстана (крупные тап-зоны, VStack); живая проверка —
  при включении флага (испытания).
