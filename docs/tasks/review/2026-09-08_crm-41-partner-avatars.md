# crm-41 · Аватарки партнёров в CRM: загрузка менеджером и рисование ИИ

**Приоритет:** низкий (удобство менеджеров)
**Создано:** 2026-09-08
**Связано:** [crm-16](2026-08-04_crm-16-clients-table.md) (список партнёров), [crm-40](2026-09-08_crm-40-lifecycle-reasons.md)

## Зачем

Список партнёров — двадцать строк «ООО …», которые различаются третьим словом.
Менеджер ищет карточку глазами по тексту. Картинка рядом с именем узнаётся быстрее,
чем читается наименование из 1С, и это единственная задача аватарки: узнавание, не отчётность.

## Главное ограничение: аватарки не публичные

Их рисует отдел продаж **для себя**. Партнёр не должен увидеть в кабинете, каким его
изобразили, — ни по прямой ссылке, ни случайно.

- Файлы лежат на приватном диске `crm-avatars` (`storage/app/private/crm-avatars`),
  у которого `visibility: private` и **`serve: false`** — встроенная отдача Laravel дала бы
  адрес без проверки прав.
- Медиатека (`spatie/laravel-medialibrary`, публичный диск) не задействована намеренно.
- Наружу файл выходит единственным маршрутом `crm.clients.avatar` под `crm-clients.view`
  и тем же скоупом видимости, что список: чужой партнёр — 404, а не 403.
- Тест `the_file_never_reaches_public_storage` держит это: он проверяет и пустоту публичного
  диска, и сами настройки диска — иначе правка конфига однажды тихо откроет файлы наружу.

## Как рисуется

Два хода через OpenRouter (`ClientAvatarGenerator`):

1. **Текстовая модель придумывает промт** по фактам о партнёре (`PartnerFacts`): человек или
   организация, пол по отчеству, лига по обороту за год, город, тип бизнеса, годы с нами,
   интересы-теги. Тон задан системным сообщением: дружелюбный маскот, без карикатур на
   внешность, возраст и национальность, без надписей на картинке.
2. **Модель-художник рисует** по этому промту; ответ разбирается в трёх формах
   (`message.images`, вложение в контенте, data-URL в тексте) — смена модели в конфиге
   не должна ломать генерацию.

Почему не одним ходом: художник берёт промт буквально и по строке «ООО Ромашка, оборот 4 млн»
рисует табличку с текстом. Промт остаётся в базе — через месяц видно, почему у партнёра
именно этот пингвин.

**В промт не попадают долги, просрочка и жалобы.** Шутка про должника, которую менеджер
показывает коллеге, рано или поздно окажется на экране при самом должнике.

## Кеш и деньги

- Файл пережимается в WebP 256×256 (`AvatarImageProcessor` на GD) — 15–30 КБ вместо мегабайта
  из модели; заодно с загруженных менеджером картинок слетает EXIF.
- Отдача кешируется браузером по ETag (`Cache-Control: private, max-age=604800`), в адресе —
  кусок контрольной суммы, поэтому замена видна сразу, а не через неделю.
- Генерация платная: пачка ограничена `batch_limit` (25), после неудачи пауза
  `failure_cooldown_hours` (24 ч), попыток не больше `max_attempts` (3). Джоб уникален
  по партнёру — кнопка, ночная пачка и второй заход менеджера не сложатся в три оплаченных рисунка.
- Ручную аватарку ИИ не перерисовывает никогда, даже `--force`: выбор человека старше автоматики.

## Что где лежит

| Файл | Роль |
|---|---|
| `config/crm_avatars.php` | флаги, модели, размеры, лимиты |
| `config/filesystems.php` → `crm-avatars` | приватный диск |
| `database/migrations/2026_09_08_140000_create_crm_client_avatars_table.php` | таблица |
| `app/Services/Crm/Avatars/*` | хранение, пережатие, факты, генератор, ссылки для UI |
| `app/Jobs/GenerateClientAvatar.php` | очередь, уникальность по партнёру |
| `app/Console/Commands/CrmAvatarsGenerate.php` | пачка (в расписании 04:40) |
| `app/Http/Controllers/Crm/ClientAvatarController.php` | отдача, загрузка, перерисовка, снятие |
| `resources/js/Crm/Components/PartnerAvatar*.jsx` | картинка и меню в карточке |

Управление — из карточки: клик по аватарке открывает меню «Загрузить свою / Перерисовать
через ИИ / Снять». Отдельных кнопок в шапке нет: аватарка нужна ради узнавания, а не ради
работы с ней.

## Проверка

- `tests/Feature/Crm/ClientAvatarTest` — загрузка, ETag и 304, приватность (партнёр и гость
  не получают файл, публичный диск пуст, диск настроен приватно), чужой партнёр за 404,
  снятие, постановка в очередь, попадание в список и карточку, русская ошибка валидации.
- `tests/Feature/Crm/ClientAvatarGenerationTest` — два хода с фактами в теле запроса, осечка
  как счётчик попыток, неприкосновенность ручной аватарки, исчерпанные попытки, разбор
  data-URL из текста, отбор партнёров командой.

## После выката

- `php artisan bi:sync-grants` — новая таблица; без этого BI-агент её не увидит
  (см. `project_analytics_mcp` в памяти). Аватарки ему не нужны, но реестр прав должен сходиться.
- Прогнать `crm:avatars-generate --limit=5` и посмотреть глазами, прежде чем отпускать
  ночную пачку на всю базу.
