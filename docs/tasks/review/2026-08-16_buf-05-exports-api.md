# buf-05: буфер в выгрузках и client-api

**Приоритет:** высокий
**Эпик:** [buf-00](2026-08-16_buf-00-epic.md)
**Зависит от:** buf-04
**Создано:** 2026-08-16

## Описание

Выгрузки — главная поверхность дропшиппера: именно из них его витрина берёт
остатки. Занижение обязано совпадать с сайтом до штуки.

### Что подхватывается само (через `StockService` из buf-04)

- Пресетные выгрузки (`AbstractPreset`: YML, Shopify, Google Merchant, JSON) —
  `getAvailableStockMap($productList, $clientUser)`;
- кастомные CSV (`CustomFieldsPreset::preloadChunkCache` → поля
  `user_stock_available` / `user_stock_preorder`);
- client-api `GET /api/client-api/{token}/stocks` (`ClientApiController`).

Ключ сегмента — `client_user_id` выгрузки / владелец токена. Проверить, что
у выгрузок без привязки к клиенту (`client_user_id IS NULL`) буфер не применяется.

### Дырки мимо `StockService` — закрыть

Три поля кастомных выгрузок читают `product_warehouse` напрямую:
`TotalStockField`, `WarehouseQuantityField` («Остаток: {склад}»),
`WarehousesQuantityField` (JSON по складам). Закрыть одним concern-ом по образцу
`RestrictsWarehousesByRegion` (уже подключается в `CustomFieldsPreset`):
для клиента с галочкой количества складов уменьшаются на буфер пропорционально
или из первого склада с остатком — главное, чтобы сумма сходилась с
`user_stock_available`. Native/JSON-режим (`WarehousesQuantityField::nativeValue`)
тоже покрыт.

### Попутный фикс модификаторов

`applyArithmetic` (`multiply`/`add` из `product_exports.fields[].modifiers`)
не клампит результат — ручное `add: -3` уводит остаток в минус. Добавить
`max(0, …)` для складских полей.

### Кеш выгрузок — инвалидация строго условная

Выгрузки кешируются (`cached_at`, `data_version_at`, bump из `HandleStockUpdated`).
Ловушка регрессии: безусловный `bump()` из ночного `stock:buffers:recompute`
протухнет **все** кешированные выгрузки каждую ночь, и утро начнётся с массовой
перегенерации. Поэтому:

- пересчёт дёргает инвалидацию **только при непустом диффе** изменённых SKU
  (дифф отдаёт команда из buf-01); пустой пересчёт не трогает ни один кеш;
- переключение галочки клиента сбрасывает кеш **адресно** — только выгрузки
  этого клиента (`product_exports.client_user_id`) и только у клиентов
  с изменившимся флагом, не глобальную версию;
- у клиентов без галочки версии кешей от жизни буфера не меняются вообще.

## Реализация (2026-08-16)

- Пресеты и client-api подхватились через `StockService` из buf-04 без правок;
  выгрузка без `client_user_id` буфер не применяет (buffersApplyTo(null) = false).
- Дырки закрыты трейтом `AppliesStockBufferToWarehouses` (по образцу
  `RestrictsWarehousesByRegion`, подключён в `CustomFieldsPreset` **и** в
  `ProductExportService::fetchData` — preview обязан совпадать с файлом):
  буфер «выедается» из primary-складов региона по порядку, начиная с первого
  с остатком; preorder-склады не трогаются; сумма по складам сходится
  с `user_stock_available` до штуки. Мутируются только загруженные pivot-ы.
- Кламп `max(0, …)` для полей группы «Складские остатки» после модификаторов —
  в обоих зеркалах (`CustomFieldsPreset` extractRow/extractRowNative и
  `ProductExportService::extractFields`).
- Инвалидация — адресная, а не глобальный bump: непустой дифф пересчёта
  сбрасывает `cached_at` только выгрузок клиентов сегмента (и только при
  включённом `STOCK_BUFFER_ENABLED`); переключение галочки — только выгрузки
  этого клиента (в той же транзакции `changeStockBuffer`). Глобальная версия
  `data_version_at` не трогается вообще — клиенты без галочки не задеты
  по построению.

## Критерии готовности

- [x] Клиент с галочкой: кастомная выгрузка = сайт = client-api по рисковому SKU (сквозной тест `StockBufferExportsTest`)
- [x] Клиент без галочки и выгрузки без `client_user_id`: как раньше (регресс-тест)
- [x] `TotalStockField` / `WarehouseQuantityField` / `WarehousesQuantityField` согласованы с буфером; сумма по складам сходится (тест: буфер 2 при складах 1+4 → 0+3)
- [x] Модификаторы складских полей не уходят в минус (тест `add: -10` → 0)
- [x] Инвалидация условная — три отдельных теста: непустой дифф → сброшен только сегмент; пустой дифф → ни один кеш не тронут; галочка → только выгрузки этого клиента
- [ ] Ручная проверка реальной выгрузки клиента на dev — после деплоя (флаг на стендах выключен)
