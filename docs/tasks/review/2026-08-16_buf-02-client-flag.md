# buf-02: галочка «страховой запас» на клиенте в CRM

**Приоритет:** высокий
**Эпик:** [buf-00](2026-08-16_buf-00-epic.md)
**Зависит от:** buf-01 (концептуально; технически независима)
**Создано:** 2026-08-16

## Описание

Явный признак клиента, к которому применяется занижение остатков. Решение
закреплено заказчиком: **никакой автоматики по анкете** — признак «интернет-магазин /
маркетплейсер» из CRM-профиля может быть неточным, галочку ставит менеджер руками.

### Поле

`users.stock_buffer_enabled` (bool, default false) — новая миграция с комментарием
столбца: «Страховой запас: клиенту показываются заниженные остатки по рисковым
товарам». Поле в `$fillable` не добавлять — менять только через CRM-экшен.

### CRM-карточка клиента

- Галочка «Страховой запас остатков» в карточке клиента `/crm/`, под правом
  `crm-clients.edit`; рядом — краткое объяснение, что именно изменится для клиента.
- Подсказка-рекомендация (не автопроставление): если в `crm_client_profiles`
  `business_type` ∈ {online, seller} или `works_with_marketplaces = 1` — бейдж
  «похоже на интернет-магазин, рекомендуем включить».
- Изменение пишется в лог/ревизии профиля, как остальные правки карточки.

### Список клиентов

Колонка или фильтр «страховой запас» в списке клиентов CRM, чтобы менеджер видел,
кому включено (ожидаемо ~50 клиентов).

## Критерии готовности

- [x] Миграция с комментарием столбца; флаг по умолчанию выключен у всех
- [x] Галочка в CRM-карточке под правом редактирования, подсказка по анкете — рекомендация, не автоматика
- [x] Фильтр («включён/выключен») + бейдж в строке списка клиентов CRM
- [x] Изменение флага фиксируется в журнале `crm_client_status_changes` (`field = stock_buffer`, кто и когда)
- [x] UI на Chakra-обёртках `@/components/ui/*` (Switch, NativeSelect), весь интерфейс на русском
- [x] Feature-тесты: вкл/выкл с журналом, no-op без мусора в журнале, 403 без права, рекомендация ≠ автоматика, round-trip фильтра
- [ ] Браузерная проверка на dev — после деплоя

## Решения по ходу реализации (2026-08-16)

- Права `crm-clients.edit` в матрице не существует — использовано `crm-profile.edit`:
  галочка живёт в том же блоке карточки, что профиль и жизненный статус,
  и меняет её тот же менеджер.
- Журнал — существующий `crm_client_status_changes` с новым `field = 'stock_buffer'`
  (прецедент: `lifecycle`, `user_kind`), а не отдельная таблица.
- Смена значения на то же самое журнал не засоряет (no-op).
- Рекомендация «похоже на интернет-магазин» считается на бэкенде:
  `business_type ∈ {online, seller}` или `works_with_marketplaces` — фронт получает
  готовый флаг `client.stock_buffer.recommended`.
