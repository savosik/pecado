# Налоговый режим юрлиц партнёров: сейчас и план на следующий год

**Приоритет:** высокий
**Создано:** 2026-09-11
**Ветка:** `feature/crm-tax-regime`
**Постановка:** РОП (Трипуть), 11.09.2026 — отчёт «риски потери объёма в связи с переходом клиентов
на НДС в следующем году».

## Зачем

Часть клиентов со следующего года начнёт платить НДС. Тот, кто будет принимать входящий НДС к
вычету (ОСНО или УСН по ставке 22 %), будет искать товар с НДС и может уйти к НДС-поставщикам —
в том числе к «Андрею», — тем вероятнее, чем меньше у нас будет НДС-ного товара. Чтобы оценить
риск, нужно знать режим каждого юрлица сейчас и на следующий год, а потом сопоставить это с тем,
сколько НДС-ного и не НДС-ного товара юрлицо берёт по реализациям (`shipment_items.vat_rate`).

## Что сделано

- **Признак — на юрлице** (`companies`), а не на партнёре: режим — свойство ИНН, реализации
  проведены на юрлицо (`shipments.company_id`), у 196 партнёров юрлиц больше одного.
- **Таблица `crm_contractor_tax_regimes`**: режим сейчас, план, год плана, комментарий, кто и когда
  подтвердил; журнал `crm_contractor_tax_regime_history`. В `companies` не пишем: модель
  принадлежит 1С, и её сохранение публикует контрагента в шину. ERP-контракт не затронут.
- **Варианты** (`App\Enums\Crm\TaxRegime`) сгруппированы по вопросу «принимает ли НДС к вычету»:
  ОСНО и УСН 22 % — с вычетами; УСН 5/7 % — без вычетов; УСН без НДС, патент, АУСН — без НДС;
  нерезидент. Для плана — ещё «партнёр не решил».
- **Смена режима** (`TaxRegimeShift`): переходит на НДС с вычетами / начинает платить 5–7 % /
  не решил / меняет режим без роста НДС / без изменений.
- **Данные не устаревают**:
  - ответ актуален 90 дней, «не решил» — 30 (`config/crm_tax_regime.php`, env `CRM_TAX_REGIME_*`);
  - 1 января года плана ответ устаревает безусловно, форма подставляет прошлогодний план в «сейчас»;
  - «Всё так же» — подтвердить без изменений одной кнопкой;
  - `crm:tax-regime-tasks` по понедельникам 06:25: одна задача на партнёра (тег «Налоговый режим»)
    по юрлицам, покупавшим за 365 дней, без актуального ответа; повторно не ставится; задача
    закрывается сама, когда ответы собраны.
- **Экраны**:
  - карточка партнёра, вкладка «Контрагенты» — блок «Налоговый режим» у каждого юрлица;
  - карточка контрагента — тот же блок;
  - список партнёров — отбор «Налоговый режим: уточнить / переходят на НДС / ещё не решили»;
  - `/crm/tax-regimes` «Налоговые режимы» — сводка (собрано, нужно подтвердить, не заполнено),
    сводка по менеджерам, плитки смены режима, фильтры, выгрузка в Excel.
- **Права**: заполнение — `crm-profile.edit` (как анкета), просмотр — `crm-contractors.view`.
  Новых ресурсов прав нет.
- **Тесты**: `tests/Feature/Crm/ContractorTaxRegimeTest.php` — сохранение и журнал, валидация,
  границы доступа, давность и Новый год, совпадение SQL и PHP на всех 81 сочетании режимов,
  отбор в списке партнёров, задачи (одна на партнёра, без дублей, автозакрытие), реестр и выгрузка.

## Опрос клиента на сайте (второй заход, 11.09.2026)

Документы у клиентов не запрашиваем (решение РОПа: без бюрократии). Режим, НДС и план клиент
указывает сам в коротком опросе; заодно спрашиваем, насколько ему важен НДС в товаре
(`VatPreference`: нужен к вычету / желателен / без разницы / лучше без НДС).

- **Охват**: из 112 покупающих партнёров 70 заходили на сайт за 30 дней — 71 % выручки.
  Остальных закрывает менеджер в CRM, как раньше.
- **Где показываем** (от тихого к заметному, всплывающих окон при входе нет):
  - ярлычок «Вопрос про НДС» у правого края на десктопе, пока есть о чём спросить;
  - карточка на дашборде кабинета;
  - карточка сразу после оформления заказа — флеш `order_placed` из чекаута.
- **Опрос** — шторка (справа на десктопе, снизу на телефоне), по вопросу на экран, ответ
  нажатием, у каждого вопроса «Не знаю — уточню у бухгалтера». По каждому покупающему юрлицу:
  «как работаете сейчас» и «а в следующем году»; в конце один вопрос про важность НДС.
- **Ненавязчивость**: «Не сейчас» прячет приглашение на 14 дней, после двух отказов — насовсем,
  остаётся только ярлычок (`crm_tax_survey_prompts`, на сервере — одинаково на всех устройствах).
- **Ответ клиента** пишется в ту же таблицу с `source = client`, закрывает задачу менеджера,
  в CRM виден как «ответ клиента на сайте». «Уточню у бухгалтера» не стирает уже известное и не
  продлевает старый ответ. Менеджер «Всё так же» переводит ответ на себя.
- **Менеджер в режиме «Просмотр от имени партнёра»** видит опрос так же, как клиент, и может
  пройти его во время звонка: ответ записывается от имени менеджера (`source = manager`,
  подтвердил — менеджер), в шторке предупреждение «ответ запишется от вашего имени».
  «Не сейчас» у менеджера прячет карточку только у него — за клиента опрос не откладывается
  (решение РОПа 14.09.2026).
- **Флаги**: `CRM_TAX_SURVEY_ENABLED`, `CRM_TAX_SURVEY_SNOOZE_DAYS`, `CRM_TAX_SURVEY_MAX_SNOOZES`.
- **Тесты**: `tests/Feature/User/TaxSurveyTest.php`.
