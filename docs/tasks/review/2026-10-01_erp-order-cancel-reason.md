# ERP — причина отмены строки заказа `cancel_reason` (v16.17.0)

**Приоритет:** высокий
**Создано:** 2026-10-01
**Источник:** Agent Hub, топик №17 «Заказ по устаревшему остатку» (seq 3–4), смежный топик №19
**Ветка:** `feature/erp-order-cancel-reason`

## Контекст

Инцидент 23.09.2026 («Отель Подушкин»): четыре заказа по одной штуке при остатке 2. Заказы 3 и 4
остались в 1С активными строками «Не обеспечивать», счёт ушёл на полную сумму, клиент о нехватке
не узнал. Решения заказчика 01.10.2026: строку без свободного остатка 1С отменяет сразу при приёме
заказа, счёт — только на отгружаемое. Вместе с этим 1С начинает передавать причину отмены строки —
вопрос, открытый с v16.5.0 (журнал недоборов размечался руками).

## Контракт

- `items[].cancel_reason` в `order.updated` и `order.created` (1С → Сайт): необязательная строка,
  `out_of_stock` / `shortage` / `client` / `reserve_expired` / `other`.
- **Не `enum`**: неизвестное значение сайт трактует как `other` (предупреждение в лог).
- Условие «при `cancelled = true` поле обязательно» схемой **не** накладывается: 1С включает поле
  поставкой, в очереди и в истории лежат сообщения без него; причина — аналитический признак,
  терять из-за неё статус и состав заказа несоразмерно.
- 1С с включением дробит строку при приёме: активная часть + отменённый хвост со своим `line_number`.

## Не сделано / вне объёма

- Клиентский API v1 (`ClientOrderPresenter::apiPayload`) причину не отдаёт — это изменение
  публичного контракта capi, отдельной задачей.
- Автоматическая разметка причины справочника по причине 1С — решение заказчика (short-01:
  «автоматика не проставляет»), вынесено вопросом.
- Фильтр журнала недоборов по причине 1С.
