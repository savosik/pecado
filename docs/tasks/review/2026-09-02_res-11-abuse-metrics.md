# res-11 · Метрики злоупотреблений и рычаг РОПа

**Приоритет:** средний
**Создано:** 2026-09-02
**Эпик:** [res-00](2026-09-02_res-00-epic.md)
**Зависимости:** res-09
**Волна:** 3

## Описание

Защита режима от «резервирую и бросаю». Дедлайн (res-09) — предохранитель на один заказ;
эта карточка — контроль привычек партнёра.

### Метрики по партнёру (за окно, например 90 дней)

- % подтверждённых резервов (подтверждено / всего резервов);
- % снятых по таймауту;
- доля правок (заказов с уменьшением состава после резерва);
- средняя длительность жизни резерва.

Источник — история статусов и `order_change_logs`; свой SUM по отгрузкам не изобретаем.
Сигнал отмен строк уже питает страховой буфер (`config/stock_buffer.php`) — не
дублировать его, а дополнить метрикой уровня партнёра.

### Экран РОПа

- Сводка по партнёрам в CRM (права по образцу `crm-`): сортировка по % снятых по
  таймауту, красная зона по порогу из конфига.
- Рычаги прямо из сводки: сократить индивидуальное окно резерва или отключить опцию
  партнёру (механизм отклонений из res-05).
- Действия строк — стандарт глаз/карандаш/корзина.

### Не делаем

- Автоматическое отключение по порогу — только сигнал и ручное решение РОПа
  (по духу проекта: не движок правил, а рычаг у человека).

## Ход работ

- **04.09.2026** — реализовано:
  - источник истины исходов — новое поле `orders.reserve_outcome`
    (confirmed/cancelled/expired) с индексом: флаг `reserve` при завершении
    обнуляется, и постфактум исход без поля не восстановить; пишется в
    `ClientOrderActions` (confirm/cancel) и `reserve:release-expired`;
  - экран `/crm/reserves` (`ReserveControlController`): по каждому участнику —
    активные резервы, подтверждено/отменено/сгорело за 90 дней, % сгоревших;
    красная зона по порогу `order_reserve.expired_share_alert` (30%, env),
    сортировка «злоупотребляющие сверху»; плашка-предупреждение при выключенном
    глобальном рубильнике;
  - рычаги РОПа прямо из сводки (право `crm-reserves.edit`): индивидуальное окно
    (1–168 ч) и тумблер «Отключён» (сужение поверх флага 1С); пустое окно +
    выключенный тумблер = возврат к умолчаниям = строка отклонения удаляется;
  - права `crm-reserves.{view,edit}` — три реестра (сидер + выдача sales-head,
    группы RoleController, меню CRM «Резервы заказов»), дрейф-тесты прав зелёные (91);
  - автоматики намеренно нет — только сигнал и ручное решение РОПа.
- Прогон на копии прода не делался: исходы копятся с нуля (поле новое), реальных
  данных до включения режима не существует.

## Критерии готовности

- [x] Метрики считаются по исходам резервов (`reserve_outcome`) — точнее, чем
  реконструкция по истории статусов; данные появятся с включением режима.
- [x] Экран РОПа со сводкой и красной зоной; рычаги окна/отключения работают из сводки.
- [x] Права настроены (три реестра: сидер, группы, меню — дрейф-тесты зелёные).
- [x] Feature-тесты на расчёт метрик, красную зону, рычаги и доступ по правам.
