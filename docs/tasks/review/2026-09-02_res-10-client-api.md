# res-10 · Клиентский API: резервы для интеграций магазинов

**Приоритет:** средний
**Создано:** 2026-09-02
**Эпик:** [res-00](2026-09-02_res-00-epic.md)
**Зависимости:** res-07, res-08, res-09
**Волна:** 3

## Описание

Конечная точка эволюции: розничный покупатель отказался на сайте интернетчика → его
система сама дёрнула наш API → резерв снят. Ноль людей в цепочке с обеих сторон.

Методы в `/api/client-api/{token}/*` (существующий контур интеграций клиентов),
зеркально кнопкам кабинета:

- список заказов в резерве — с `reserved_until`, составом и суммами;
- подтвердить (в отгрузку);
- изменить состав (те же ограничения v1, что в res-08: только уменьшение/удаление,
  полная замена состава, `revision`);
- отменить.

Правила:

- вся бизнес-логика — общая с кабинетом (те же сервисы/экшены, API — тонкий слой);
  никакого дублирования механики резервов;
- у партнёра с отключённой опцией (res-05) методы отвечают понятной ошибкой;
- ошибки конфликтов (`revision`, статус уехал) — машиночитаемые коды + русский текст;
- разумный rate limit по токену.

Документация — Scramble (`/docs/api`, `/docs/api.json`) подхватывает методы
автоматически; проверить полноту описаний и примеров.

## Ход работ

- **04.09.2026** — реализовано:
  - логика вынесена в общий `App\Services\Order\ClientOrderActions`
    (cancel/confirmReserve/updateReserveItems + `ReserveActionException` с
    машиночитаемым кодом) — кабинетные контроллеры res-04/07/08 отрефакторены
    на него, их 20 тестов зелёные без правок ожиданий;
  - методы `/api/client-api/{token}/reserves` (список с фактическим
    `reserved_until`, составом, суммами), `/reserves/{order}/confirm`, `/items`
    (целевой состав `{item_id, quantity}`, только уменьшение), `/cancel`;
    коды ошибок: `reserve_unavailable` (403), `order_not_found` (404, чужой
    заказ неотличим от несуществующего), `not_reserved`, `increase_forbidden`,
    `empty_composition`, `no_changes`, `not_cancellable`;
  - бонус сверх карточки: `reserve: true` в существующем `POST /orders` —
    интеграция создаёт резервный заказ сразу (в ответе `reserve`/`reserved_until`);
    неучастнику — явный 403, а не молчаливое игнорирование;
  - отмена через API помечается в истории статусов «Отменён клиентом через API»;
  - rate limit — общий throttle группы client-api (60/мин); Scramble подхватывает
    русские докблоки автоматически.
  - Тесты: `ClientApiReservesTest` (6 шт), смежные Api+Order — 224 зелёных, Pint чистый.
