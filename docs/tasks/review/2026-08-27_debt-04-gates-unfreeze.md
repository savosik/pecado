# debt-04: ограничения в чекауте и мгновенная разморозка — один релиз

**Приоритет:** высокий
**Эпик:** [debt-00 v2](2026-08-27_debt-00-epic.md)
**Зависит от:** debt-03 (нет письма — нет ограничения)
**Создано:** 2026-08-27

## Описание

`DebtGate` в `CheckoutService::checkout()` — единственная точка всех путей заказа:

| Ступень | Гейт |
|---|---|
| `no_preorders` | `type = preorder` отклоняется с объяснением и ссылкой на оплаты |
| `no_orders` | любые заказы от **этого контрагента** (`company_id`) отклоняются; другие контрагенты партнёра работают |
| `hold` | все заказы партнёра отклоняются; вход, каталог, корзина, оплаты работают |

Сообщение чекаута: причина + сумма + кнопка «к оплатам». `UserStatus::BLOCKED`
в лестнице не участвует. Никакого режима «отгрузка после оплаты» и лимитов — снято
за сложность (разбор в v1).

### Разморозка

Обработчики `settlement.posted` / `balance.updated` после записи данных диспатчат
событие; листенер пересчитывает ступень партнёра **только вверх**. Просрочка ниже
отсечки → `clean`, уведомление `finance.debt_cleared` один раз. Вниз — только
ночью (debt-02). Активная разблокировка (debt-05) снимает гейт, не меняя ступень.

## Критерии готовности

- [ ] Тесты гейта: ступень × тип заказа × контрагент; инвариант «нет письма — нет гейта»
- [ ] Разморозка по событию шины: идемпотентна при повторной доставке, только вверх — интеграционные тесты шины (обязательны)
- [ ] Ручная проверка на dev: платёж из эмулятора 1С снимает `no_orders` без людей
- [ ] Релиз гейта только вместе с разморозкой
- [ ] **Чек-лист выкатки:** в день включения гейта менеджер Гевеи вносит разблокировку
      на партнёра целиком (`company_id = NULL`, ≤ 14 дней, причина — договорённость
      об оплате); дальше продлевается по мере обещаний. Без этого первый ночной пересчёт
      закроет ей 5 юрлиц из 12 (1,37 млн у Литвиненко). Проверить на shadow-отчёте
      накануне, что разблокировка учтена
