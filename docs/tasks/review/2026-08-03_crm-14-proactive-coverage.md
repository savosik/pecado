# crm-14 · Проактивность: закрытие задачи с отчётом, следующий шаг и покрытие клиентов

**Приоритет:** высокий
**Создано:** 2026-08-03
**Эпик:** [crm-00](../backlog/2026-08-02_crm-00-epic.md)
**Волна:** 3 (работа менеджера), надстройка над [crm-09](2026-08-02_crm-09-tasks.md)
**Зависимости:** `crm-09` (задачи), `crm-01` (комментарии)

## Описание

Задачи из `crm-09` закрывались одной галочкой. Этого достаточно для учёта, но не для
работы: закрытая задача — это ровно тот момент, когда менеджер в последний раз думает
об этом клиенте, и если в этот момент не спросить «что дальше», клиент выпадает из работы
до следующего входящего звонка.

Отсюда три вещи, которые делает эта карточка:

1. **Закрытие с отчётом** — необязательный комментарий «что сделано», попадающий в ленту клиента.
2. **Следующий шаг** — необязательная follow-up задача прямо из формы закрытия, наследующая
   привязку и исполнителя.
3. **Покрытие клиентов задачами** — менеджер видит, по кому следующего шага нет.

Терминология проактивности здесь не украшение: разница между «реагировать на входящие»
и «планировать следующий контакт» — это ровно разница между первым и вторым квадрантом
матрицы Кови. Инструмент должен подталкивать ко второму, а не просто фиксировать первый.

## Что сделано

| Слой | Изменения |

| Тесты | `tests/Feature/Crm/TasksTest.php` — 7 новых сценариев |

### Решения, принятые по ходу

**Закрытие — отдельный эндпоинт, а не статус через PATCH.** Отметка, комментарий и следующая
задача должны лечь одной транзакцией. Разложенные по трём запросам с фронта, они допускали бы
закрытие с потерянным комментарием, который пользователь всё-таки написал.

**Оба поля формы необязательны.** Требовать отчёт по каждой мелочи — верный способ научить
людей не закрывать задачи вовсе, и тогда пропадёт вся статистика разом.

**Возврат задачи в работу диалога не показывает.** Это действие исправляющее, переспрашивать
о нём нечего.

**Follow-up наследует привязку и исполнителя.** Следующий шаг по клиенту — это шаг по тому же
клиенту, и заново искать его в поиске незачем. Срок по умолчанию — неделя.

**Покрытие считается по незакрытым задачам, включая задачи по документам клиента.** Задача
по заказу клиента — это задача по клиенту: денормализованный `client_user_id` для того и заведён.
Закрытая задача покрытием не считается — следующего шага по клиенту после неё нет.

**Блок покрытия на дашборде показывает не только процент.** Отчёт, из которого нельзя ничего
сделать, читают один раз, поэтому рядом с цифрой — первые пять непокрытых клиентов и кнопка
«Поставить задачу».

## Границы

- Автоматических задач по расписанию (например, «касание раз в квартал») не делаем: это
  генерация мусора, пока нет правил сегментации. Кандидат в отдельную карточку.
- Перепривязка существующей задачи к другой сущности не поддерживается — привязка выбирается
  только при создании.
- Норматив покрытия («не более N клиентов без задач на менеджера») не вводим: сначала нужно
  посмотреть на реальные цифры отдела.
