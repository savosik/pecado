# stack-00 · Стопки складов: приоритет складов региона для остатков, цен и заказов

**Приоритет:** высокий
**Создано:** 2026-08-19
**Статус:** реализовано на сайте (спека v16.6.0), в review; включение обоих флагов заблокировано ответами 1С
**Связанные:** [org-07](../done/2026-08-01_org-07-orders-outbound.md) — триггер «один заказ = один склад» наступил

## Суть

На уровне региона настраивается упорядоченная стопка primary-складов
(`region_warehouse.priority`, флаг `regions.stock_stack_enabled`). Верхний склад
**строго замещает** собой остатки и цены нижних по товарам, которые на нём
в наличии; чего нет наверху — фолбэк на склад ниже. Цель — торговля для
отдельных клиентов (отдельный регион + `users.region_id`) с отдельных складов
по иным ценам.

## Что сделано

- **Спека v16.5.0** (spec-first): семантика `warehouse_uuids` — для стопочных
  регионов сайт шлёт ровно один UUID, 1С проводит строго по нему; схема не менялась.
  `docs-erp/content/rules/orders.md` (раздел «Фиксация склада сайтом»), changelog,
  AsyncAPI, JSON Schema description.
- **БД**: `regions.stock_stack_enabled`, `region_warehouse.priority`
  (+ unique `(region_id, type, priority)`), `orders.assigned_warehouse_id`
  (отдельная колонка — roundtrip 1С её не затирает).
- **Ядро**: `WarehouseStackResolver` (чистый), `StockService` — замещение
  в `getStockMapsByIds`, `getWinningWarehouseMap` (мемо), подзапрос-победитель
  в `applyStockSubselects` (сортировка каталога); буфер (buf-04) вычитается
  из остатка победителя.
- **Цены**: победитель резолвится в `PriceService` (единая точка) для точечного
  и батч-пути; починен недетерминизм `findPrice`/`loadPriceMap` (правило
  «минимальный warehouse_id» без стопки) — раньше карточка и каталог могли
  показывать разные цены.
- **Заказы**: фиксация склада в транзакции `CheckoutService::checkout`, сплит
  группы `order` по складам в `OrderAssembler` (общий `checkout_uuid`),
  то же в клиентском API; `PublishOrderToErp` шлёт `[uuid победителя]`,
  костыль Тюмени и ветки preorder/defect/promo не тронуты; warning при
  расхождении склада проведения 1С с зафиксированным.
- **UI**: checkout — таблицы наличия по складам («Товары со склада „X“»),
  админка регионов — переключатель режима + сортируемая стопка.
- **Консолидация**: кабинетные корзины на `StockService` (заодно получили
  буфер), выедание буфера в экспорте — в порядке стопки.
- **Организации (частично, v16.6.0)**: `warehouses.organization_id` — справочная
  привязка нашего юрлица к складу (админка, эпик org-00 переиспользован).
  Опциональное поле `organization_uuid` в исходящем `order.created` —
  **подсказка**, не решение: 1С по-прежнему сама выбирает и возвращает
  организацию. Заполняется только при однозначной организации (обычно —
  зафиксированный склад стопки); при неоднозначности или без стопки — явный
  `null`. Закрыто отдельным переходным флагом `ERP_ORGANIZATION_UUID_ENABLED`
  (по умолчанию выключен, независим от флага фиксации склада).
- **Тесты**: 42 новых (резолвер, StockService, цены, чекаут, публикация
  в шину с валидацией схемы, roundtrip, админка регионов и складов,
  организация в исходящем заказе).

## Блокеры включения (вопросы 1С) и легаси-совместимость

Три независимых уровня защиты, пока 1С-разработчик недоступен:

1. **Флаг региона** `stock_stack_enabled` — по умолчанию выключен у всех:
   ничего не меняется вообще (ни на сайте, ни в шине).
2. **Переходный флаг складов** `ERP_STACK_WAREHOUSE_PINNING_ENABLED=false`
   (default): даже при включённой стопке региона `warehouse_uuids` уходит
   в прежнем легаси-формате (перечисление складов региона, 1С выбирает сама).
   Стопка при этом полностью работает на сайте; `assigned_warehouse_id`
   копится в БД, расхождения со складом проведения 1С логируются warning-ом.
3. **Переходный флаг организации** `ERP_ORGANIZATION_UUID_ENABLED=false`
   (default, независим от флага 2): пока выключен, `organization_uuid` в
   payload нет вовсе. Справочная привязка `warehouses.organization_id`
   на сайте работает уже сейчас — это флаг только про отправку в шину.

`docs/erp-1c-warehouse-stack-questions.md` — вопросы 1–3 блокируют включение
фиксации складов (строгое проведение, отключение фолбэка «ОсновнойСклад»,
больше пяти документов на оформление); вопрос 5 (обновлён) — подтверждение,
что приёмник безопасно принимает/игнорирует незнакомое опциональное поле
`organization_uuid`, и полный список UUID наших организаций для сверки
справочника (org-11). Нюанс легаси-режима складов: при включённой стопке без
флага пиннинга 1С может отгрузить не со склада-победителя (выбирает сама из
перечисления) — цена клиента при этом посчитана по победителю.
