# Багфикс — заказы уценки подписаны как «Со склада»

**Приоритет:** высокий (дефект на проде)
**Создано:** 2026-07-31
**Отделено от:** [promo-10-order-type-ui](../backlog/2026-07-27_promo-10-order-type-ui.md)

## Проблема

Тип заказа разбирался тернарником `type === 'preorder' ? … : …` — то есть «всё, что не
предзаказ, это заказ со склада». Уценка появилась в 2026-06 третьим типом, и восемь мест
об этом не узнали:

| Место | Что показывало для уценки |
|---|---|
| `Admin/Pages/Orders/Index.jsx` | «Со склада», бирюзовый бейдж |
| `Admin/Pages/Orders/Show.jsx` | «Заказ со склада» |
| `Admin/Pages/Orders/Edit.jsx` | «Заказ со склада» |
| `Admin/OrderController::index` | уценки нет в списке `types` — **фильтр по типу её не находил** |
| `Admin/ShipmentController` | `type_label` связанных заказов — «Заказ со склада» |
| `Cabinet/Shipments/Show.jsx` | «Заказ» |
| `Cabinet/Dashboard.jsx` (моб. + десктоп) | «Заказ» |

Уже знали про уценку и не тронуты: `Cabinet/Orders/Index.jsx`, `Cabinet/Orders/Show.jsx`
(у них своя логика тона), `User/OrderController` (в списке `types` уценка была).

## Что сделано

**Единый источник правды** — [resources/js/constants/orderType.js](../../../resources/js/constants/orderType.js):
`ORDER_TYPE_LABELS` / `ORDER_TYPE_SHORT_LABELS` / `ORDER_TYPE_COLORS` плюс геттеры.
Положен в `constants/`, а не в `utils/` как было в promo-10, — рядом с уже существующим
`orderStatus.js`, у которого ровно такая же роль.

Неизвестный тип → «Заказ» серым, без падения: из 1С может приехать документ с типом,
которого сайт ещё не знает.

**Серверная сторона** — `OrderType::options()` для списков фильтров и `OrderType::label()`
вместо литералов. Заодно `OrderType::ORDER->label()` уточнён с «Заказ» до «Заказ со склада»
(метод нигде не использовался, поэтому это не изменение поведения).

**Цвет предзаказа** в админке сменился с фиолетового на оранжевый — так предзаказ уже
подписан в каталоге и в клиентском кабинете. Уценка — красная, как в кабинете.
