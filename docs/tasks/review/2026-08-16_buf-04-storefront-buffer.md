# buf-04: врезка буфера в витрину и корзину

**Приоритет:** высокий
**Эпик:** [buf-00](2026-08-16_buf-00-epic.md)
**Зависит от:** buf-01 (сервис буфера), buf-02 (галочка), buf-03 (единая точка SQL)
**Создано:** 2026-08-16

## Описание

Собственно занижение. Включается флагом `STOCK_BUFFER_ENABLED`; для клиентов
без галочки поведение не меняется ни на грамм.

### `StockService` — available-путь

Для пользователя с `stock_buffer_enabled` карты и одиночные значения available
считаются как `max(0, sum − buffer)` через `StockBufferService::bufferMap()`
(буфер — производная при чтении, по прецеденту `PromoStockService`;
`product_warehouse` не трогаем). Preorder не занижается.

Цена для горячего пути — строго ноль: гость и клиент без галочки не должны
получить **ни одного** дополнительного SQL-запроса и ни одного лишнего
PHP-вызова, кроме проверки булева поля уже загруженного `User`. Для клиента
с галочкой карта буфера запрашивается **один раз на HTTP-запрос** (мемоизация
в `StockBufferService`): карточка + варианты + похожие + корзина в одном
запросе не должны ходить в `product_stock_buffers` четырежды. Сама таблица —
~100–150 строк по PK, но дисциплина «один запрос» дешевле споров о ней.

### Подзапросные места (из buf-03)

Поиск (`SearchApiController`) и избранное (`FavoriteController`) используют
подзапрос в ORDER BY — для пользователей сегмента подзапрос available строится
с `LEFT JOIN product_stock_buffers` и `GREATEST(0, … − buffer)`, чтобы сортировка
«в наличии первыми» не показала товар, который карточка уже считает нулевым.

### Корзина и чекаут

`CartService` зажимает количества через `StockService` — занижение подхватывается
само (`setQuantity`, `addToCart`, батч-пересчёт). Отдельно проверить сплит
instock/preorder: буфер уменьшает только instock-часть.

### Согласованность

Клиент с галочкой видит одно и то же число в: листинге, поиске, карточке/QuickView,
вариантах, избранном, корзине. Сквозной сценарий: рисковый SKU с остатком 5 и
буфером 2 → везде «3», в корзину кладётся максимум 3.

## Реализация (2026-08-16)

Точка врезки — два метода `StockService` (как и задумано buf-03):
`getStockMapsByIds()` (все карты: каталог, карточка, главная, корзина, экспорт,
client-api) и `applyStockSubselects()` (поиск, избранное). Гейт —
`buffersApplyTo()`: две булевы проверки (`config('stock_buffer.enabled')` +
`users.stock_buffer_enabled`), ноль SQL для гостей и клиентов без галочки.

`StockBufferService` скоуплен на запрос и при первом обращении поднимает всю
таблицу буферов одним запросом (~150 строк) — дальше карточка + варианты +
похожие + корзина отвечают из памяти. Клиент сегмента платит **+1 запрос на
HTTP-запрос** (в замерах ниже он не виден из-за прогретого мемо между
итерациями — в бою это один SELECT по PK-таблице).

Подзапрос для сегмента: `GREATEST((SUM…) − COALESCE(мануал ?? расчёт, 0), 0)`;
в SQLite (тесты) вместо GREATEST — скалярный двухаргументный MAX.
Проверено на локальной MySQL: подзапрос и карта дают одно число (товар 6126:
остаток 28, буфер 1 → 27 и там, и там).

Корзина: `CartService` зажимает через `StockService::getStock()` — занижение
подхватывается само; буфер уменьшает только instock-часть (preorder в картах
не трогается вообще).

## Замер A/B (один прогон подряд, тот же клиент с галочкой и без, копия прода)

| Страница | SQL с галочкой / без | p95 с галочкой / без, мс |
|---|---|---|
| Каталог | 12 / 12 | 363 / 341 |
| Поиск | 12 / 12 | 172 / 163 |
| Избранное | 14 / 14 | 48 / 51 |
| Карточка | 43 / 43 | 131 / 129 |
| Главная | 22 / 23 | 196 / 192 |

Разница p95 ±6 % — в пределах шума машины (избранное с галочкой даже быстрее).

- [x] Карта буфера мемоизирована: один запрос к `product_stock_buffers` на HTTP-запрос (тест со счётчиком)
- [x] Замер под клиентом с галочкой: p95 в пределах погрешности (таблица выше)
- [x] Клиент с галочкой: available занижен и одинаков в картах, подзапросах и enrich (`StockBufferApplicationTest`)
- [x] Preorder не занижается; корзина зажимает через тот же `getStock()` (буфер бьёт только instock-часть)
- [x] Поиск/избранное: подзапрос с GREATEST проверен на локальной MySQL, согласован с картой
- [x] Гости и клиенты без галочки не задеты (тесты неизменности + счётчик запросов)
