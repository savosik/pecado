# crm-28 · Лиды: воронка, время на этапе, аналитика по отделу и менеджеру

**Приоритет:** средний
**Создано:** 2026-08-12
**Эпик:** [crm-00](../backlog/2026-08-02_crm-00-epic.md)
**Волна:** 7 (взаимозаменяемость и охват), этап 3 из 3
**Зависимости:** `crm-27` (стадии и журнал переходов)

## Описание

Воронку по лидам нужно **видеть визуально** — в том числе по отделу и по каждому менеджеру.
Плюс две метрики времени: **сколько дней конкретный лид находится на текущем этапе** и
**сколько этот этап занимает у лидов в среднем**.

Вторая метрика — самая полезная в разделе: она превращает «лид завис» из ощущения в факт.
Если квалификация обычно занимает три дня, а этот лид висит двенадцать — с ним что-то не так.

## Источник данных

Всё считается из `crm_lead_stage_transitions` (`crm-27`) и текущей стадии лида. Своего движка
расчёта не заводить и в аналитику отгрузок не лезть: лиды с отгрузками не связаны, это
самостоятельная витрина.

## Ловушки метрики, зафиксированные заранее

**Средняя длительность — только по завершённым переходам.** Если считать по всем лидам,
находящимся на этапе, застрявшие занижают метрику: лид, который войдёт в статистику через
полгода, сейчас в неё не попадает вовсе, и этап выглядит быстрее, чем есть.

**Медиана рядом со средним.** Один лид, зависший на полгода, перекашивает среднее по этапу
так, что цифрой нельзя пользоваться. Показывать обе.

**Малая выборка.** Лидов сейчас единицы; при 2–3 переходах «средняя длительность этапа» —
шум. Показывать число наблюдений рядом с метрикой и скрывать её ниже порога, иначе на первом
же брифинге по ней примут решение.

**Возвраты назад по воронке.** Лид может уйти на предыдущую стадию. Считать надо **сумму
времени на стадии по всем заходам**, а не разницу между первым входом и выходом.

**Конверсия — по флагам `is_won` / `is_lost`**, а не по последней колонке: добавление стадии
в конец не должно молча ломать цифру.

## Разрезы и права

- Воронка по отделу и по менеджеру. **Разрез по менеджерам — РОПовское право**, ровно как выручка
  в `crm-21`: менеджеру-соседу видны лиды коллеги (взаимозаменяемость), но не его сводные
  показатели.
- Свои цифры менеджер видит всегда.
- Фильтры: период, источник лида, менеджер, воронка (если появится `funnel_id` из `crm-27`).

## Реализация графиков

Перед первой строкой кода диаграммы **загрузить skill `dataviz`** — он задаёт палитру,
формы и правила подписей, чтобы график не выпадал из остального интерфейса.

Формы: воронка — горизонтальные полосы с числом и суммой на каждой стадии; время на этапе —
таблица со средним, медианой и числом наблюдений. Экзотику не изобретать, читаемость важнее.

## Критерии готовности

- [ ] Воронка показывает число лидов и сумму квалификации по стадиям
- [ ] «Дней на текущем этапе» видно в карточке лида и на канбан-карточке
- [ ] Средняя и медианная длительность этапа считаются по завершённым переходам
- [ ] Тест: возврат лида на предыдущую стадию суммирует время по обоим заходам
- [ ] Тест: конверсия считается по флагам стадии, а не по позиции
- [ ] Метрика скрыта или помечена при выборке ниже порога
- [ ] Разрез по менеджерам недоступен рядовому менеджеру — тест
- [ ] Pint, PHPStan, ESLint чистые; UI на русском
- [ ] Визуальная проверка на https://dev.pecado.ru/crm/leads
