# buf-03: рефакторинг — SQL остатков в одной точке

**Приоритет:** высокий (предусловие buf-04)
**Эпик:** [buf-00](2026-08-16_buf-00-epic.md)
**Создано:** 2026-08-16

## Описание

Сегодня остатки витрины считаются двумя независимо выросшими ветками:
`StockService` (корзина, чекаут, экспорт, client-api) и подзапросы
`ProductQueryService::withRegionStockSums` (каталог, поиск, избранное, похожие,
акции, главная через `enrichProductsWithStock`). Это историческая случайность
(git: подзапросы появились 14.02.2026 под статус «Предзаказ», батч-методы
`StockService` — позже и только для экспорта). Чтобы буфер в `buf-04` врезался
в одно место, а не в пять, SQL остатков переезжает в `StockService`. **Поведение
не меняется** — чистый рефакторинг, выкатываемый и проверяемый отдельно.

### Что переезжает в `StockService`

- Новый комбинированный `getStockMaps(iterable, ?User): array{available, preorder}` —
  оба типа за 2 запроса (как текущий `enrichProductsWithStock`), а не 4
  (как пара `getAvailableStockMap` + `getPreorderStockMap`), иначе регресс листинга.
- Вариант по ID (`...ByIds`) для главной, где товары приходят массивами из кеша,
  а не моделями.
- Построение подзапросов `primary_stock`/`preorder_stock` — методом-scope в
  `StockService`; `ProductQueryService::withRegionStockSums` становится тонким
  адаптером над ним.
- Дублирующий резолв региона (`resolveRegionId` vs `getRegionWarehouseIds`) —
  в одно место; гостевой фолбэк `Region::defaultId()` сохраняется.

### Потребители: перевод на батч-вызов после `paginate()`

Сортировки/фильтра по алиасам у них нет — замена безболезненна:

- `CatalogApiController` (фильтры наличия и так идут через `scopeAvailable`/`scopeInStock` c `whereExists`);
- `ProductByIdsController`, `PromotionController`, `Api/Content/ProductController`
  (учесть подмену региона через `?region_id`);
- `SimilarProductsService` (фильтр «есть остаток» переписать с атрибутов модели на map);
- `enrichProductsWithStock` — главная, карточка товара, QuickView, варианты.

Бонусом уходит хрупкость: обязательный `select('products.*')` перед
`withRegionStockSums` (каталог, избранное) и костыль `toBase()` в
`CatalogFacetService`.

### Потребители: подзапрос остаётся (участвует в ORDER BY до пагинации)

- `SearchApiController` — «в наличии выше предзаказа выше отсутствующих»;
- `FavoriteController` — сортировка `stock_desc`.

Оба используют подзапрос, построенный `StockService`-ом, — SQL остатков живёт
в одном файле.

### Замер производительности (обязателен, до мержа)

Рефакторинг принимается только с доказательством «не медленнее». На dev
(или локально на копии прода, `make db-pull-prod`):

- **Число SQL-запросов на страницу** (debugbar/Telescope) до и после — по
  каждому потребителю: каталог, поиск, избранное, карточка товара, главная,
  страница акции. Рост числа запросов = блокер.
- **Тайминг** тех же страниц (p50/p95 по 20 прогонам, хотя бы `ab`/`wrk` или
  ручной замер из Telescope) — до и после, таблицей в карточку.
- Ловушка «4 запроса вместо 2»: пара `getAvailableStockMap` +
  `getPreorderStockMap` дублирует резолв складов региона — использовать только
  комбинированный `getStockMaps()`. В `StockService` — мемоизация карты складов
  региона в пределах запроса, чтобы карточка + варианты + похожие не резолвили
  регион трижды.

## Разведка перед реализацией (2026-08-16, факты из кода)

- `getRegionWarehouseIds()` не мемоизируется: **карточка товара резолвит регион 3 раза**
  (enrich вариантов [ProductController.php:517](../../app/Http/Controllers/User/ProductController.php#L517), enrich товара `:771`, похожие через `SimilarProductsService`),
  **главная — 1 + N подборок + 2 раза**; избранное с фильтром наличия — 2 раза.
- Каталог на один запрос делает **минимум два независимых чтения `region_warehouse`**:
  `getRegionWarehouseIds()` + свой резолв в `CatalogQueryBuilder`/`scopeAvailable`.
- `SearchApiController::applyRelevanceOrder` ставит `ORDER BY primary_stock` **раньше**,
  чем `withRegionStockSums` добавляет алиасы (строки 62 vs 73) — работает лишь потому,
  что алиасы появляются до `paginate()`. При рефакторинге сохранить.
- Бонус-находки (баги вне скоупа, кандидаты в отдельные карточки):
  - `Api/Content ProductController::show()` вообще не считает остатки —
    `stock_quantity`/`preorder_quantity` в детальной карточке всегда 0;
  - фильтр `in_stock` в Content API — no-op: `inStock('instock')` зовётся без
    `$regionId`, а скоуп при null-регионе молча возвращает запрос как есть;
  - подмена региона `?region_id` в Content API не покрыта тестами;
  - сортировка избранного `stock_desc` не покрыта тестами (grep по tests/ пуст).
- `StockServiceInterface` принимает модели Product; батч-по-ID нет — нужен для главной
  (массивы из кеша). Реализация одна, биндинг в `AppServiceProvider:47`.
- Тесты-стражи порядка выдачи: `SearchApiControllerTest::test_products_include_unavailable_by_default`
  (наличие выше предзаказа выше отсутствующих), `CatalogApiControllerTest::test_guest_uses_default_region_for_availability`,
  `test_guest_response_hides_prices_and_stock`, `StockServiceBatchMapTest` (счётчик запросов).

## Решение по реализации (2026-08-16) — консервативнее карточки

SQL остатков переехал в `StockService` (карты, подзапросы, резолв региона —
один файл, мемоизация на HTTP-запрос через scoped-биндинг), но **потребители
остались на прежнем статическом API**: `withRegionStockSums` /
`enrichProductsWithStock` / `getRegionWarehouseIds` стали тонкими адаптерами
над `StockService`. Перевод потребителей на «батч после paginate()» из
карточки НЕ выполнен намеренно:

- замена коррелированных подзапросов на батч-вызов добавляла бы по +1
  запросу на страницу каталога/поиска — прямое нарушение принципа
  «рост числа запросов = блокер»;
- цель «буфер врезается в одну точку» достигается и так: buf-04 правит два
  метода одного файла — `getStockMapsByIds()` (все карты) и
  `applyStockSubselects()` (поиск/избранное);
- диff в 4 файла вместо ~12 — меньше поверхность регресса.

Хрупкий `select('products.*')` перед подзапросами остаётся (задокументирован
в `applyStockSubselects`). Костыль `toBase()` в фасетах остаётся. Новое:
комбинированная карта `getStockMaps()`/`getStockMapsByIds()` (оба типа склада
за 1 запрос + мемо региона), `Region::defaultId()` для гостей мемоизируется.

`storage/app/measure-stock.php` (не в гите), повторяем в обоих деревьях.
