# Промо, баг — кратность считается по первому условию, а не по сработавшему

**Приоритет:** высокий (правило молча не выдаёт награду)
**Создано:** 2026-07-28
**Исправлено:** 2026-07-28
**Найдено:** при разборе механики условий на обкатке волны 1
**Затрагивает:** [promo-02-engine](2026-07-27_promo-02-engine.md)

## Симптом

Правило с режимом **«Достаточно любого»** и наградой с кратностью **«На каждые N»**
срабатывает, но **не выдаёт ничего**. Ни награды, ни причины в предпросмотре — в блоке
«Что было бы выдано» пусто, в «Почему не выдаётся» тоже пусто. Выглядит как поломка сайта.

## Причина

[`PromotionEngine::buildRewards()`](../../../app/Services/Promotion/PromotionEngine.php)
берёт значение агрегата из **первого** условия правила:

```php
// Кратность считается по первому условию правила — оно и задаёт «на каждые N»
$primaryValue = (float) ($outcome['items'][0]['value'] ?? 0);
```

Дальше:

```php
$multiplier = $this->multiplier($reward, $primaryValue);   // floor($primaryValue / per_value)
if ($multiplier < 1) {
    continue;                                              // награда молча пропускается
}
```

При режиме `all` это безобидно: выполнены все условия, первое в том числе. При режиме
`any` правило срабатывает от **любого** условия — и если сработало второе, а по первому
в корзине пусто, то `$primaryValue = 0`, множитель `0`, награда пропускается через
`continue`. Правило числится сработавшим, награды нет, причина не сообщается.

Решение «считать по первому условию» принято в карточке 02 сознательно — награда не
указывает, к какому условию относится «на каждые N», и «первое» было единственным
детерминированным выбором. Про сочетание с `any` тогда не подумали.

## Что сделать

Минимальный честный фикс — считать множитель по **первому сработавшему** условию:

```php
$satisfied = array_filter($outcome['items'], fn (array $item) => $item['satisfied']);
$primaryValue = (float) (reset($satisfied)['value'] ?? 0);
```

Детерминированность сохраняется (позиции условий упорядочены), при `mode: all` поведение
не меняется вовсе — там сработали все, первое сработавшее и есть первое.

Отдельно решить на ревью: если сработали несколько условий с разными агрегатами
(штуки и рубли), брать первое или максимум множителя. Предлагаю первое — предсказуемее
для маркетолога, а «сумма по нескольким условиям» относится к
[promo-13](2026-07-28_promo-13-per-item-multiplicity.md).

**Сделано:** взят первый сработавший. Про несколько сработавших условий вопрос
снят вместе с promo-13: если позиции условия задают свои шаги, множитель
складывается по ним, и «первое сработавшее» остаётся только запасным путём
для правил, где шаг задан в награде.

## Подстраховка

Даже после фикса возможен ноль (например, `per_value` больше, чем набрано, — хотя порог
взят по другому условию). Молчать в этом случае нельзя: добавить в `blocked` причину для
предпросмотра, чтобы админ видел «кратность не набрана», а не пустоту. Клиенту, как и
прежде, ничего не показываем — список причин закрытый, потребуется шестая
(`MULTIPLIER_NOT_REACHED` в `App\Enums\PromoBlockReason`).

**Сделано:** причина добавлена шестым случаем перечисления, движок кладёт её в
`blocked` вместо `continue`. Заодно валидатор теперь не даёт сохранить шаг больше
порога — самый частый способ получить нулевую кратность закрыт на входе.

## Критерии готовности

- [x] Тест: правило `mode: any`, два условия, сработало второе, награда с
      `per_threshold` — награда выдаётся, множитель считается по сработавшему условию
      (`test_multiplier_uses_first_satisfied_condition`).
- [x] Тест: при `mode: all` поведение не изменилось
      (`test_multiplier_in_mode_all_still_uses_first_condition`).
- [x] Тест: если множитель всё же ноль, в `blocked` появляется причина
      (`test_zero_multiplier_is_reported_as_blocked`).
- [x] Клиенту причина не утекает — `/api/cart/promotions`
      (`unreached_multiplier_is_not_shown_to_the_client`).

## Что изменилось в коде

| `app/Services/Promotion/PromotionEngine.php` | `multiplier()` принимает все позиции условия, считает по сработавшим; нулевой множитель уходит в `blocked` |
| `app/Enums/PromoBlockReason.php` | шестая причина `MULTIPLIER_NOT_REACHED` |

## Временный обход — снят

Обход «при кратности «на каждые N» держать в правиле одно условие» больше не нужен.
