# crm-17 · Лента-чат как главная вкладка карточки клиента

**Приоритет:** высокий
**Создано:** 2026-08-04
**Эпик:** [crm-00](../backlog/2026-08-02_crm-00-epic.md)

**Зависимости:** [crm-16](2026-08-04_crm-16-clients-table.md), `crm-01` (комментарии), `crm-09` (задачи), `crm-10` (письма)

## Описание

Карточка клиента показывала пять равноправных вкладок, из которых лента была третьей
и умела только читать. Чтобы записать мысль после разговора, менеджер шёл во вкладку
комментариев; чтобы поставить следующий шаг — в задачи; чтобы приложить счёт — в файлы.
Три разных места для одного действия «зафиксировать, что произошло с клиентом».

Теперь лента — главная вкладка и работает как чат: хронология сверху, поле ввода снизу.
В хронологию попадают не только записи менеджеров (комментарии, задачи, письма), но и
то, что делал сам клиент — заказы и реализации. Одна стена вместо пяти вкладок.

Режимы поля ввода: комментарий (Ctrl+Enter), задача (Enter, чипы срока «сегодня / завтра /
+3 дня / неделя», исполнитель по умолчанию — автор), письмо, файл. Каждый уходит в свой
существующий эндпоинт.

### Решения, принятые по ходу

**Лента расширяется, а не переписывается.** Новые источники приходят в той же форме записи
(`type, id, happened_at, author, title, excerpt, entity, can`), только с флагом `system` и
суммой. Ни один существующий ключ не изменился — врезка `EntityCrmPanel` и админские карточки
продолжают работать без правок.

**Документы датируются бизнес-датой 1С.** `COALESCE(erp_created_at, created_at)`: по
`created_at` вся импортированная история встала бы одним днём поверх свежих записей.
`whereNull('deleted_at')` проставлен явно — `DB::table()` не применяет SoftDeletes.

**Четвёртый ключ сортировки — `source`.** `id` уникален внутри источника, но не между ними;
без него страницы «плавали» бы на записях с одинаковой датой. Тест `pagination_is_stable_across_pages`
это фиксирует.

**Общего `feed.store` нет.** Composer дёргает `/crm/comments`, `/crm/tasks`, `/crm/emails`,
`/crm/attachments` — единый эндпоинт с полиморфным диспатчем неизбежно разошёлся бы в правах
и валидации с теми четырьмя, что уже работают.

**Файл в ленте вешается на комментарий-подпись.** `MediaService` не умеет загружать «в никуда»,
поэтому сначала запись, потом файл. Если загрузка упала — комментарий остаётся, к нему можно
приложить файл повторно, а не терять написанный текст.

**Закреплённые вынесены отдельным блоком.** В чате они ломали бы хронологию, а «важное»
должно быть на виду постоянно.

**`lazyMount` без `unmountOnExit`.** Размонтирование теряло бы позицию скролла ленты и
черновик поля ввода при каждом переключении вкладки. Ленивый монтаж остаётся — четыре
вкладки не грузятся разом.

**Вкладка «Комментарии по клиенту» удалена.** Её заменяет фильтр типов в ленте; сам
`CommentThread` остался — он нужен в `TaskDialog` и админских карточках.
