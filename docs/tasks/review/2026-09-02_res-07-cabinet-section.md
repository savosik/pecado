## Описание

Отдельный пункт меню кабинета «Заказы в резерве» — рабочее место интернетчика.

### Список

- Только заказы в статусе «Резерв»; в строке — **живой таймер обратного отсчёта**
  до `reserved_until` (отсчёт на клиенте, без запросов на каждый тик).
- Бейдж-счётчик резервов на пункте меню — чтобы висящие резервы не забывались.
- Состояние «истекает скоро» визуально акцентировано (порог — например, < 6 ч).
- Действия строк — по стандарту глаз/карандаш/корзина (`RowActions`), без текстовых кнопок.

### Детали резервного заказа

- Тот же таймер + **три полноценные кнопки** (не иконки):
  - **«Отправить в отгрузку»** — подтверждение: заказ переходит в обычный конвейер
    (исходящее сообщение по протоколу res-01/res-02), уходит из раздела в «Заказы»;
  - **«Редактировать»** — правка состава (res-08);
  - **«Отменить»** — снятие резерва целиком (механика res-04, ConfirmDialog).
- После истечения срока заказ не исчезает молча — ясное состояние «резерв снят».

### UX

- Идеально на десктопе и мобильном: основной сценарий — правка с телефона сразу после
  звонка покупателю; операции в один-два тапа.
- Стандарты кабинета: русский язык, карточки с фоном (не «серое на сером»), минимализм
  эффектов, Chakra через `@/components/ui/*`.
- У партнёра с отключённой опцией раздел скрыт (но с живыми резервами — виден, пока они
  не доживут).

## Ход работ

- **04.09.2026** — реализовано за рубильником:
  - `GET /cabinet/reserves` (`ReserveOrderController@index`) — карточки резервов
    с живым таймером (`components/cabinet/ReserveCountdown.jsx`: тик на клиенте,
    < 6 ч — красный, истёкший показывает «резерв истёк», не исчезает молча),
    сортировка по сроку, пустое состояние с подсказкой;
  - `POST /cabinet/orders/{order}/confirm-reserve` — публикует `order.confirmed`,
    локально снимает признак (заказ уходит из раздела, статусы приедут эхом из 1С);
    гонка со снятием резерва → 422, чужой заказ → 403;
  - страница заказа: фиолетовая плашка резерва (таймер + «Отправить в отгрузку»
    с ConfirmDialog) и бейдж «В резерве» рядом со статусом (резервные приезжают
    как «Готов к отгрузке» — без бейджа клиент запутается);
  - меню кабинета: пункт «Заказы в резерве» (виден только участнику —
    `config.reserves_enabled` из shared props) с бейджем-счётчиком
    (`config.reserve_count`; ноль запросов к БД для неучастников и при
    выключенном рубильнике);
  - кнопка отмены на странице заказа — из res-04; правка состава — в res-08.
  - Тесты: `ReserveCabinetSectionTest` (7 шт), ESLint/tsc чистые.
- Мобильная вёрстка — кнопки полноразмерные, колонки схлопываются; живая проверка
  на экране — при включении флага на dev (совместные испытания).
