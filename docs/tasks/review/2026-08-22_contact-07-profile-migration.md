## Описание

В анкете партнёра (`crm_client_profiles`) восемь колонок свободного текста про контактных лиц:
бухгалтер, собственник, ЛПР — ФИО и контакт одной строкой. Переносим их в справочник.

Риск измерен и близок к нулю: на проде заполнена **одна анкета из 185**. Проверить перенос
глазами — минута.

## Маппинг

| Анкета | Контакт |
|---|---|
| `owner_name` + `owner_contact` | роль `owner` |
| `accountant_name` + `accountant_contact` | роль `accountant` |
| `decision_maker_name` + `decision_maker_contact` | роль `manager` |
| `decision_maker_role` | `position` |
| `decision_maker_birthday` | `birthday` |

Парсер строки — восстановленный `parseContact()` из
`git show 0fb19a22^:app/Services/Notifications/ClientContactService.php` (регулярки на почту
и телефон), но с **ослабленным условием**: строка без почты тоже переносится. В прошлый раз
контакт без адреса был бесполезен для рассылки; теперь это нормальная карточка телефонной книги.

`source = 'profile_import'`, привязка к партнёру, `is_active = true`. Миграция идемпотентна:
повторный прогон не плодит записи.

## Колонки пока не удаляются

Двухшаговый порядок с релизом между шагами. Дроп — в
[contact-15](../backlog/2026-08-22_contact-15-cleanup.md), после того как перенос проверен глазами.
Неделю данные полежат в двух местах: это допустимо, месяц — нет.

## Форма анкеты

На месте секции «Контакты по ролям» — врезка `ContactsPanel` со ссылкой в справочник.
Менеджер не должен гадать, куда делись поля.

## Критерии готовности

- [ ] Миграция данных, идемпотентная
- [ ] Строка без почты переносится (в отличие от прошлого подхода)
- [ ] На dev перенесена единственная заполненная анкета, проверена глазами
- [ ] В форме анкеты вместо текстовых полей — врезка справочника
- [ ] Колонки анкеты **не** удалены
