# Сортировка каталога «По умолчанию» + починка «Новинок»

**Приоритет:** высокий
**Создано:** 2026-09-04
**Зависимости:** нет

## Проблема

Каталог открывался сортировкой «Новинки» — чистое `created_at DESC`. Наверху выдачи
оказывались предзаказные позиции и товары с нулевой ценой: по дате создания они как раз
самые свежие, а купить их нельзя.

## Решение

### 1. Полки наличия в витринных сортировках (`App\Enums\CatalogSort`)

Обе витринные сортировки сначала раскладывают выдачу по полкам живого наличия
(алиасы `primary_stock` / `preorder_stock` из `StockService::applyStockSubselects`),
и только внутри полки работает содержательный порядок:

- **`default` («По умолчанию»)** — полка наличия → товары с ценой → балл `sort_score` ↓ → id ↓;
- **`newest` («Новинки»)** — новинки в наличии → остальное наличие → предзаказ → остальное,
  внутри полки: товары с ценой → `created_at` ↓.

Полка живая, а не из снимка: товар, приехавший на склад утром, поднимается сразу, не
дожидаясь ночного пересчёта.

### 2. Балл витрины `products.sort_score` (0–1000)

Команда `catalog:rebuild-sort-scores` (расписание — ежедневно в 02:50) считает балл из двух
признаков продаж за скользящее окно 90 дней (`config/catalog_ranking.php`):

- **выручка** — `shipment_items.total` в рублях по реализациям 1С;
- **охват** — сколько разных контрагентов купили товар за окно.

Каждый признак — координата вектора товара, сжимается логарифмом и делится на максимум по
каталогу: `ln(1+x)/ln(1+max) ∈ [0,1]` (линейное деление прижало бы к нулю весь каталог,
кроме первой десятки). Дальше — скалярное произведение с вектором экспертных весов,
приведённым к сумме 1 (по умолчанию 0.5 / 0.5), и масштаб в 0…1000.

Наличие в балл **не входит намеренно** — иначе снимок наличия жил бы в базе сутки и спорил
бы с живыми остатками. Требование «товары не в наличии всегда ниже» выполняет полка.

Окно — скользящее, а не календарный квартал: 1-го числа нового квартала продаж почти нет,
и весь каталог обнулился бы разом.

### 3. Витрина открывается «По умолчанию»

- `DEFAULTS.sort = 'default'` (`resources/js/utils/compactFilters.js`) — каталог, категории,
  бренды, подборки;
- `CatalogApiController` без параметра `sort` тоже берёт `default`;
- поиск сохраняет свой дефолт — `relevance`;
- контентное API (`/api/content/products`) сохраняет прежний дефолт `newest`, значение
  `default` там доступно параметром.

## Тесты

- `tests/Unit/Enums/CatalogSortTest.php` — порядок по баллу, нулевая цена вниз, состав опций;
- `tests/Feature/CatalogSortShelvesTest.php` — полки наличия в `default` и `newest`, дефолт API;
- `tests/Feature/Console/RebuildCatalogSortScoresTest.php` — рост балла от выручки и охвата,
  окно, обнуление выпавших, защита от пустого окна, `--dry-run`.

## Не делаем

- Ручной перебивки балла в админке (экспертный оверрайд) — не просили; веса правятся
  конфигом/`env` без релиза.
- Нормировки внутри категории: балл глобальный, в категории важен только относительный
  порядок — он тот же.
- Пересчёта чаще раза в сутки: за сутки продажи порядок почти не двигают, а наличие в
  сортировке и так живое.
