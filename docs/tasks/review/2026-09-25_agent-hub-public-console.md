# Пульт Agent Hub по ссылке-хешу + API создания топиков

**Статус:** review (реализовано 2026-09-25, ветка `feature/agent-hub-public`)

## Суть

Диалоги ИИ-агентов были видны только из админки сайта — со своим входом и правами.
Смотреть за ними нужно двоим: нашему администратору и администратору 1С, у которого
учётки на сайте нет и не будет. Теперь есть **ссылка-хеш на весь пульт**: по ней
без авторизации открывается список топиков, карточка любого из них и всё
модераторское управление. Той же ссылкой внешний агент (агент 1С) авторизует
**API создания топиков** — заводить их через человека в админке больше не нужно.

## Ключевые решения

- **Одна ссылка на весь хаб, а не на топик.** Вопрос был «что видно по ссылке»:
  выбран пульт целиком (список + создание + управление), потому что адресат —
  администратор, которому нужен обзор, а не один разговор. Ссылок можно завести
  несколько (своя 1С, своя нам) и отозвать любую поимённо.
- **По ссылке можно всё, что умеет админка.** Отдельного «только смотреть» уровня
  нет намеренно: два класса ссылок пришлось бы объяснять и поддерживать, а защита
  всё равно держится на секретности 64-символьного хеша. Отзыв — одна кнопка.
- **API авторизуется тем же хешем.** Никаких вторых токенов: кому дали ссылку,
  тот и заводит топики. `POST /api/agent-hub/links/{token}/topics` возвращает
  обе агентские ссылки — дальше диалог идёт по ним, как и раньше.
- **Идемпотентность создания.** `external_key` в паре со ссылкой: ретрай возвращает
  тот же топик (`repeated: true`, 200 вместо 201). Это же держит правило «агент 1С
  однозадачный — топики не плодить»: у процесса один ключ, один топик.
- **Первый ход можно оставить себе** — `turn: "erp"` при создании, иначе ход
  по умолчанию у агента сайта.
- **Модерация вынесена в сервис.** `TopicModerationService` — одна логика на три
  входа (админка, пульт, API): системные сообщения о правке задачи, передача хода,
  закрытие. Сообщение с пульта подписывается меткой ссылки (`payload.via`), в ленте
  видно, кто из наблюдателей вмешался.
- **ERP-контракт не затронут:** канал чисто HTTP, RabbitMQ и AsyncAPI ни при чём.

## Состав

- Миграция `2026_09_25_120000_create_agent_hub_links_table` — таблица ссылок
  плюс `agent_topics.{hub_link_id, created_by_agent, external_key}` (комментарии БД).
- Модель `AgentHubLink` + фабрика; `AgentTopic` знает свою ссылку.
- Middleware `agent-hub.link` (`ResolveAgentHubLink`): 404 на отозванную и
  неизвестную, отметка `last_used_at`, `X-Robots-Tag: noindex`.
- Пульт `App\Http\Controllers\AgentHub\HubController` + страницы
  `Pages/AgentHub/{HubLayout,Index,Show}` — `/agent-hub/{token}`.
- API `App\Http\Controllers\Api\AgentHubLinkController` — `/api/agent-hub/links/{token}`
  (discovery, список, карточка, создание). Подхватывается Scramble на `/docs/api`.
- Админка ссылок `App\Http\Controllers\Admin\AgentHubLinkController` +
  `Admin/Pages/AgentTopics/Links` — `/admin/agent-topics/links`, права
  `agent-topics.{view,create,edit}` (новых прав нет).
- Тесты: `tests/Feature/AgentHub/HubLinkPageTest`, `tests/Feature/Api/AgentHubLinkApiTest`,
  `tests/Feature/Admin/AgentHubLinksAdminTest` — 41 тест вместе с прежними.

## Как выдать доступ

1. `/admin/agent-topics` → «Ссылки на пульт» → «Выдать ссылку», подписать («Админ 1С»).
2. Кнопка «Пульт» копирует адрес страницы, «API» — адрес для агента.
3. Отзыв — корзина в строке: страница и API этой ссылки гаснут сразу,
   созданные по ней топики и ссылки агентов продолжают работать.
