# crm-02 · Вложения к клиентам, заказам, реализациям, комментариям и задачам

**Приоритет:** высокий
**Создано:** 2026-08-02
**Эпик:** [crm-00](2026-08-02_crm-00-epic.md)
**Волна:** 1 (фундамент)
**Зависимости:** `crm-01` (комментарии — одна из целей вложения)

## Описание

Дать возможность прикреплять файлы к карточке клиента, заказу, реализации, комментарию, задаче
и письму. Требование сквозное: одна и та же механика во всех местах, один компонент на фронте.

## Ключевое решение: используем существующую MediaLibrary, новой таблицы нет

`spatie/laravel-medialibrary` уже стоит и настроен: таблица `media` полиморфна, диск берётся
из `MEDIA_DISK` (на dev и prod — S3/MinIO), есть санитайзер имён `SanitizingFileNamer`,
кастомный URL-генератор и сервис-обёртка `App\Services\Media\MediaService`
(`upload / attach / copy / delete / syncTags`). Двенадцать моделей уже используют
`InteractsWithMedia`, включая `User`.

Заводить свою таблицу вложений незачем — это дало бы второй механизм хранения со своим диском,
своим удалением файлов и своими URL. Ровно так сделано в `kanban_task_attachments` (своя таблица,
диск `public`, мимо MediaLibrary) — **этот путь не повторяем**, он и так исключение.

## Что делаем

**Трейт `App\Models\Concerns\HasCrmAttachments`** — единая точка регистрации коллекции:

```php
public function registerMediaCollections(): void
{
    $this->addMediaCollection(self::CRM_ATTACHMENTS)
        ->acceptsMimeTypes([...]);   // whitelist, образец — App\Models\UserQuestion
}
```

Подключается к `Order`, `Shipment`, `CrmComment`, `CrmTask` (волна 3), `CrmEmail` (волна 3).
`User` уже использует `InteractsWithMedia` — там добавляется только коллекция; существующие
коллекции модели не трогаются.

Whitelist mime по образцу `UserQuestion`: изображения (jpeg/png/webp/gif), pdf, doc/docx,
xls/xlsx, csv, txt. Лимит 20 МБ на файл — как в Kanban API, чтобы у пользователей был один
понятный порог во всём проекте.

**Контроллер `Crm\AttachmentController`** — `store` и `destroy`, работает через `MediaService`.
Резолв сущности — через `App\Support\Crm\CrmEntityMap` (карточка `crm-01`), не через имя класса
из запроса. Вложения полиморфны ровно там же, где комментарии и задачи: новая привязываемая
сущность появляется во всех трёх механиках одной строкой в карте.

**Авторизация — по владельцу вложения, а не по вложению.** Право `crm-attachments.create`
проверяется вместе с доступом к самой сущности: можно приложить файл к заказу ровно тогда,
когда этот заказ виден в скоупе `User::visibleInCrm($actor)`. Иначе загрузка файла стала бы
дырой в обход проверок карточки.

**Роуты** в `routes/crm.php`:

```
POST   /crm/attachments            — multipart: entity_type, entity_id, file
DELETE /crm/attachments/{media}    — удаление (автор загрузки или РОП)
```

**Фронтенд:** `resources/js/Crm/Components/AttachmentPanel.jsx` — обёртка над существующим
`resources/js/Admin/Components/FileUploader.jsx` (multi-file, drag&drop, превью, `existingFiles`
+ `onRemoveExisting`, лимиты). Свой загрузчик не пишем; импорт по прямому пути, не через бочку
`@/Admin/Components` — она тянет EditorJS и tiptap.

**Права** в `RolesAndPermissionsSeeder`: ресурс `crm-attachments` с действиями
`view, create, delete` (`edit` для файла бессмыслен), метка «CRM: Вложения». Выдать
`sales-manager`, `sales-manager-crm`, `sales-head`.

## Границы

- Загрузка «в никуда» (unattached) не поддерживается: `MediaService::upload()` намеренно бросает
  исключение без модели. Файл к новой задаче или письму прикрепляется **после** сохранения
  черновика — форма должна создавать черновик первым шагом.
- Превью и конвертации (thumbnails) не делаем: вложения CRM — документы, а не витрина товара.
- Миграция БД не требуется — таблица `media` уже есть.

### Решения, принятые по ходу

**Константы вынесены из трейта в `CrmAttachments`.** Константы трейта в PHP нельзя читать
через имя трейта — только через использующий класс. А имя коллекции, whitelist mime и лимит
нужны там, где модели нет вовсе: в правилах формы, в контроллере и в тестах.

**`User` больше не подключает `InteractsWithMedia` напрямую** — он приходит внутри
`HasCrmAttachments`. Два пути к одному `registerMediaCollections()` дают фатальную коллизию
методов, и она проявляется только в рантайме.

**Отказ MediaLibrary превращается в 422.** Валидация формы проверяет *заявленный* тип файла,
а MediaLibrary — фактическое содержимое. Пустой файл с расширением `.pdf` проходил первую
проверку и падал 500-й на второй; теперь это обычная ошибка поля с русским текстом.

**Комментарий добавлен в `CrmEntityMap`** — файлы прикладываются и к комментариям.
Чтобы это не открыло вложенные треды, у карты появился отдельный список
`commentableTypes()`: комментировать можно всё, кроме самого комментария.

**Автор загрузки — в `custom_properties`.** MediaLibrary его не хранит, а правило
«удалить может автор или РОП» без него не работает.
