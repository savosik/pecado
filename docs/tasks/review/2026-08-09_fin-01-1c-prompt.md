## Описание

Первый шаг эпика — **не** схемы. Мажорную спецификацию дорого переделывать, если сторона 1С
чего-то не сможет отдать, поэтому сначала пишем черновой контракт и техзадание, отправляем его
и получаем построчное подтверждение. Схемы фиксируются в `fin-02` **после** ответа.

Это сознательное отступление от обычного порядка проекта (spec-first): здесь меняется не поле
в существующем сообщении, а сама модель денег и источник истины по ней.

Артефакт — `docs-erp/content/guides/settlements-for-1c.md` по образцу
[`payment-schedule-for-1c.md`](../../../docs-erp/content/guides/payment-schedule-for-1c.md):
самодостаточный промт, который копируется в ИИ-агента, дорабатывающего обмен на стороне 1С:КА2.

## Что делаем

### 1. Промт для 1С

Обязательные разделы (структура унаследована от существующих `guides/*-for-1c.md`):

| Раздел | Содержание |
|---|---|
| Роль и задача | Разработчик 1С:КА2, дорабатывающий обмен с `pecado.ru` через RabbitMQ |
| Зачем это бизнесу | Клиент не видит своего долга — цифра на сайте расходится с 1С в разы. Привести цифры из `fin-00` |
| Что меняется концептуально | Сайт **перестаёт считать** деньги. 1С становится источником истины. Разнесение платежей на документы сайту больше не нужно |
| Что нужно от 1С | Пять новых событий + правки трёх существующих — таблицей |
| Формат данных | JSON-примеры каждого события целиком |
| Соответствие регистрам и реквизитам КА2 | Таблица «поле JSON → регистр / реквизит 1С» |
| **Знаковое соглашение** | Отдельным разделом с таблицей и примером — самое опасное место |
| Соответствие кодов | Латинские коды `type`, `settlement_procedure`, `settlement_object_kind` + русские `*_name` |
| Правила, которые нельзя нарушать | Полная замена, а не дельта; идемпотентность по `uuid`; `revision` |
| Порядок первичной выгрузки | Соглашения → сальдо 01.01.2026 → движения → графики → checkpoint 01.07.2026 |
| Критерии приёмки | Чек-лист |
| Если что-то не сходится | DLQ, типовые ошибки |
| **Вопросы, на которые нужен ответ** | Список из `fin-00`, с местом для ответа по каждому |

### 2. Черновой контракт внутри промта

Пять новых событий:

| Событие | Очередь | Единица |
|---|---|---|
| `agreement.created` / `.updated` / `.deleted` | `erp_in.contractors` | Соглашение |
| `settlement.opening_balance` | `erp_in.settlements` | Сальдо на 01.01.2026 (несверенное) |
| `settlement.checkpoint` | `erp_in.settlements` | Сверенное сальдо на 01.07.2026 |
| `settlement.posted` | `erp_in.settlements` | **Все** движения одного документа |
| `settlement.reverted` | `erp_in.settlements` | Отмена проведения документа |
| `payment_schedule.updated` | `erp_in.settlements` | График оплат **с остатками** |

Три ломающих правки:

| Событие | Правка | Как объяснить 1С |
|---|---|---|
| `payment.*` | `allocations[]` **убрать** | Разнесение теперь выражено движениями регистра. Формировать его больше не нужно — это экономия и на стороне 1С |
| `shipment.*` | `payment_schedule[]` **убрать** | Переезжает в `payment_schedule.updated`, где у строки есть остаток |
| `balance.updated` | `overdue_details[]` **убрать** | Просрочка выводится из плановых строк; новых уровней не добавляем |

### 3. Раздел про знак — писать отдельно и подробно

Самая вероятная ошибка внедрения. Нужны: таблица знаков по каждому `type`, числовой пример
(сальдо → реализация → частичная оплата → возврат товара) со сходящимся итогом, и явное
предупреждение, что перепутанный знак **не ловится валидацией схемы** — только сверкой.

### 4. Вопрос про остаток по плановой строке — ключевой

Если 1С **не** сможет отдавать `settled_amount`, вся экономия эпика теряется: сайту придётся
вернуть самодельный FIFO, который и породил расхождение 5,53 млн ₽ против 478 тыс ₽. Вопрос
задать явно, ответ получить до `fin-02`.

## Edge-кейсы, которые проговорить в промте

- **Расчёты без соглашения.** Как размечать такие движения?
  Ответ 1С: соглашения покрывают 100 %; при пустом `agreement_uuid` сайт сводит движения в группу
  «Без соглашения». Не терять и не выдумывать.
- **Документ, которого на сайте нет** (например, отчёт комиссионера). Движение всё равно
  присылается, реквизиты — в `document_kind` + `document_number` + `document_date`.
- **Курс валюты.** Ответ 1С: курса нет, есть `СуммаРегл` — рублёвый эквивалент от учёта. Принято, лучше нашего варианта: не разъедется с
  отчётами 1С.
- **Объём.** Ответ 1С: 224 632 строки по 17 607 документам за 2026.
- **Отмена проведения задним числом** документа за закрытый период.
