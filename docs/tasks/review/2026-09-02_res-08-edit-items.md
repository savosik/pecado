# res-08 · Редактирование состава резервного заказа

**Приоритет:** средний
**Создано:** 2026-09-02
**Эпик:** [res-00](2026-09-02_res-00-epic.md)
**Зависимости:** res-07, res-03
**Волна:** 2

## Описание

Клиент правит состав резервного заказа сам — вместо звонка «уберите две позиции».

- **В v1 только уменьшение**: снизить количество, удалить строку. Добавление позиций
  (рост суммы резерва, риск по остаткам) — отдельное решение после обкатки, в эту
  карточку не входит.
- Экран правки в деталях резервного заказа (res-07): изменение количества, удаление
  строк, итоговая сумма пересчитывается на лету. Удаление последней строки = отмена
  заказа целиком (через ConfirmDialog, механика res-04).
- Сохранение → исходящий `order.updated` с **полным** составом (зеркально семантике
  входящего `HandleOrderUpdated`) и `revision` — канал res-03.
- Конфликт: если `revision` на сайте отстал (менеджер успел править в 1С) — правка
  отбивается понятной ошибкой на русском с предложением обновить страницу; правила —
  из resolution res-01.
- Каждая правка — в `order_change_logs` через `OrderChangeLogger` (клиент видит
  «было → стало» в журнале изменений кабинета, как для правок из 1С).
- Мобильный UX: правка количества удобна пальцем (степперы, не только ввод с клавиатуры).

## Ход работ

- **04.09.2026** — реализовано за рубильником:
  - `POST /cabinet/orders/{order}/reserve-items` (`ReserveOrderController@updateItems`):
    клиент шлёт ЦЕЛЕВОЙ состав `{id, quantity}`, отсутствующие строки удаляются;
    только уменьшение (увеличение → 422 с подсказкой «оформите отдельный заказ»),
    пустой состав → 422 «используйте отмену», без изменений → 422; вне окна резерва →
    422, чужой → 403, флаг выключен → 404;
  - локально: транзакция (количества, subtotal, пересчёт total_amount), журнал
    `order_change_logs` через `OrderChangeLogger::logItemChanges` (source=client);
    затем исходящий `order.updated` с полным составом и `base_items_version`
    (= последний применённый `items_version` от 1С, 0 для заказа без эха);
  - конфликт версий разруливает 1С: отставшую правку отклонит и вернёт актуальный
    состав с `conflict{}` — сайт применит его обычным входящим `order.updated`
    (обработчик уже принимает items и пишет журнал);
  - UI: редактор состава — панель в плашке резерва (не правка большой таблицы):
    степперы NumberInput (min 1, max текущее), удаление строки с «Вернуть»,
    живой пересчёт «Новый итог», кнопки «Сохранить изменения»/«Отменить правку»;
    удаление последней строки открывает диалог отмены заказа (res-04);
    на время правки кнопка «В отгрузку» заблокирована.
  - Тесты: `ReserveItemsUpdateTest` (6 шт), смежные Order+Erp — 395 зелёных,
    ESLint/tsc/Pint чистые.

## Критерии готовности

- [x] Уменьшение/удаление строк работает, добавления в UI нет, сервер отбивает попытку добавить.
- [x] `order.updated` уходит с полным составом и `base_items_version` (интеграционный тест;
  по resolution блокировка идёт по версии состава, не по `revision`).
- [x] Конфликт версий: 1С отклоняет и возвращает актуальный состав с `conflict{}` —
  сайт применяет его штатным входящим `order.updated`.
- [x] Правки видны в журнале изменений заказа (source=client).
- [x] Удаление последней строки превращается в отмену заказа через ConfirmDialog.
- [x] Мобильная вёрстка свёрстана (степперы, столбики); живая проверка — при включении
  флага (испытания).
