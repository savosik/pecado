# ЭПИК: чат-помощник клиента в кабинете (assist-00)

**Приоритет:** средний
**Создано:** 2026-09-19
**Статус:** **включён на проде 22.09.2026** (коммит `3f6b7d97`): ключ организации и
`CLIENT_ASSISTANT_ENABLED=true` в `.env` прода, `assistant:ping` через прокси проходит, сквозной сценарий
от тестового клиента 860 отработал (client-catalog + client-balance через MCP-коннектор, журнал —
канал `web-assistant`). На dev ключа нет — помощник там спрятан.
Ветка `feature/assist-client-chat` (worktree `.claude/worktrees/assist`) слита в `dev` и `main`. Сделано: волны 1–4, CRM-вкладка и воронка в `/crm/agent-usage` (assist-01…09),
49 тестов с фейковым шлюзом. Осталось (assist-10): лимит workspace в консоли Anthropic; ключ на dev; ручная приёмка в браузере
(иконка, реплики, заказ по кнопке, фото прайса, Excel, голос); страница в «Инструкциях» кабинета.

**Проверено на проде 23.09.2026 (`80311a42`):** xlsx-прайс конкурента от тестового клиента 861 —
вложение распознано как `table` (по содержимому zip, а не по MIME браузера: `kindFor` ищет по массиву
конфига, так как точки в MIME Excel ломали путь `config()`), ушло в Files API (`FileParam::fromResource`,
`file_id` записан), модель прочитала книгу через `bash_code_execution`, вызвала `client-prices` по
артикулам и ответила таблицей «у конкурента / у нас» со ссылками на карточки; ход $0,05 на Sonnet 5.
Тогда же: полоса прокрутки страницы больше не ложится поверх панели (`marginRight` = ширина полосы,
измеряется при открытии и resize); в `/crm/agent-usage` активные ключи считаются только по `kind=personal`.

**Отклонения от плана при реализации (19.09.2026):**
- Право для вкладки в CRM — существующее `crm-agent-usage.view` (тот же домен «ИИ-агенты клиентов»),
  новый ресурс `crm-assistant` не заводится: три реестра прав и роли не трогаются.
- Ходы модели идут в очередь `assistant` со своим супервизором Horizon (таймаут 600 с, без повторов);
  «один ход на тред» обеспечивает статус хода в базе, а не замок уникальности job-а.
- Канал в журнале `client_agent_calls.agent` = `web-assistant` (коннектор Anthropic шлёт свой clientInfo,
  отличить чат можно только по виду токена).
- Вложения хранятся в ходе заглушкой `x-attachment` и разворачиваются в блоки по `file_id` Files API
  при сборке запроса (изображения/PDF — `image`/`document` с `source.file`, таблицы — `container_upload`).
- Реплики иконки отдаёт `GET /cabinet/assistant/bubble` (BubbleResolver), правила частоты — в localStorage
  клиента по порогам из `config/assistant.php`.
- Стоимость хранится с точностью до 6 знаков (decimal 12,6): ход на Opus 5 стоит доли цента.
- Job хода идёт явно на соединение `redis` (на проде очередь по умолчанию — RabbitMQ): первый прогон
  22.09 лёг в RabbitMQ-очередь без потребителя, исправлено в `3f6b7d97`.
**Вне эпика:** публичный сайт и гости без аккаунта (решение 19.09.2026 — только кабинет); мессенджеры и
«одно окно» сотрудников (`docs/chats/chat-00-tz.md`); голос; подписки Claude Code / Codex / OpenClaw как
транспорт (запрещены условиями вендоров, см. `project_anthropic_api_access.md`); OpenRouter как канал к
Claude (есть организация в поддерживаемой стране, платим напрямую); ERP-протокол (чат потребляет уже
принятые из 1С данные и оформляет заказ прежним путём через операции клиентского API).

## Идея

У клиентов уже есть `/mcp/client` с 77 операциями (capi-00), но чтобы им пользоваться, нужно поставить
Claude Code, Cursor или другого MCP-клиента и завести токен. Это барьер, из-за которого журнал
`client_agent_calls` почти пуст, а руководитель делает вывод «агенты никому не нужны». Эпик убирает
барьер: тот же агент с теми же правами живёт прямо в кабинете как чат. Клиент пишет «покажи мой долг»,
«собери заказ по этому прайсу», кидает фото или Excel — агент вызывает операции MCP от его имени, помнит
предыдущие разговоры и подтверждает необратимые действия кнопкой.

Проверка спора — те же метрики, что в capi-17: успешные `orders.create` / `checkout.submit` /
`questions.create` в `/crm/agent-usage`, но теперь с отдельным каналом «чат сайта».

## Решения заказчика (19.09.2026)

1. **Только авторизованным клиентам, но на всех страницах сайта.** Плавающая кнопка помощника
   видна клиенту с юрлицом везде: каталог, карточка товара, корзина, кабинет, документы. В кабинете
   его «не найти» — точка входа должна быть там, где клиент сейчас. Гостям не показывается.
   Помощник **слегка привлекает внимание** (уточнение 19.09.2026): цель эпика — конверсия
   авторизованных клиентов в диалог, она и есть мера спора «агенты никому не нужны».
2. **Менеджер видит переписку своего клиента, только чтение.** Вкладка в карточке партнёра CRM.
3. **Запуск сразу всем клиентам кабинета** одним рубильником `CLIENT_ASSISTANT_ENABLED`,
   без персональных флагов.
4. **Оплата напрямую Anthropic** на организацию компании в поддерживаемой стране. С прода API достижим
   только через `pecado-outbound-proxy` (напрямую 403 по региону — проверено 19.09.2026).
5. **Путь к операциям один — MCP.** Чат является MCP-клиентом `/mcp/client`, а не параллельным вызовом
   `OperationRunner`: каждая реплика в чате — живой прогон слоя MCP, второй путь не деградирует.
6. **Файлы читает модель, а не наш парсер.** Скриншот, фото, PDF — штатные блоки запроса; Excel —
   серверное выполнение кода Anthropic (Files API + `code_execution`). Детерминированную сверку с
   каталогом («найди дешевле, чем у конкурента») **не** делаем сейчас — по итогам пилота, отдельной
   операцией реестра, чтобы её получили и CLI-агенты.

## Принципы

1. **Messages API + MCP-коннектор.** Запрос в `POST /v1/messages` с `mcp_servers` (url
   `https://pecado.ru/mcp/client`, `authorization_token` = токен клиента) и `tools: [{type: mcp_toolset}]`
   (бета `mcp-client-2025-11-20`). Список инструментов и их вызовы Anthropic делает сам; наш код не
   описывает инструменты и не крутит цикл. Сервер Anthropic должен достучаться до `pecado.ru:443` —
   он публичный, открывать ничего не нужно.
2. **Токен чата — короткоживущий.** Полный вечный токен клиента наружу не отдаём. Новая миграция:
   `api_tokens.kind` (`personal` | `assistant`) и `expires_at`; воркер выпускает токен на тред с TTL
   (конфиг, по умолчанию 1 час), продлевает при активности, отзывает по завершении. Права те же, что у
   личного токена (токен один и полный — решение capi-00), отличается только срок жизни. Клиенту в
   `/cabinet/api-tokens` такие токены не показываются.
3. **Журнал — канал по виду токена.** `ClientServer` при `kind = assistant` пишет в
   `client_agent_calls.agent` значение `web-assistant` (коннектор Anthropic представляется своим
   `clientInfo`, заголовков в `mcp_servers` нет). `/crm/agent-usage` получает разрез «чат сайта / свои
   агенты». Аргументы и ответы операций в журнал по-прежнему не пишутся.
4. **История append-only, блоки как есть.** В `chat_messages.content` хранится JSON массива блоков
   ответа целиком (включая `thinking` с подписями и результаты MCP-вызовов), не текст. Воркер собирает
   `messages` из базы в том же порядке. Историю не редактируем; инструкции по ходу треда — сообщением
   `role: system` внутри `messages`; длинный тред сжимается серверной компакцией
   (бета `compact-2026-01-12`), блок компакции сохраняется как обычное сообщение.
5. **Память клиента — в нашей базе.** (а) `client_assistant_notes` — заметка о клиенте на несколько КБ
   (как обращаться, что заказывает, предпочтения), модель дописывает её по закрытии треда отдельным
   дешёвым запросом; (б) резюме закрытых тредов; (в) поиск по старым тредам — инструмент на Meilisearch
   (добавляется во второй волне, если заметки не хватит). Векторного RAG на старте нет. В заметку
   никогда не попадают токены и пароли.
6. **Кеш промпта.** Порядок запроса: инструменты (одинаковые у всех клиентов) → системный промпт
   (заморожен, без дат и идентификаторов) → заметка о клиенте (маркер `cache_control`) → история.
   Правильность проверяется тестом на `usage.cache_read_input_tokens > 0` на втором ходу.
7. **Необратимое — только кнопкой.** `orders.create`, `checkout.submit`, `returns.create`,
   `questions.create` модель вызывает лишь после подтверждения человеком: перед вызовом выводит карточку
   (состав, сумма, юрлицо), клиент жмёт «Оформить». Реализуется как тул-конфиг коннектора
   (`configs` по инструменту) + инструкция в системном промпте + проверка на нашей стороне:
   `Idempotency-Key` для заказа генерирует воркер и хранит в треде.
8. **Потолок расходов — в трёх местах.** Лимит workspace в консоли Anthropic (не наш код);
   `config/assistant.php`: дневная квота диалогов и токенов на юрлицо, предел токенов на тред,
   месячный предел организации. Стоимость каждого хода считается из `usage` по прайсу в конфиге и
   хранится в `chat_messages` — видна в CRM.
   **Кончился баланс — помощник исчезает; пополнили — появляется сам** (решение заказчика
   19.09.2026). Никаких «помощник отдыхает» на весь сайт: недоступный сервис не рекламируют.
   - `AssistantAvailability` держит флаг в кеше: `available` / `unavailable(reason)`. В `unavailable`
     его переводит воркер по ошибке API `402 billing_error` (кончились кредиты), по отказу из-за
     лимита workspace, по отсутствию ключа, по недоступности `outbound-proxy` и по нашему месячному
     пределу организации. Флаг уходит в shared-props Inertia, `AssistantLauncher` при `unavailable`
     **не рендерится вообще**: ни иконки, ни реплик, ни пункта меню; `/cabinet/assistant` отвечает 404.
   - **Возврат автоматический**: пока флаг `unavailable`, планировщик раз в 10 минут делает пробный
     запрос минимальной стоимости (`max_tokens: 1`, без инструментов) через тот же прокси; успех
     переводит флаг в `available`, иконка появляется у всех при следующем переходе. Наш месячный
     предел снимается сам первого числа. Ручной переключатель — команда `assistant:availability`.
   - Тред, в котором баланс кончился посреди ответа: ход помечается `failed`, клиенту показывается
     нейтральное «Не удалось ответить, попробуйте позже», тред не закрывается и продолжится, когда
     сервис вернётся. Токен `assistant` при этом отзывается по обычному TTL.
   - Исчерпание **персональной** квоты юрлица — не то же самое: иконка остаётся, диалог говорит,
     сколько осталось и когда квота обновится, и предлагает `questions.create`. Это единственный
     случай «отдыхает», и он виден одному клиенту, а не всем.
   - РОПу и роли `sales-head` при `unavailable` — внутреннее уведомление `assistant.unavailable`
     через матрицу (адресат `manager`, одно письмо на смену состояния, не чаще раза в час), чтобы
     пополнение баланса не зависело от того, что кто-то заметил пропажу иконки.
9. **Модель.** `claude-opus-5`, `thinking: adaptive`, `output_config.effort` из конфига (старт `low`),
   `fallbacks: "default"` на отказ по безопасности; модель и усилие — переменные окружения, чтобы
   перевести рутину на Sonnet 5 без релиза. Стриминг в воркере; клиенту — polling `/cabinet/assistant/…`
   раз в секунду с частичным текстом (как `/crm/salary/data`), без WebSocket.
10. **Изоляция.** Тред принадлежит `user_id`; юрлицо выбирается в треде (умолчание — как в API:
    `is_default` → единственная → модель спрашивает). Менеджер видит треды только своих клиентов
    (`crm-clients-all.view` — всех), права `crm-assistant.view`. Таблицы `chat_*` и
    `client_assistant_notes` **исключены** из `bi:sync-grants` (переписка конфиденциальна).
11. **Файлы.** Клиент прикрепляет файлы кнопкой-скрепкой, перетаскиванием в диалог и вставкой
    скриншота из буфера. Разрешённые форматы и размеры — только из `config/assistant.php`
    (`attachments.mimes`, `attachments.max_size`), одинаково проверяются на фронте (до загрузки,
    с русским текстом ошибки «Формат .exe не поддерживается», «Файл больше 20 МБ») и на бэке
    (`FormRequest`, по содержимому, а не по расширению). Старт: изображения jpg/png/webp/heic,
    pdf, xlsx/xls/csv, docx; 20 МБ на файл, до 5 файлов на сообщение. `chat_attachments`: оригинал
    в MinIO (`assistant/`), превью для изображений, срок хранения — как у треда. Изображения и PDF
    уходят блоками `image`/`document`; таблицы и docx — через Files API + инструмент `code_execution`
    (в контейнере Anthropic есть openpyxl/pandas/python-docx; 1 550 бесплатных часов в месяц на
    организацию, далее $0,05/ч). `file_id` хранится, чтобы не загружать повторно. Файлы клиента
    менеджер в CRM видит и может скачать (вкладка read-only).
12. **UI на русском.** Название — «Помощник». Все тексты, ошибки, состояния квот — по-русски.
13. **Паттерн «онлайн-консультант»** (уточнение заказчика 19.09.2026). Помощник свёрнут в приятную
    иконку в углу и живёт в корневом лейауте, переживая переходы Inertia (состояние в `zustand`).
    При переходе на страницу из иконки **всплывает одна короткая реплика** (пузырь с хвостиком,
    одна строка до ~70 знаков), которая **лучше всего подходит контексту этой страницы**, держится
    несколько секунд и **гаснет сама**. Клик по реплике открывает диалог с этим вопросом и контекстом
    страницы; клик по иконке — просто диалог.
    - **Реплики выбирает код, не модель**: каталог фраз по типу страницы и данным клиента в
      `config/assistant.php` и `AssistantPromptResolver`. **Каждая реплика — уже ответ или действие
      из данных, никогда не «спросить у менеджера».** Карточка товара: «Есть 120 шт, под ваш заказ
      хватит — добавить 24?» / «Сейчас только предзаказ, приедет к 28 сентября — оформить?»; заказ:
      «Собран, ждёт выдачи сегодня до 21:00 — показать состав?» / «Сборка идёт, будет готов к 14:40»
      (стадия из `OrderFulfilmentResolver`, срок из `WarehouseSchedule`); документы: «Сверка за август
      готова — скачать?»; долг: «Просрочка 12 дней по счёту № 418 на 36 400 ₽ — показать график?»;
      резерв: «Резерв истекает завтра — продлить или отгрузить?»; каталог: «Пришлите прайс или фото —
      подберу по вашим ценам». Стоит ноль токенов и показывается мгновенно. Реплики, сгенерированные
      моделью персонально, — кандидат после пилота.
    - **Ненавязчивость — правилами частоты**: не чаще одной реплики на N переходов и на M секунд,
      не больше K за сессию, одна и та же фраза не повторяется, тишина при открытом диалоге и пока
      идёт ответ, после трёх закрытий подряд — пауза на сутки. Все пороги в конфиге.
    - **Только дешёвая анимация** (`feedback_ui_effects_minimal.md`): плавное появление и угасание
      через `opacity`/`transform`, без сдвига вёрстки, с уважением `prefers-reduced-motion`. Без звука,
      без автооткрытия диалога, без модалок. Тихая точка на иконке, когда есть повод (готов ответ,
      истекает резерв, недобор при сборке).
    - **Одноразовое знакомство** при первом входе после релиза: реплика «Я помощник: цены, заказы,
      документы, долг. Спросите» — закрыл, больше не увидит ни на одном устройстве (отметка в профиле).
    - События пузырей (`bubble_shown`, `bubble_clicked`, `bubble_dismissed`) идут в `chat_events` —
      по ним видно, какие фразы на каких страницах ведут в диалог, и каталог фраз правится без релиза
      кода, если вынести его в настройки CRM (кандидат после пилота).
14. **Контекст страницы уходит в запрос.** Виджет передаёт `page` (тип, id товара / заказа / раздела)
    первым сообщением треда: модель сразу знает, о чём речь, и не переспрашивает артикул. Контекст
    добавляется только к новому ходу (append-only), в системный промпт не вписывается.
16. **Помощник заменяет менеджера, а не теребит его** (уточнение заказчика 19.09.2026). Всё, что есть в
    данных сайта, помощник отвечает сам и до конца: стадия и срок готовности заказа
    (`OrderFulfilmentResolver`, `WarehouseSchedule`), остатки и предзаказ со сроком, цены клиента, долг
    и график по регистру, документы и сверка, резервы, возвраты, уведомления, пропуск курьеру. Системный
    промпт прямо запрещает предлагать «уточню у менеджера», если операция реестра даёт ответ.
    `client-ask-manager` — последний ход и только для того, чего в данных нет (список из инструкций
    `ClientServer`: объединить заказы в одну отправку, придержать до прихода предзаказа, самовывоз к
    часу, трек-номер, разблокировка по долгу, замена недовезённого). Каждый такой вопрос — сигнал о
    дыре: доля диалогов, закончившихся эскалацией, выводится в `/crm/agent-usage` как метрика
    качества, а сами темы ложатся в карту «рутина без менеджера» (capi-16) как задачи на
    самообслуживание, чтобы список эскалаций сокращался с каждым релизом.
17. **Голосовой ввод — микрофон в поле сообщения** (уточнение заказчика 19.09.2026). Нажал —
    говорит, текст появляется в поле по мере распознавания, отпустил или нажал ещё раз — остановка.
    **Распознанное — это текст в поле, а не отправка**: клиент видит, что услышано, правит и жмёт
    «Отправить» сам (голос ошибается в артикулах и числах, а заказ необратим).
    - Первый слой — `SpeechRecognition` браузера (`lang: ru-RU`, `interimResults`): без затрат и
      без нашего сервера, работает в Chrome, Яндекс.Браузере, Edge, Safari на iOS и macOS. Где API
      нет (Firefox) или доступ к микрофону не дан — кнопка скрыта, поле обычное; никаких «ваш браузер
      не поддерживает», просто нет микрофона.
    - Второй слой, если пилот покажет, что клиенты диктуют много: запись аудио и распознавание на
      сервере (STT через `openai-php/client` по тому же прокси, Whisper), для браузеров без API и для
      длинных надиктовок. Кандидат после пилота, в конфиге под флагом `voice.server_stt`.
    - На телефоне кнопка микрофона крупнее поля ввода — там это основной способ. Индикатор «слушаю»
      только у кнопки, без анимаций на всю страницу. Разрешение на микрофон запрашивается по первому
      нажатию, не при открытии диалога.
    - В `chat_events` — `voice_used` без аудио и текста, чтобы видеть долю голосовых обращений.
18. **Конверсия измеряется.** События `assistant_shown`, `assistant_opened`, `assistant_first_message`,
    `assistant_confirmed_action` пишутся в `chat_events` (без текста), экран `/crm/agent-usage` показывает
    воронку: «видели → открыли → написали → оформили» по неделям и по менеджерам. Это и есть отчёт
    для спора: не «сколько вызовов», а «какая доля клиентов заговорила с агентом».

## Модель данных

| Таблица | Назначение |
|---|---|
| `chat_threads` | тред клиента: `user_id`, `company_id` (nullable), `title`, `status` (`open`/`closed`), `token_id`, `compaction_at`, счётчики токенов и `cost`, `summary` после закрытия |
| `chat_messages` | ход: `thread_id`, `role` (`user`/`assistant`/`system`), `content` JSON блоков, `text` (плоский текст для показа и поиска), `status` (`pending`/`streaming`/`done`/`failed`), `usage` JSON, `cost`, `anthropic_id` |
| `chat_attachments` | файл: `thread_id`, `message_id`, диск/путь, `mime`, размер, `anthropic_file_id`, `expires_at` |
| `chat_confirmations` | ожидающее подтверждение: `thread_id`, операция, аргументы, `idempotency_key`, `decided_at`, решение |
| `client_assistant_notes` | заметка о клиенте: `user_id`, `content`, `version`, `updated_at` |

## Экраны

- **Иконка-консультант на всех страницах сайта** для авторизованного клиента (входные точки `app.jsx`
  и кабинет — один компонент `AssistantLauncher` в корневом лейауте). Свёрнута в иконку, при
  переходах выпускает и гасит одну реплику по контексту страницы (п. 13). Открывает Drawer с
  диалогом, не уводя со страницы: клиент продолжает смотреть товар, пока помощник отвечает.
  Непрочитанный ответ — точка на иконке.
- **Кабинет `/cabinet/assistant`** — полная страница: треды слева, диалог справа, вложения, история.
  Тот же диалог, что в Drawer. Пункт меню «Помощник» в группе «Интеграции» рядом с MCP.
- **В Drawer и на странице:** карточки подтверждения заказа, загрузка файлов и вставка скриншота из
  буфера, состояние «помощник отдыхает».
- **CRM: вкладка «Помощник» в карточке партнёра** — список тредов и переписка, только чтение; из треда
  кнопки «Написать клиенту» (письмо через матрицу) и «Задача». Действия строк — по стандарту
  `RowActions` (глаз открывает тред).
- **`/crm/agent-usage`** — фильтр канала «чат сайта / свои агенты», стоимость по клиенту и по месяцу,
  **воронка конверсии** «видели → открыли → написали → оформили» (п. 15) по неделям и менеджерам.

## Тесты

- Клиент Anthropic в тестах — фейк (HTTP-фикстуры ответов с блоками `thinking`/`mcp_tool_use`/
  `mcp_tool_result`/`compaction`); реальный API в CI не вызывается.
- Тред: второй ход отправляет первый ход байт-в-байт (append-only), блоки мышления не вырезаются;
  компакция сохраняется и уходит в следующий запрос.
- Токен: `assistant` не показывается в кабинете, истекает по `expires_at`, после закрытия треда
  отозван; `personal` работает как раньше (тесты legacy и capi не редактируются).
- Журнал: вызов через коннектор с токеном `assistant` даёт `agent = web-assistant`; `/crm/agent-usage`
  разделяет каналы.
- Подтверждение: `orders.create` без решения клиента не выполняется; повтор с тем же
  `Idempotency-Key` не создаёт второй заказ.
- Квоты: исчерпание квоты юрлица переводит чат в «отдыхает» и создаёт подсказку `questions.create`.
- Доступность: ответ `402 billing_error` от фейка переводит флаг в `unavailable`; после этого
  shared-props не содержат помощника, `/cabinet/assistant` даёт 404, реплики не пишутся в
  `chat_events`; успешный пробный запрос планировщика возвращает `available`; РОП получает одно
  уведомление на смену состояния.
- Реплики: ни одна фраза каталога не содержит «менеджер»/«уточню»; для заказа в сборке реплика
  называет срок из `WarehouseSchedule`, а не предлагает спросить.
- Эскалации: доля диалогов с `questions.create` считается на фикстуре журнала и показывается в CRM.
- Вложения: запрещённый формат и файл больше лимита отклоняются на бэке с русским текстом ошибки
  (проверка по содержимому: `.xlsx`, переименованный в `.png`, отклоняется); шестой файл в сообщении
  — 422; изображение уходит блоком `image`, xlsx — через Files API (по фикстуре запроса).
- Голос: кнопка микрофона не отправляет сообщение сама — компонентный тест на то, что распознанный
  текст попадает в поле, а отправка требует клика.
- Изоляция: менеджер без `crm-clients-all.view` не видит треды чужих клиентов; BI-гранты не содержат
  `chat_*`.
- Кеш: на втором ходу `cache_read_input_tokens > 0` (по фикстуре usage).

## Критерии готовности (эпик)

- [ ] Авторизованный клиент видит иконку помощника на любой странице сайта, гость — нет; при переходе
      в карточку товара всплывает и гаснет реплика по этому товару, клик по ней открывает диалог с
      контекстом товара; правила частоты не дают показать две реплики подряд.
- [ ] Клиент в чате смотрит цены, собирает заказ и оформляет его кнопкой; заказ в 1С
      уходит прежним путём, в `client_agent_calls` — канал `web-assistant`.
- [ ] Воронка «видели → открыли → написали → оформили» считается в `/crm/agent-usage`; одноразовая
      подсказка после закрытия не возвращается ни на одном устройстве клиента.
- [x] Фото прайса и Excel-файл в чате приводят к списку позиций с нашими ценами (Excel — на проде 23.09,
      фото уценки — 23.09); файл вне разрешённых форматов или больше лимита отклоняется с понятной
      русской ошибкой до отправки.
- [ ] Голосовой ввод с телефона и десктопа кладёт распознанный текст в поле, клиент правит и
      отправляет сам; в браузере без поддержки кнопки микрофона просто нет.
- [ ] Второй тред клиента знает, что было в первом (заметка + резюме), без повторного объяснения.
- [ ] Менеджер видит переписку своего клиента в CRM только для чтения; чужие треды недоступны.
- [ ] Потолок расходов срабатывает на всех трёх уровнях; стоимость хода видна в CRM.
- [ ] При нулевом балансе Anthropic иконка и реплики пропадают у всех клиентов без релиза; после
      пополнения возвращаются сами в пределах 10 минут; РОП получил уведомление о пропаже.
- [ ] Токены `assistant` не живут дольше TTL и не видны клиенту.
- [ ] Весь интерфейс на русском; миграции с комментариями; `make verify` зелёный; сквозной сценарий
      на dev пройден реальным API через `outbound-proxy`.

## Риски

- MCP-коннектор и компакция — беты Anthropic; поведение может измениться. Фиксируем версии бет в
  конфиге, фейк в тестах держит формат ответов.
- Единственный выход к Anthropic — VPS прокси (`45.77.101.56`, США). Падение прокси = помощник
  исчезает у всех (тот же механизм `AssistantAvailability`, что и при нулевом балансе), РОП
  получает уведомление; проверка здоровья прокси — в assist-05.
- Токен клиента транзитом проходит через Anthropic — поэтому TTL и отдельный вид токена, а не
  личный ключ.
- Промпт-инъекция из файлов клиента: агент действует только с правами этого же клиента, необратимое
  подтверждается кнопкой — вред ограничен его же данными.
