# ERP — приём ожидаемых поступлений и показ менеджеру (v16.16.0, этап 2)

**Приоритет:** высокий
**Создано:** 2026-10-02
**Источник:** Agent Hub, топик №16 «Ожидаемые поступления товара» (seq 0–4)
**Ветка:** `feature/erp-expected-arrivals-receive` (от `origin/dev`)

## Контекст

Менеджер должен отвечать клиенту на вопрос «когда приедет?». Закупки с 01.10.2026 вносят
ожидаемые даты в 1С; контракт `product.expected_arrivals.updated` (v16.16.0, проект) выложен
01.10 и принят 1С без замечаний к структуре (seq 4). Этап 1 был только документацией: очереди
и обработчика не существовало. Эта задача — приём и экран для менеджера. Приём должен оказаться
на проде **раньше**, чем 1С включит публикацию (у них она выключена отдельной настройкой).

## Решения

- Ожидания видят **только менеджеры** (Трипуть, 01.10.2026). Витрина, кабинет, клиентский API — нет.
- `date: null` — два случая: дата не заполнена **или** прошла, а товар не принят (закупки, 30.09.2026).
  Прошедших дат 1С не шлёт; ночная выгрузка переводит вчерашние в `null`.
- Дату, ставшую вчерашней до прихода выгрузки, сайт показывает как «дата уточняется» —
  так же, как её пришлёт выгрузка (а не прячет, как было в первой редакции правил).
- Отдельного права на раздел нет: открыт тому, кто видит заказы партнёров (`crm-clients.view`).
- Отброшенный снимок — статус `stale` в журнале шины; неизвестные склад и товар — `success` с пометкой.
