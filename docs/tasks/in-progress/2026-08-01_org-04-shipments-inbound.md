# org-04 · Организация и склад в реализациях (приём от 1С)

**Приоритет:** высокий
**Создано:** 2026-08-01
**Эпик:** [org-00](../backlog/2026-08-01_org-00-epic.md)
**Зависимости:** `org-01`, `org-02`; параллелится с `org-03`

## Описание

Симметрично `org-03`, но для `shipment.*`. Отдельная карточка потому, что реализация —
источник двух других вещей: организации возврата (`org-08`) и разрезов аналитики
(`org-09`), которая считается именно по `shipment_items`.

## Что делаем

**Миграция:** `shipments` + `organization_id` (nullable FK), + `warehouse_id` (nullable FK),
с комментариями.

**Handler-ы** `HandleShipmentCreated`, `HandleShipmentUpdated` — тот же `OrganizationResolver`,
та же семантика «отсутствие поля не сбрасывает значение».

**UI:**
- ЛК клиента, список и карточка реализаций — «Продавец: {организация}». Для клиента это
  самое заметное место: по реализации он сверяет накладную;
- админка и CRM — колонка «Организация» в списке + фильтр;
- поиск по реализациям в кабинете (`cabinet-search`) — организацию в индекс **не** добавляем
  в этой карточке, отдельным решением после `org-09`.

**Уценка:** реализация по заказу `type: defect` списывает партию некондиции
(`PreservesDefectItemLinks`, `project_erp_wipes_defect_links_bug`). Проверить, что новые
поля не участвуют в матчинге позиций и списание не ломается.

## Edge-кейсы

- **Реализация без организации** (legacy) → `null`, в ЛК строка скрыта.
- **Реализация по организации, которой нет в справочнике** → stub, клиент увидит UUID
  вместо названия. Приемлемо на переходный период, но stub-записи должны быть заметны
  в админке, чтобы менеджер дозаполнил имя.
- **У заказа одна организация, у его реализации другая** — легитимно (1С могла
  переоформить). Не «чиним», но подсвечиваем расхождение в админке карточки заказа.
- **Одна реализация по нескольким заказам** — существующая связка через
  `shipment_items.order_uuid`; организация берётся с реализации, а не с заказа.
- **Промо-реализации** (`promo_sample` → организация «Реклама») наконец получают явную
  организацию — это то, чего ждала отложенная карточка
  [промо-отгрузки в аналитике](../backlog/2026-08-01_promo-shipments-in-analytics.md).
- **Реализация удалена** (`shipment.deleted`) → soft delete, организация сохраняется.

- [x] Миграция с комментариями, `db:comments:audit` чист
- [x] Организация видна в ЛК и админке (список + карточка + фильтр)
- [x] Списание партий некондиции по реализации не сломано — 216 тестов `Shipment|Defect` зелёные
- [x] Интеграционный тест: `shipment.created` с организацией и складом
- [x] Интеграционный тест: `shipment.created` без них → реализация создана
- [x] Интеграционный тест: `shipment.updated` без поля не сбрасывает организацию
- [x] Интеграционный тест: расхождение организации заказа и реализации не роняет обработку
- [x] Интеграционный тест: организация переживает soft delete
