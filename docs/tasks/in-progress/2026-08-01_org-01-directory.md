# org-01 · Справочник организаций: таблица, модель, админка

**Приоритет:** высокий
**Создано:** 2026-08-01
**Уточнено:** 2026-08-01 — 1С справочник **не присылает**, организации заводятся руками
**Эпик:** [org-00](../backlog/2026-08-01_org-00-epic.md)
**Зависимости:** нет — стартовая карточка

## Описание

Завести на сайте справочник наших юрлиц. 1С справочник организаций **не отправляет** и
отправлять не будет — в своих сообщениях она указывает только UUID организации.
Организации заводятся в админке **разово, вручную**, с проставлением `external_id` (UUID
из 1С) — ровно так же, как сейчас заводятся склады (`warehouses.external_id`, см. миграции
`set_defect_warehouse_external_id`, `set_promo_sample_warehouse_external_id`).

Никакого события `organization.*` и очереди в шине не появляется.

## Что делаем

**Миграция `organizations`** (с комментариями к таблице и всем столбцам — правило проекта):

```php
$table->comment('Наши организации (юрлица компании), от имени которых 1С проводит документы');
$table->id();
$table->string('external_id')->nullable()->unique()
      ->comment('UUID организации в 1С. Заводится вручную в админке, как у складов');
$table->string('name')->comment('Краткое название для UI: «ООО Пекадо»');
$table->string('legal_name')->nullable()->comment('Полное юридическое наименование');
$table->string('tax_id')->nullable()->comment('ИНН организации');
$table->string('tax_code')->nullable()->comment('КПП организации');
$table->string('bank_name')->nullable()->comment('Банк для оплаты');
$table->string('bank_bik')->nullable()->comment('БИК банка');
$table->string('correspondent_account')->nullable()->comment('Корреспондентский счёт');
$table->string('account_number')->nullable()->comment('Расчётный счёт');
$table->boolean('is_active')->default(true)->comment('Активна — используется в текущих документах');
$table->boolean('is_stub')->default(false)
      ->comment('Заглушка: UUID пришёл из 1С, в админке организация ещё не заведена');
$table->unsignedInteger('sort_order')->default(0)
      ->comment('Порядок отображения в списках и фильтрах (меньше — выше)');
$table->timestamps();
$table->softDeletes();
```

Банковские реквизиты нужны не для красоты: клиент видит долг перед конкретным юрлицом
(`org-06`) и должен понимать, куда платить.

`external_id` — `string`, а не `uuid`: так хранят UUID из 1С все остальные таблицы
(`warehouses.external_id`, `companies.erp_id`, `users.erp_id`). `char(36)` отбраковал бы
неканоническое значение, а 1С — источник истины, её значение надо сохранить как есть.

**Модель `App\Models\Organization`** — `SoftDeletes`, скоупы `active()`, `real()`
(не заглушка), сортировка по `sort_order`.

**Сервис `OrganizationResolver`** — единая точка получения организации по UUID из входящего
сообщения. Им пользуются все handler-ы волны 1:

```php
public function resolveByUuid(?string $uuid, ?array $hint = null): ?Organization
```

- `null`/пусто → `null` (документ без организации легитимен);
- найдена → возвращаем, при наличии `hint` (`name`, `legal_name`, `tax_id`, `tax_code`
  из payload) дозаполняем **пустые** поля;
- найдена мягко удалённой → **восстанавливаем** + `Log::warning`: 1С продолжает проводить
  документы на юрлицо, которое админ скрыл. Иначе `belongsTo` вернул бы `null` (клиент
  увидел бы пустого продавца), а создать заглушку с тем же UUID не дал бы unique-индекс;
- не найдена → создаём **заглушку** `is_stub = true`, `name = $hint['name'] ?? $uuid`,
  `Log::info`. Гонка воркеров ловится через `QueryException` + повторный поиск.

⚠️ **Почему заглушка, а не просто `null`.** Раз справочник заводится руками, неизвестный
UUID означает «админ ещё не завёл организацию». Заглушка сохраняет связь документа
с юрлицом: когда админ заполнит название, все ранее принятые заказы и реализации сразу
отобразятся правильно, без бэкфилла. Вариант с `null` потребовал бы разбирать историю.

⚠️ **`is_stub` снимает только сохранение в админке, а не подсказка от 1С.** Отклонение
от первоначального проекта карточки, сделано осознанно: 1С банковские реквизиты
не присылает, а они нужны клиенту в разрезе взаиморасчётов (`org-06`). Если снимать флаг
по присланному названию, организация уходит из виду недозаполненной — и никто не узнает,
что платить клиенту некуда. Флаг означает «карточку не подтверждал админ». Название-UUID
подсказка при этом заменяет — клиент не должен видеть UUID вместо продавца.

**Админка** — раздел «Организации» в группе «Финансы» (список / просмотр / создание /
редактирование), `external_id` редактируемое поле. Всё на русском. Права
`organizations.*` — только у `super-admin`: юрлицо, его реквизиты и UUID из 1С правят
не менеджеры. Менеджеры видят организацию в самих документах (`org-03`, `org-04`).

⚠️ **Заглушки нужно показывать явно.** Это единственный способ узнать, что 1С работает
с юрлицом, которого нет в справочнике: бейдж «Не заведена — пришла из 1С», сортировка
заглушек наверх списка и счётчик в разделе. Иначе клиент увидит UUID вместо названия
в своём кабинете, и никто об этом не узнает.

**Сидер/команда** — завести реальные организации компании с их UUID. UUID запросить
у стороны 1С; до получения запись создаётся с пустым `external_id`.

**Feature-flag** `ORGANIZATIONS_ENABLED` (`config/erp.php` → `erp.organizations.enabled`)
— `false` по умолчанию. Гейтит **только показ графы «Продавец»** в документах: админка,
ЛК, CRM, отчёты и выгрузки (волны 1–2).

Сам справочник флагом **не закрыт** — он доступен по праву `organizations.view`. Иначе
получается замкнутый круг: юрлица с UUID нужно завести до того, как 1С начнёт присылать
организацию, иначе всё приедет заглушками. Приём и сохранение из сообщений 1С работают
всегда, независимо от флага, — данные, присланные раньше срока, иначе потеряются
безвозвратно.

## Edge-кейсы

- **Документ с неизвестным UUID** → заглушка. Админ открывает её, дозаполняет и сохраняет
  — дубль не создаётся, `is_stub` снимается.
- **1С прислала подсказку с названием** → название-UUID заменяется, но `is_stub` остаётся:
  реквизитов у записи по-прежнему нет.
- **Админ завёл организацию с опечаткой в UUID** → документы 1С создадут рядом заглушку
  с правильным UUID. Отсюда важность видимости заглушек: два похожих юрлица в списке —
  сигнал об опечатке.
- **UUID организации сменился в 1С** (перезаведение) → появится заглушка с новым UUID.
  Слияние не автоматизируем: старую помечаем `is_active = false`, документы остаются
  при своей ссылке.
- **Одинаковый ИНН у двух записей** (реорганизация) — `tax_id` не уникален намеренно.
- **Удаление организации с документами** → только soft delete, FK на документах nullable
  без каскада.
- **1С проводит документы на мягко удалённую организацию** → `OrganizationResolver`
  восстанавливает её и пишет `Log::warning`. Молча оставить удалённой нельзя: `belongsTo`
  отдал бы `null`, а заглушку с тем же UUID не создать из-за unique-индекса.
- **Гонка воркеров на одном неизвестном UUID** → вторую вставку отбивает unique-индекс,
  `QueryException` перехватывается, возвращается уже созданная запись.
- **Заглушки в фильтрах отчётов** — показываем, иначе итог разреза не сойдётся с общим
  (`org-09`), но помечаем как незаведённые.
