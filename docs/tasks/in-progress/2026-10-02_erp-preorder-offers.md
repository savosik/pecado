# ERP — предзаказ по предложениям 1С (v16.18.0)

**Приоритет:** высокий
**Создано:** 2026-10-02
**Источник:** Agent Hub, топик №18 «Предзаказ: товар, которого нет в наличии, — сколько, по какой цене и через сколько дней» (seq 0–7)
**Ветка:** `feature/erp-preorder-offers` (от `origin/dev`)

## Контекст

Принцип модератора: сайт не знает о внешних поставщиках. Про товар, которого нет в наличии,
1С сообщает абстрактно — сколько штук можно предзаказать и через сколько дней он будет; у кого
закупить, решает 1С. Сейчас предзаказ идёт через `stock.updated` по складу «Тюмень Основной»,
срок «7–9 дней» — настройка сайта, UUID склада в заказе подменяется (костыль с 26.06.2026).

Сайт — тонкая витрина: показывает то, что прислала 1С, и не даёт заказать больше показанного.

## Решения

- Цена предзаказа — **обычная цена клиента**; `price` в событии нет (Трипуть, 01.10.2026).
- Заказ сверх ближайшего яруса сайт раскладывает по ярусам сам: несколько строк одного товара
  с разным `lead_time_days` (Трипуть, 01.10.2026; 1С подтвердила, seq 4).
- Заказ с несколькими ярусами ждёт все ярусы и отгружается целиком; клиенту обещаем дальний
  срок (Трипуть, 02.10.2026; совпало с решением заказчика 1С).
- Сдвиг срока 1С сообщает в первой версии — `order.updated.expected_date`; сайт показывает дату
  в заказе, письма о сдвиге нет (seq 6–7).
- Сайт подсвечивает менеджеру предзаказы с истёкшим сроком (Трипуть, 02.10.2026).
- `revision` в событии нет, свежесть по `calculated_at` с миллисекундами (seq 6).
- Отказ поставщика — отменённая строка с `cancel_reason: supplier_unavailable`; значение
  в перечень и тексты добавляет ветка `fix/doc-revoked-mail-and-gi-rules`.

## Открытые вопросы

- Нижняя граница `lead_time_days`: в ленте согласовано только «целое». В проекте — `≥ 0`.
- Равный `calculated_at`: в проекте «применяется» (как в 16.16.0); в seq 5 было «не позже — отбрасывается».
- `expected_date: null` — в проекте «дата не менялась», а не «сбросить».
- Отправка предзаказа поставщику сайтом (v15.9) при новой схеме.
