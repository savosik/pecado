# debt-04: платёжка «бери и плати» — PDF, файл клиент-банка, QR

**Приоритет:** высокий
**Эпик:** [debt-00](2026-08-21_debt-00-epic.md)
**Зависит от:** debt-01 (сверенные суммы); независим от debt-02
**Создано:** 2026-08-21

## Описание

Генерация готового платёжного поручения по паре **контрагент клиента × наша
организация** (валюта — рубли; мультивалютных пар нет в `contractor_balances`).
Сырьё уже в базе: `organizations` (получатель: ИНН/КПП/банк/БИК/счета; `is_stub`
отсекать), `company_bank_accounts` (плательщик), `contractor_organization_balances`
и `contractor_balance_overdue_details` (сумма и основание).

### Сценарии суммы (решение исходной идеи)

1. **Погасить просрочку** — сумма просроченных документов пары, в назначении
   платежа перечень «оплата по счетам №…»;
2. **Погасить долг полностью** — всё сальдо пары;
3. **Предоплата** — произвольная сумма или сумма конкретного заказа
   (используется debt-06 в режиме `prepay_only`);
4. частный случай — по одному выбранному документу («оплатить именно это», debt-05).

### Форматы (решение 21.08 — все три сразу)

- **PDF** — печатная форма платёжного поручения;
- **1CClientBankExchange** (`.txt`) — бухгалтер клиента загружает в свой
  клиент-банк двумя кликами; главный формат «без трения»;
- **QR ГОСТ Р 56042** — читается банковскими приложениями юрлиц/ИП.

Сущность `payment_orders`: uuid, user/company/organization, сценарий, сумма,
состав документов, кем создана (клиент/менеджер/система), `sent_to`.
Хранить факт генерации обязательно — debt-07 использует его для окна «деньги
в пути», debt-11 меряет конверсию.

### Отправка бухгалтеру

Кнопка «отправить на оплату»: выбор контакта из `client_contacts` (роль
`accountant` первая в списке) или ввод нового email — **новый адрес сохраняется
в адресную книгу** с ролью «бухгалтер», source `self`. Письмо уходит через пульт
(журнал, suppressions), вложения: PDF + txt + QR.

### Вложения в касания (решение 21.08)

Со **второго** касания каскада debt-03 платёжка на сумму просрочки прикладывается
к письму автоматически (пульт умеет attachments). Первое напоминание — без неё.

### Поверхности

Кабинет: раздел «Оплаты» (за `CABINET_FINANCE_ENABLED`). CRM: те же кнопки
в карточке клиента — менеджер генерирует и шлёт платёжку сам.

## Критерии готовности

- [ ] `PaymentOrderService`: три формата из одних данных; формат 1CClientBankExchange проверен реальной загрузкой в клиент-банк (хотя бы один банк, вручную)
- [ ] Назначение платежа собирается из документов пары, юнит-тесты на все сценарии сумм
- [ ] UI кабинета: выбор контрагента → нашей организации → сценария → скачать/отправить; всё на русском
- [ ] Отправка бухгалтеру: контакт из адресной книги, новый email сохраняется в `client_contacts`
- [ ] Миграция `payment_orders` с комментариями, `bi:sync-grants`
- [ ] Вложение платёжки в письма каскада со второго касания — интеграционный тест с пультом
