## Описание

Метка — то, за что цепляется фильтр. Без меток правило может искать только по тексту
письма, а это ненадёжно: ИНН найдётся внутри более длинного числа, название компании —
внутри чужой заметки.

Метка сравнивается **целиком**. `инн:7701234567` — одно значение, а не кусок строки.

## Какие метки бывают

| Группа | Примеры | Откуда |
|---|---|---|
| Кто | `инн:7701234567`, `контрагент:Ромашка`, `партнёр:467` | из связи письма с клиентом |
| Что | `акт-сверки`, `недобор`, `просрочка`, `упд` | из повода, по которому письмо собрано |
| Сколько | `просрочка:60+`, `сумма:100000+` | ступенями, чтобы числа ловились фильтром |
| Про клиента | `город:Тюмень`, `бизнес:маркетплейсы`, `стадия:спящий` | из профиля CRM |

Ступени вместо точных чисел — сознательно: фильтр по подстроке числа не работает,
а условие «больше 60 дней» в интерфейсе почтового фильтра выглядит чужеродно.
Кому нужен точный порог — `mail-09`.

## Что делаем

- Таблица меток письма (или json-колонка в `crm_emails` — решить при реализации,
  исходя из того, как будет искать фильтр).
- Метки видны в карточке письма списком: человек глазами понимает, за что можно зацепиться.
- Метки проставляются при создании письма: у менеджерского — по клиенту и вложениям,
  у собранного системой — плюс метки повода.
- Подсказка меток в конструкторе правила: набираешь «инн» — видишь список.

## Критерии готовности

- [ ] Метки хранятся и видны в карточке письма
- [ ] Метка сравнивается целиком: тест, что `инн:7701234567` не совпадает с `инн:77012345678`
- [ ] Метки клиента считаются из профиля CRM
- [ ] Ступени для чисел (`просрочка:30+/60+/90+`)
- [ ] Подсказка меток при наборе
