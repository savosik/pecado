# debt-11: метрики эффективности — DSO и конверсия ступеней

**Приоритет:** низкий
**Эпик:** [debt-00](2026-08-21_debt-00-epic.md)
**Зависит от:** debt-03 (журнал касаний), debt-07 (события оплат)
**Создано:** 2026-08-21

## Описание

Без измерения мы не узнаем, какие ступени собирают деньги, а какие только
раздражают. Вкладка «Эффективность» на `/crm/debt` (или в `/crm/finance` —
решить при реализации, второго расчёта продаж не появляется: всё через
`PaymentForecast` и существующие журналы).

### Метрики

| Метрика | Как считается |
|---|---|
| **DSO** (дни оборота дебиторки) | средневзвешенный возраст непогашенных строк графиков; динамика по неделям — главный индикатор «система работает» |
| **Собрано после касания** | сумма платежей клиента в N дней после каждого касания (`notification_deliveries` × `payments`); разрез по типу касания |
| **Конверсия ступеней** | доля клиентов, заплативших на `reminder`, не дойдя до `prepay_only`; и т.д. по лестнице (`debt_level_transitions`) |
| **Самостоятельные разморозки** | доля переходов вверх без участия менеджера (по инициатору перехода) |
| **Платёжки** | сгенерировано → отправлено → оплата пришла в M дней (`payment_orders` × `payments`) |
| **Обещания** | доля `kept` / `broken` |
| Структура просрочки | существующий `aging()` — динамика корзин 7/30/90+ |

Плюс BI-вьюхи в схеме `analytics` для аналитического MCP (агенты менеджеров
смогут отвечать «как идёт взыскание») — после наката `bi:sync-grants`.

### Базовая линия

Зафиксировать стартовые значения (снимок 21.08: долг 11,34 млн, просрочка
2,60 млн, DSO на дату включения) — без базовой линии эффект системы недоказуем.

## Критерии готовности

- [ ] Вкладка с метриками; периоды сравнения (до/после включения ступеней)
- [ ] Связка касание → платежи в окне N дней — юнит-тесты на границы окна
- [ ] DSO покрыт тестом на синтетических графиках (агрегаты проверить на локальной MySQL)
- [ ] BI-вьюхи + гранты для `bi_agent`
- [ ] Базовая линия зафиксирована в карточке при выкатке
