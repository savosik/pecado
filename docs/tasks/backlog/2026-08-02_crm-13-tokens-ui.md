# crm-13 · Выдача и отзыв агентских токенов: команда и экран в CRM

**Приоритет:** средний
**Создано:** 2026-08-02
**Эпик:** [crm-00](2026-08-02_crm-00-epic.md)
**Волна:** 5 (гейт для ИИ-агентов)
**Зависимости:** `crm-12` (таблица токенов)

## Описание

Дать РОПу возможность выдавать и отзывать токены ИИ-агентов самостоятельно, без обращения
к разработчику.

У аналитических токенов UI нет — только `php artisan analytics:token issue|list|revoke`,
то есть каждая выдача требует доступа в контейнер на проде. Для пишущего доступа это тем более
неудобно: отзыв токена — операция срочная (уволился менеджер, утёк токен), и она не должна
ждать свободного разработчика.

## Что делаем

**Команда `crm:token`** — по образцу `App\Console\Commands\AnalyticsToken`:

```bash
php artisan crm:token issue "Менеджер Сухов" --user=42
php artisan crm:token list
php artisan crm:token revoke <token|id>
```

Выдача без `--user` невозможна: `crm_agent_tokens.user_id` обязателен (см. `crm-12`).

**Экран `/crm/agent-tokens`** под правом `crm-agent-tokens.edit`:
- список: кому выдан, менеджер, активен ли, когда использовался последний раз;
- выдача: имя + выбор сотрудника с CRM-доступом; после создания токен показывается
  с кнопкой копирования и короткой инструкцией «как подключить агента»;
- отзыв одной кнопкой с подтверждением.

Токен показывается в списке всегда, а не единожды при создании: он хранится открытым текстом
(это bearer для машинного доступа, как в `analytics_tokens` и `api_tokens`), и прятать его
в UI, оставляя доступным в БД, было бы имитацией безопасности. Право на экран есть только
у РОПа.

**Инструкция для менеджера** — короткий блок прямо на экране: адрес `https://pecado.ru/mcp/crm`,
где взять токен, куда его вписать в настройках агента, и ссылка на `/docs/crm-api` для
REST-варианта.

**Права:** ресурс `crm-agent-tokens`, действия `view, create, delete`, метка
«CRM: Токены ИИ-агентов». Выдать только `sales-head` (и, разумеется, `super-admin`).

## Границы

- Срок жизни токена и автоматический отзыв не делаем: отзыв ручной, поле `is_active` уже есть.
- Самообслуживание менеджера (выдать токен себе) не делаем — выдаёт РОП.
- Ротация токенов — вне скоупа; при необходимости отзывается старый и выдаётся новый.

## Критерии готовности

- [ ] `crm:token issue|list|revoke` работает; выдача без `--user` отклоняется с понятным текстом
- [ ] Экран доступен только с правом `crm-agent-tokens.edit`; менеджер без него получает 403
- [ ] Токен выдаётся, копируется и сразу работает на `/mcp/crm`
- [ ] Отзыв закрывает доступ немедленно — проверено запросом после отзыва
- [ ] Исполнителем токена можно выбрать только сотрудника с CRM-доступом
- [ ] Весь экран и инструкция — на русском
- [ ] Feature-тест `tests/Feature/Crm/AgentTokensTest.php` (выдача, отзыв, гейт права)
