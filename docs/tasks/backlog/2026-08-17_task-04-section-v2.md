## Описание

Сейчас раздел — плоская таблица `DataTable` с постраничной пагинацией и нативными
`<select>`-фильтрами. Требование: наглядно, читаемо, искаемо, закрепляемо,
без пагинации — задачи «умещаются все на экран».

### Группировка по сроку вместо плоской таблицы

Открытые задачи группируются секциями в фиксированном порядке:

**Закреплённые → Просрочено → Сегодня → Завтра → Эта неделя → Позже → Без срока**

У секции — заголовок со счётчиком и суммой трудоёмкости («Сегодня · 6 задач · ~4 ч»),
секции сворачиваются (состояние в localStorage). Просрочка — красный акцент заголовка.
Закрытые задачи в группировку не лезут — им отдельный пресет/фильтр «Завершённые»,
где сортировка по `done_at` и видны исходы.

Строка задачи — компактная карточка-ряд: чекбокс закрытия, заголовок, бейдж
приоритета, прогресс чек-листа «3/5», привязка, ответственный + стопка
соисполнителей, значок контроля, трудоёмкость, срок. Всё из task-01…03 видно сразу.

### Бесконечная прокрутка

- Пагинацию убрать. Подгрузка при прокрутке — Inertia `WhenVisible` + merge props
  (Inertia v2 это умеет из коробки); проверить версию `@inertiajs/react` и выбрать
  механизм по факту (fallback — кнопка «Показать ещё» с `only`+merge).
- Порция 50; фильтры/пресеты сбрасывают ленту и скроллят к началу.
- `preserveState` при смене фильтров сохраняется, «снимок отбора» — известный класс
  багов, покрыть round-trip-тестом.

### Закрепление (pin)

```php
Schema::create('crm_task_pins', function (Blueprint $table) {
    $table->comment('Личные закрепления задач: закреплённые висят сверху раздела');
    $table->id()->comment('Первичный ключ');
    $table->foreignId('user_id')->comment('Кто закрепил (users.id)')->constrained('users')->cascadeOnDelete();
    $table->foreignId('task_id')->comment('Задача (crm_tasks.id)')->constrained('crm_tasks')->cascadeOnDelete();
    $table->timestamps();
    $table->unique(['user_id', 'task_id']);
});
```

Кнопка-скрепка в строке; секция «Закреплённые» всегда первая и не зависит от
фильтров срока. Закрепление личное — у каждого своё. Закрытие задачи снимает пин.

### Фильтры v2

- Все `<select>` → Select-обёртки из `@/components/ui/*` **с collection**
  (нативные инлайн-стили убрать; классы багов фильтров — в памяти проекта).
- Панель фильтров: статус, приоритет, исполнитель (включая соисполнителей), автор,
  клиент, тип привязки, срок, **исход** (task-03), «на контроле», «с чек-листом».
- Активные фильтры — чипы с крестиками над списком; «Сбросить всё».
- Пресеты (Мне / От меня / На контроле / Просрочено / Без привязки / Завершённые / Все)
  остаются фильтрами поверх одного списка — принцип crm-09 не ломаем.
- Поиск — крупное поле сверху (title+description, серверный, уже есть), debounce.

### Не трогаем

`DataTable` остаётся в других разделах; раздел задач уходит на собственный
список-компонент. Deep-link `?task=ID`, `ScopeToggle`, диалоги — сохраняются.

## Критерии готовности

- [ ] Секции по сроку с счётчиками и суммой трудоёмкости; сворачивание переживает перезагрузку
- [ ] Пагинации нет; прокрутка догружает порциями по 50 без дублей и пропусков (тест на курсор/offset при изменении данных между порциями)
- [ ] Пин: закреплённая задача сверху, у коллеги не закреплена, закрытие снимает пин
- [ ] Все фильтры — Select с collection; ключи возвращаются в снимке filters (round-trip-тест)
- [ ] Чипы активных фильтров, сброс, поиск с debounce
- [ ] В строке видны: чек-лист прогресс, соисполнители, контроль, трудоёмкость, исход (для завершённых), «переносилась ×N»
- [ ] Пресеты не теряют задачи (тест из crm-09 расширен новыми пресетами)
- [ ] ESLint чист; UI на русском; браузерная проверка на dev
