## Описание

Сайт начинает принимать и сохранять движения регистра. Читает их пока **никто** — переключение
чтения это волна 3. Смысл: данные должны начать копиться до того, как на них что-то завяжется,
иначе первое же переключение упрётся в пустые таблицы.

## Что делаем

### Хендлеры (`app/Services/Erp/Handlers/`)

| Хендлер | Логика |
|---|---|
| `HandleAgreementCreated` / `Updated` / `Deleted` | `updateOrCreate` по `uuid`; резолв сторон существующим трейтом [`ResolvesContractorParty`](../../../app/Services/Erp/Support/ResolvesContractorParty.php) и [`ResolvesDocumentOrganization`](../../../app/Services/Erp/Support/ResolvesDocumentOrganization.php). Удаление — мягкое |
| `HandleSettlementOpeningBalance` | Одна строка `type=opening_balance`, `date=as_of_date`. Повторная доставка **заменяет**, а не добавляет |
| `HandleSettlementPosted` | **Полная замена** движений документа: удалить все `settlement_entries` с этим `document_uuid` и `nature=fact`, создать заново из `entries[]`. Затем `SettlementProjector` |
| `HandleSettlementReverted` | Удалить движения документа. Строки графика по нему — тоже |
| `HandlePaymentScheduleUpdated` | Полная замена строк `nature=plan` в скоупе `document_uuid` |

Общий трейт `app/Services/Erp/Support/ResolvesAgreement.php` — резолв соглашения по `agreement_uuid`
с ленивым backfill, по образцу `ResolvesContractorParty`.

**Delete-and-recreate, а не diff** — тот же приём, что в `PaymentAllocationService::sync()` и
`HandleShipmentCreated::syncItems()`. Отличить «строка не изменилась» от «строки больше нет»
по дельте нельзя.

### Конвертация валюты

Рублёвый эквивалент **приходит из 1С** полем `amount_rub` (`СуммаРегл`) — сайт его не считает.
Для рублёвых движений `amount_rub = amount`. Если поле не пришло для валютного движения —
`NULL` + warning; подставлять курс из своего справочника нельзя, акт сверки разъедется с 1С.

### Регистрация

- `ErpMessageValidator::SCHEMA_MAP` (`app/Services/Erp/ErpMessageValidator.php:26-75`) —
  восемь новых событий;
- `ErpRevisionGuard::DOCUMENTS` (`app/Services/Erp/ErpRevisionGuard.php:49-61`) —
  `settlement.*`, `agreement.*`, `payment_schedule.*`;
- `SetupRabbitMQTopology` (`app/Console/Commands/SetupRabbitMQTopology.php:63-77`) — очередь
  `erp_in.settlements` ← `settlement.*`, `payment_schedule.*`; `agreement.*` добавляется в
  binding существующей `erp_in.contractors`;
- `docker/supervisor/conf.d/worker.conf` — воркер `erp_in.settlements`, `numprocs=2` (224 632 движения за год — объём умеренный).

### `SettlementProjector` (`app/Services/Settlements/SettlementProjector.php`)

**Единственный писатель** денормализованных проекций. Пересчитывает:
- `shipments.paid_amount / payment_status / paid_at` — теперь «закрыто по данным 1С»;
- `orders.prepaid_amount`;
- `settlement_checkpoints` (из `settlement.checkpoint`, не из движений).

Правила, унаследованные от `PaymentAllocationService` (они себя оправдали):
- пересчёт — **полная функция от состояния БД**, никогда инкремент;
- чанки по 500;
- `saveQuietly` + `withoutEvents` — иначе десятки тысяч лишних переиндексаций Scout;
- идемпотентность обязательна и покрывается тестом.

⚠️ Пока `SETTLEMENTS_LEDGER_ENABLED` выключен, проектор **не трогает** `shipments.paid_amount`:
эту колонку ещё пишет `PaymentAllocationService`, два писателя подерутся. До волны 3 проектор
ведёт только `settlement_checkpoints` и собственные агрегаты.

## Edge-кейсы

- **Движение раньше документа** → `document_id = NULL`, читается по `document_number`.
  Доклейка при получении документа — в `HandleShipmentCreated`/`HandleOrderCreated` по
  `document_uuid`. Отдельных трейтов-доклейщиков **не плодим**: одна точка на все типы.
- **Повторная доставка того же `settlement.posted`** → результат идентичен. Тест обязателен.
- **Устаревшая ревизия обогнала свежую** → `ErpRevisionGuard` отбрасывает, статус `'stale'`
  в журнале шины.
- **`entries[]` пуст** → все движения документа удаляются. Это валидный способ обнулить
  документ, не отменяя проведение.
- **Неизвестный `type`** → сообщение в DLQ целиком. Пропустить строку молча нельзя: баланс
  разъедется, и никто не заметит.
- **Контрагент или соглашение не найдены** → движение сохраняется с `NULL` в связи + warning.
  Деньги важнее связей; доклеится позже.
- **Гонка очередей**: `erp_in.settlements` и `erp_in.documents` независимы, порядок не
  гарантирован — та же ситуация, что уже описана в `rules/message-ordering.md`.
