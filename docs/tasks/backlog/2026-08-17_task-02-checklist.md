# task-02: todo-чекбоксы внутри задачи

## Описание

Чек-лист — плоский список пунктов внутри задачи. Не подзадачи: без исполнителей,
сроков и рекурсии. «Обзвонить 5 клиентов» превращается в 5 галочек, а не в 5 задач.

### Таблица

```php
Schema::create('crm_task_checklist_items', function (Blueprint $table) {
    $table->comment('Пункты чек-листа задачи CRM');
    $table->id()->comment('Первичный ключ');
    $table->foreignId('task_id')->comment('Задача (crm_tasks.id)')->constrained('crm_tasks')->cascadeOnDelete();
    $table->string('title', 500)->comment('Текст пункта');
    $table->unsignedSmallInteger('position')->comment('Порядок в списке');
    $table->boolean('is_done')->default(false)->comment('Пункт выполнен');
    $table->foreignId('done_by_id')->nullable()->comment('Кто отметил (users.id)')->constrained('users')->nullOnDelete();
    $table->timestamp('done_at')->nullable()->comment('Когда отмечен');
    $table->timestamps();
    $table->index(['task_id', 'position']);
});
```

### Поведение

- CRUD внутри карточки задачи (`TaskDialog`): добавление по Enter (поле «+ пункт»
  внизу), инлайн-правка текста, удаление, перетаскивание для порядка (`position`).
- Отметить/снять пункт может любой участник задачи: автор, ответственный,
  соисполнитель, `crm-department.edit`. `done_by_id`/`done_at` фиксируются —
  в команде видно, кто что сделал.
- Прогресс «3/5» — в строке списка задач (бейдж рядом с заголовком), в карточке —
  тонкий прогресс-бар. У задач без чек-листа ничего не показывается.
- Закрытие задачи с невыполненными пунктами **не блокируется** — диалог закрытия
  показывает «остались невыполненные пункты (2/5)» как информацию. Блокировка
  научила бы отмечать галочки не глядя.
- Чек-лист попадает в `payload()` (объекты + счётчики `checklist_done`/`checklist_total`),
  чтобы список не грузил пункты каждой строки — счётчики через `withCount`.

### Эндпоинты

Вложенные, под существующими правами задач:

```
POST   /crm/tasks/{task}/checklist              crm-tasks.edit
PATCH  /crm/tasks/{task}/checklist/{item}       crm-tasks.edit  (текст, is_done, position)
DELETE /crm/tasks/{task}/checklist/{item}       crm-tasks.edit
```

Проверка доступа — через существующую политику задачи (участник), не отдельную.

### Интеграции

- Агентское API `TaskOperations`: чек-лист в `show`, операции add/toggle —
  ИИ-агент менеджера сможет вести списки обзвона.
- Шаблон автоповтора: опциональный чек-лист в правиле (`crm_task_recurrences`),
  копируется в каждую порождённую задачу — «еженедельная сверка» с готовым списком шагов.

## Критерии готовности

- [ ] Миграция с комментариями; `db:comments:audit --strict` чист; `bi:sync-grants` прогнан
- [ ] Пункты добавляются Enter-ом, правятся инлайн, переставляются; порядок сохраняется
- [ ] Отметка фиксирует `done_by_id`/`done_at`; соисполнитель может отмечать
- [ ] Прогресс виден в списке задач (withCount, без N+1) и в карточке
- [ ] Закрытие задачи с открытыми пунктами возможно, но диалог предупреждает
- [ ] Чек-лист шаблона автоповтора копируется в порождённые задачи
- [ ] Агентское API отдаёт и меняет чек-лист
