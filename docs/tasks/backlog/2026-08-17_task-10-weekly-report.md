# task-10: пятничный отчёт по задачам — менеджерам и РОПу

**Приоритет:** средний
**Эпик:** [task-00](2026-08-17_task-00-epic.md)
**Зависит от:** task-03 (исходы, переносы), желательно task-01 (трудоёмкость)
**Создано:** 2026-08-17

## Описание

Каждую пятницу в 17:00 менеджер получает письмо о своей неделе, РОП — сводку по
отделу. Отчёт считается из фактов модели (`done_at`, `outcome`,
`postponed_count`, `due_at`) — никаких накопительных таблиц статистики.

### Команда и расписание

`crm:tasks-weekly-report {--date=} {--dry-run}` в `routes/console.php`:
`weeklyOn(5, '17:00')`, `withoutOverlapping()` — рядом с `crm:tasks-remind`.
`--date` — пересборка отчёта за прошлую неделю при отладке; `--dry-run` — в лог.
Неделя = понедельник 00:00 – пятница 17:00 момента запуска, в зоне приложения.

### Письмо менеджеру (свои задачи: ответственный или соисполнитель)

- **Закрыто за неделю**: всего, из них успешно / с проблемой (с заголовками
  «проблемных» — это то, что стоит обсудить с РОПом до понедельника);
  закрыто вовремя vs с опозданием (`done_at` vs `due_at`).
- **Переносы**: сколько раз двигались сроки; задачи с ≥2 переносами поимённо.
- **Висит просроченным на момент отчёта** — поимённо, с давностью.
- **На следующую неделю**: сколько задач и сумма трудоёмкости.
- Пустые секции не показываются; если неделя чистая — короткое «Все задачи недели
  закрыты, просрочек нет».

### Письмо РОПу (`crm-department.view`)

Таблица по менеджерам: закрыто (успешно/с проблемой), вовремя %, переносов,
просрочено сейчас, план следующей недели (шт и ~часы). Ниже — «проблемные»
закрытия недели по всему отделу списком и топ застарелых просрочек.
РОП получает **оба** письма (своё как менеджер — только если у него есть свои
задачи).

### Техника

- Флаг — существующий `MAIL_FEATURE_CRM_TASKS` (отдельный не заводить: это то же
  семейство почты задач); на проде включение — осознанный шаг с релизом эпика.
- Markdown-шаблоны в `resources/views/mail/crm/` рядом с существующими
  (`task-assigned`, `task-due`), тема `pecado`, вся типографика русская.
- Получатели-менеджеры: пользователи с активными задачами недели, а не «все с
  ролью» — адресация по данным, не по ролям (принцип проекта);
  РОПы — обладатели `crm-department.view` с CRM-доступом.
- Queued mail, chunkById; повторный запуск команды в ту же пятницу не рассылает
  дубли (отметка в кэше/логе — решить в реализации, тест обязателен).

## Критерии готовности

- [ ] Расписание пятница 17:00; `--dry-run` и `--date` работают
- [ ] Письмо менеджеру: закрыто/исходы/вовремя, переносы, просрочка, план недели; пустые секции скрыты
- [ ] Письмо РОПу: таблица по менеджерам + проблемные закрытия + застарелые просрочки
- [ ] Двойной запуск не шлёт дубли (тест)
- [ ] Границы недели в зоне приложения (тест на стыке суток)
- [ ] Соисполнение учтено (задача не считается дважды в сводке отдела)
- [ ] `MAIL_FEATURE_CRM_TASKS=false` — тишина; при `true` письма в Mailpit
- [ ] Feature-тесты; письма на русском; визуальная проверка вёрстки письма
