## Контекст — найденный дефект

Типы заказов сейчас размазаны по интерфейсам **хардкодом в тернарках**, и при добавлении
уценки часть мест обновить забыли:

| Место | Код | Проблема |
|---|---|---|
| [Admin/Pages/Orders/Index.jsx:20](../../../resources/js/Admin/Pages/Orders/Index.jsx#L20) | `type === 'preorder' ? 'Предзаказ' : 'Со склада'` | **Заказ уценки показывается как «Со склада»** |
| [Admin/Pages/Orders/Index.jsx:21](../../../resources/js/Admin/Pages/Orders/Index.jsx#L21) | `getTypeColor` | та же проблема с цветом |
| [OrderController.php:166](../../../app/Http/Controllers/Admin/OrderController.php#L166) | список `types` | **фильтр по типу не содержит уценки** — заказы уценки нельзя отфильтровать в админке |
| [Cabinet/Orders/Index.jsx:509](../../../resources/js/Pages/User/Cabinet/Orders/Index.jsx#L509) | тернарка на три типа | добавление двух типов сделает её нечитаемой |
| [Cabinet/Orders/Show.jsx:44](../../../resources/js/Pages/User/Cabinet/Orders/Show.jsx#L44) | то же | то же |

С добавлением `promo` и `promo_sample` типов станет пять, и тернарки окончательно
расползутся. Эта карточка чинит существующий дефект и заодно готовит почву.

## Задача

### 1. Единый источник правды

`resources/js/utils/orderType.js`:

```
ORDER_TYPES = {
  order:        { label: 'Заказ со склада',   short: 'Заказ',    color: 'teal'   },
  preorder:     { label: 'Предзаказ',          short: 'Предзаказ', color: 'purple' },
  defect:       { label: 'Уценка',             short: 'Уценка',   color: 'orange' },
  promo:        { label: 'Промо-позиции',      short: 'Промо',    color: 'blue'   },
  promo_sample: { label: 'Рекламные образцы',  short: 'Образцы',  color: 'gray'   },
}
getOrderTypeLabel(type) / getOrderTypeColor(type) / getOrderTypeShort(type)
```

Неизвестный тип → нейтральная подпись и серый цвет, **без падения**: в БД могут оказаться
заказы, приехавшие из 1С с неизвестным сайту типом.

Цвета проверить на конфликт с палитрами статусов заказа, которые уже используются рядом, —
два разноцветных бейджа в одной строке не должны сливаться.

Серверная сторона — `OrderType::label()` уже существует, использовать его везде, где список
типов формируется на бэкенде (фильтры, экспорт, письма), вместо литералов.

### 2. Заменить хардкод

Пройти по всем местам из таблицы выше плюс найти остальные:
`grep -rn "preorder" resources/js/ | grep -i "предзаказ\|label\|type"`.

Проверить как минимум: админка (список, карточка, редактирование, экспорт), кабинет клиента
(список, карточка, фильтры, печатные формы), CRM (аналитика продаж — разрезы по типам
заказа), WMS (очередь отбора), письма о заказе и смене статуса.

### 3. Фильтры

- Админка: добавить в список `types` **уценку** (существующий пропуск) и два новых типа.
- Кабинет клиента: проверить, что фильтр по типу заказа, если он там есть, знает все пять.
- CRM-аналитика: убедиться, что промо-заказы с нулевой суммой не портят отчёты — их надо
  либо исключать из выручки, либо показывать отдельной строкой. **Решить явно**, а не
  оставлять как получится: заказ на 0 ₽ в отчёте по продажам выглядит как ошибка данных.

### 4. Карточка заказа

Для промо-заказов на странице заказа показывать:
- бейдж типа;
- строку «Оформлен по акции “…”» со ссылкой на лендинг (данные из `promotion_rule_id`
  позиций);
- для `promo_sample` — пометку «Рекламные образцы, не входят в накладную»;
- связь с «родительским» заказом того же оформления: клиент видит пять заказов и должен
  понимать, что это одна покупка. У `orders` есть поле `parent_id` — проверить, используется
  ли оно сейчас при расщеплении на наличие/предзаказ, и либо задействовать, либо
  группировать по `cart_id`.

## Нюансы

- **Печатные формы и выгрузки.** Если где-то формируется печатная форма заказа или
  экспорт в Excel — типы там тоже подписаны, проверить.
- **Сортировка списка.** Пять заказов одного оформления должны идти рядом и в понятном
  порядке (основной → предзаказ → уценка → промо → образцы), а не вперемешку по id.
- **Пустая сумма.** В списках заказов «0 ₽» не должно выглядеть как ошибка загрузки —
  для промо-заказов с нулевой суммой писать «Бесплатно».
- Интерфейс — только русский.

## Критерии готовности

- [ ] `orderType.js` создан, все найденные хардкоды заменены.
- [ ] Заказ уценки в админке подписан «Уценка», а не «Со склада» (починка дефекта).
- [ ] Фильтр по типу в админке содержит все пять типов и работает.
- [ ] Промо-заказы видны и корректно подписаны в админке, кабинете, WMS.
- [ ] Решено и реализовано поведение промо-заказов в CRM-аналитике.
- [ ] Заказы одного оформления группируются или явно связаны в интерфейсе.
- [ ] Неизвестный тип не роняет страницу (тест с подставным значением).
