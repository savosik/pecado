# Промо 10 — Типы заказов во всех интерфейсах (+ починка уценки)

**Приоритет:** средний
**Создано:** 2026-07-27
**Roadmap:** [docs/promo-constructor-roadmap.md → Волна 2](../../promo-constructor-roadmap.md)
**Зависит от:** [promo-09-erp-order-types](2026-07-27_promo-09-erp-order-types.md)

## Контекст

Дефект с уценкой (заказы уценки подписывались «Со склада», фильтр по типу их не находил)
**вынесен и починен отдельно** — см. [багфикс от 2026-07-31](../review/2026-07-31_order-type-labels-defect.md).
Там же создан единый справочник типов
[resources/js/constants/orderType.js](../../../resources/js/constants/orderType.js)
(в `constants/`, рядом с `orderStatus.js`, а не в `utils/` как планировалось здесь)
и серверный `OrderType::options()`.

Эта карточка доделывает остаток — то, что завязано на новые типы `promo` и `promo_sample`.

## Задача

### 1. Добавить два типа в справочники

Во фронтовый `constants/orderType.js` — два ключа в каждую из трёх карт:

```
promo:        { label: 'Промо-позиции',     short: 'Промо',    color: 'blue' },
promo_sample: { label: 'Рекламные образцы', short: 'Образцы',  color: 'gray' },
```

и в `App\Enums\OrderType` — соответствующие кейсы с `label()`. Фильтры типов на бэкенде
уже строятся из `OrderType::options()`, так что подхватится само.

Цвета проверить на конфликт с палитрами статусов заказа, которые уже используются рядом, —
два разноцветных бейджа в одной строке не должны сливаться.

### 2. Проверить оставшиеся интерфейсы

Багфикс прошёл по админке (список, карточка, редактирование), отгрузкам и кабинету.
**Не проверены**: экспорт заказов в Excel, печатные формы, письма о заказе и смене статуса,
CRM (аналитика продаж — разрезы по типам), WMS (очередь отбора).

### 3. Фильтры

- Кабинет клиента: проверить, что фильтр по типу заказа знает все пять.
- CRM-аналитика: убедиться, что промо-заказы с нулевой суммой не портят отчёты — их надо
  либо исключать из выручки, либо показывать отдельной строкой. **Решить явно**, а не
  оставлять как получится: заказ на 0 ₽ в отчёте по продажам выглядит как ошибка данных.

### 4. Карточка заказа

Для промо-заказов на странице заказа показывать:
- бейдж типа;
- строку «Оформлен по акции “…”» со ссылкой на лендинг (данные из `promotion_rule_id`
  позиций);
- для `promo_sample` — пометку «Рекламные образцы, не входят в накладную»;
- связь с «родительским» заказом того же оформления: клиент видит пять заказов и должен
  понимать, что это одна покупка. У `orders` есть поле `parent_id` — проверить, используется
  ли оно сейчас при расщеплении на наличие/предзаказ, и либо задействовать, либо
  группировать по `cart_id`.

## Нюансы

- **Печатные формы и выгрузки.** Если где-то формируется печатная форма заказа или
  экспорт в Excel — типы там тоже подписаны, проверить.
- **Сортировка списка.** Пять заказов одного оформления должны идти рядом и в понятном
  порядке (основной → предзаказ → уценка → промо → образцы), а не вперемешку по id.
- **Пустая сумма.** В списках заказов «0 ₽» не должно выглядеть как ошибка загрузки —
  для промо-заказов с нулевой суммой писать «Бесплатно».
- Интерфейс — только русский.
