# up-05: «Пора пополнить» — кабинет и страница недобора

**Приоритет:** средний
**Эпик:** [up-00](2026-08-14_up-00-epic.md)
**Зависит от:** up-02; блок недобора — от sub-04 парного эпика
**Создано:** 2026-08-14

## Описание

### Кабинет: блок «Пора пополнить»

На дашборде кабинета и отдельной страницей: просроченные циклы клиента
(слой 1) с человеческой причиной «вы берёте это каждые ~3 недели, последний
раз — 5 недель назад», типовым количеством и кнопкой «В корзину».
Это **его собственные данные о нём самом** — прозрачность как сервис:
показываем интервалы и историю честно, без манипуляций.

- Только товары с запасом; количество предзаполнено `typical_quantity`.
- «Скрыть» у строки → `dismissed`, пара не показывается до следующего цикла.
- Показы/действия → `upsell_signals`, `surface = cabinet`.

### Страница недобора (sub-04): блок «раз уж едет новая коробка»

Пост-заказное окно 2 из эпика — вердикт «да, ограниченно»:

- **только слой 1** — его собственные циклы; никаких новинок, сопутствия
  и маркетинга: тон страницы — извинение;
- формулировка: «Раз собираем новую отгрузку — можно добавить то, что у вас
  заканчивается, чтобы не платить доставку дважды»;
- блок визуально второстепенный, ниже вариантов замены;
- **только товары с запасом** (недобор на странице недобора недопустим);
- предохранители: сумма недобора выше порога **или** `sentiment` клиента
  `irritated`/`at_risk` → блок не показывается вовсе;
- выбранное уходит в тот же заказ-замену (в программную корзину sub-04),
  строки метятся `upsell_signals` с `surface = shortage_page` — по ним
  отдельная конверсия.

## Критерии готовности

- [ ] Блок в кабинете: причина, типовое количество, «В корзину», «Скрыть»
- [ ] Блок на странице недобора: только слой 1, предохранители по сумме и sentiment работают
- [ ] Добавленное на странице недобора попадает в заказ-замену и метится источником
