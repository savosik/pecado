# res-06 · Чекаут: radio «можно отгружать / поставьте в резерв»

**Приоритет:** высокий
**Создано:** 2026-09-02
**Эпик:** [res-00](2026-09-02_res-00-epic.md)
**Зависимости:** res-05
**Волна:** 2

## Описание

Текущая галочка подтверждения перед оформлением (из рефакторинга сводки-чека) превращается
в radio из двух вариантов:

- 🔘 **«Подтверждаю — можно отгружать»** (по умолчанию) — текущее поведение;
- 🔘 **«Поставьте в резерв»** — заказ уходит в 1С с признаком резерва. Рядом — срок:
  «Резерв держится N часов, до {дата, время}» (срок из res-05, с учётом индивидуального).

### Бэкенд

- `CheckoutService`/`OrderAssembler`: признак резерва прокидывается в заказ и в исходящий
  `order.created` (поле из res-02). При расщеплении корзины на несколько заказов признак
  применяется ко всем, к которым применим (уточнить: promo/defect/preorder — применим ли
  резерв, по умолчанию — только к типу `order`).
- Партнёр с отключённой опцией (res-05) — radio нет, поведение как сегодня; выбор резерва
  в обход UI отбивается валидацией на сервере.

### Редирект после оформления

- Несколько заказов → раздел «Заказы в резерве» (res-07);
- один заказ → сразу в его детали (там таймер).

### UX

- Radio через обёртки `@/components/ui/*` (Chakra v3), недостающие снипеты — через CLI.
- Мобильный чекаут: крупные тап-зоны, без переносов-огрызков — с учётом свежих мобильных
  дефектов чекаута. Все тексты на русском.

## Критерии готовности

- [ ] Radio с умолчанием «можно отгружать»; выбор резерва создаёт заказ с признаком резерва.
- [ ] `order.created` уходит в 1С с признаком, интеграционный тест зелёный.
- [ ] Редирект: несколько заказов → раздел, один → детали.
- [ ] У отключённого партнёра radio нет, серверная валидация отбивает обход.
- [ ] Мобильная вёрстка чекаута проверена на реальном экране.
