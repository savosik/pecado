# debt-08: обещания оплаты и диспуты по документам

**Приоритет:** средний
**Эпик:** [debt-00](2026-08-21_debt-00-epic.md)
**Зависит от:** debt-02; поверхности — debt-05
**Создано:** 2026-08-21

## Описание

### `payment_promises` — обещание оплаты (promise-to-pay)

| Поле | Комментарий |
|---|---|
| `user_id`, `company_id` | кто и по какому контрагенту |
| `amount`, `promised_at` | сколько и к какой дате |
| `created_by`, `source` | менеджер из CRM / клиент из кабинета |
| `status` | `active` → `kept` (оплата пришла к дате) / `broken` / `cancelled` |

Эффекты: активное обещание замораживает эскалацию по обещанной сумме до даты;
`kept` проставляется автоматически по платежам из 1С; `broken` — **сильнейший
негативный сигнал скоринга** (немедленно уровень выше, задача менеджеру).

Права (решение 21.08): менеджер — без ограничений из CRM; клиент — из кабинета
(«Сообщить об оплате»), с ограничителями: одно активное обещание, дата не дальше
14 дней, после `broken` следующее — только через менеджера.

### `debt_disputes` — «не согласен с документом»

Клиент помечает строку долга спорной (кнопка в расшифровке debt-05, комментарий
обязателен). Эффект (решение 21.08): спорная сумма **сразу** исключается из
скоринга; менеджеру — задача с SLA 2 рабочих дня (`CrmTaskService`, related —
отгрузка). Разбор: менеджер закрывает диспут исходом `confirmed` (долг правильный,
сумма возвращается в скоринг, клиенту письмо с объяснением) или `resolved`
(ошибка данных — эскалация по ней отменяется, расхождение уходит 1С-нику).
Злоупотребление видно в журнале: активных диспутов у клиента больше N — сигнал
РОП, не автоматике.

Это главный предохранитель от блокировки добросовестного клиента по ошибке
данных (история завышения долга в 5–20 раз).

**Первый боевой кейс — Гевея** (решение 21.08): крупная сеть, поставки не
прекращаем и не блокируем; долг 1,54 млн ведём через цепочку обещаний оплаты
с датами — обещания и контроль их исполнения заменяют этому клиенту всю
лестницу ограничений.

## Критерии готовности

- [ ] Миграции с комментариями, `bi:sync-grants`
- [ ] Обещание: авто-`kept` по платежам 1С (интеграционный тест шины), `broken` ночным переходом даты, эффект заморозки/эскалации — юнит-тесты
- [ ] Ограничители клиентских обещаний (одно, ≤ 14 дней, запрет после `broken`)
- [ ] Диспут: мгновенное исключение из скоринга, задача менеджеру с SLA, оба исхода
- [ ] Поверхности в кабинете (debt-05) и CRM-карточке клиента; всё на русском
- [ ] `debt:explain` показывает активные обещания и диспуты в разборе уровня
