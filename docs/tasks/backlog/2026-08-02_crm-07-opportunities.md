# crm-07 · Возможности: кому продать, кто не брал, кто просел

**Приоритет:** средний
**Создано:** 2026-08-02
**Эпик:** [crm-00](2026-08-02_crm-00-epic.md)
**Волна:** 4 (планы и аналитика)
**Зависимости:** `crm-06` (выполнение планов); мягко — `crm-09`, `crm-10` (кнопки действий)

## Описание

Превратить «отставание от плана» в список конкретных действий: кому позвонить сегодня, кто
перестал брать бренд, кто просел против прошлого периода, кто спит с высоким средним чеком.

## Ключевое решение: ранжирование поверх существующего gap-анализа

`App\Services\Analytics\GapAnalysisService` уже отвечает на вопрос «кто не покупал X»:
поддерживает subject `partner|contractor`, include/exclude по бренду и категории, окна
(`all|months|period`), пул спящих (`include_dormant`), обогащение метриками периода и датой
последней покупки. Экран gap-анализа уже работает на `/crm/analytics`.

Чего не хватает — **приоритизации**: сейчас это плоский список, а менеджеру нужен порядок
обзвона. Новая часть — только ранжирование и пресеты, сам поиск не переписываем.

## Что делаем

**Сервис `App\Services\Crm\OpportunityService`** — обёртка над `GapAnalysisService`
и `SalesPlanService`:

```php
public function rank(CarbonInterface $month, PlanScope $scope, OpportunityPreset $preset): array
```

Каждая строка — клиент с причиной попадания и оценкой:

| Сигнал | Смысл |
|---|---|
| Разрыв плана клиента | план месяца минус факт, в рублях — сколько недобрано именно здесь |
| Давность последней отгрузки | дней с последней покупки против обычного цикла клиента (`crm_client_profiles.order_cycle_days`, если заполнен) |
| Средний чек | клиент с крупным чеком стоит звонка раньше мелкого |
| Падение против прошлого периода | факт периода против такого же предыдущего (`AnalyticsFilters::previousPeriod()` уже умеет) |
| ABC-класс | `ShipmentAnalyticsService::abcXyz()` — A-клиент важнее C |

Оценка — взвешенная сумма нормированных сигналов, веса в `config/crm.php`. **Каждая строка
несёт человекочитаемое объяснение** («не брал 74 дня при обычном цикле 30; средний чек 180 тыс. ₽»):
список без причины менеджер не примет, а с причиной — проверит.

**Пресеты `App\Enums\Crm\OpportunityPreset`:**
- «Отстают от плана» — клиенты с наибольшим разрывом плана месяца;
- «Спящие с высоким чеком» — нет отгрузок дольше обычного цикла, чек выше медианы;
- «Не берут бренд/категорию» — параметризуемый пресет поверх `GapAnalysisService`;
- «Просели» — факт периода ниже предыдущего сопоставимого более чем на N %;
- «Ни разу не покупали» — клиент с менеджером, но без единой отгрузки (на проде таких ~86 %,
  поэтому пресет обязательно с фильтром по давности регистрации).

**Скоуп и права.** Право `crm-opportunities.view`. Менеджер видит только своих клиентов
(`User::visibleInCrm`), РОП — отдел с фильтром по менеджеру.

**Роуты** в `routes/crm.php`:

```
GET /crm/opportunities          — список с пресетом и фильтрами
GET /crm/opportunities/export   — XLSX через SimpleXlsxExporter::stream()
```

**Фронтенд:**
- панель «Возможности» на `Crm/Pages/Plans/Index.jsx` и виджет-топ-5 на дашборде;
- в строке — клиент, причина, сумма разрыва, дата последней отгрузки и кнопки действий:
  **«Поставить задачу»** (диалог из `crm-09` с подставленным клиентом) и **«Написать письмо»**
  (диалог из `crm-10`). Если волна 3 ещё не сделана — кнопки добавляются последним шагом
  карточки, список работает и без них.

## Границы

- Рекомендаций «какой товар предложить» на уровне ML не делаем. Товарный слой уже есть
  в `ShipmentAnalyticsService::insights()` (`reorderSuggestions`, `trendBrands`) — при
  раскрытии строки показываем его как есть.
- Автоматических действий (сам поставил задачу, сам отправил письмо) нет: список предлагает,
  решает менеджер.
- Своей таблицы у возможностей нет — это витрина над существующими данными. Кэш на 15 минут
  по ключу скоупа и пресета.

## Критерии готовности

- [ ] Поиск идёт через `GapAnalysisService`, дублирующего SQL нет
- [ ] Каждая строка объясняет, почему клиент в списке
- [ ] Пять пресетов работают; веса вынесены в конфиг
- [ ] Менеджер видит только своих клиентов; РОП фильтрует по менеджеру
- [ ] XLSX выгружается
- [ ] Кнопки «Поставить задачу» и «Написать письмо» открывают диалоги с подставленным клиентом
      (если волна 3 готова)
- [ ] UI на русском
- [ ] Feature-тест `tests/Feature/Crm/OpportunitiesTest.php`: пресеты, порядок ранжирования
      на фикстуре, изоляция скоупа, гейт права
