# Изменение формата первоначального пароля `partner.created` из 1С

**Приоритет:** средний
**Исполнитель:** -
**Создано:** 2026-04-15

## Описание

Изменилось требование к формату первоначального пароля, с которым 1С создаёт нового пользователя. Ранее в событии `partner.created` поле `password` ожидалось как CRC32-хеш в шестнадцатеричном (hex) формате (строго 8 символов, например `a1b2c3d4`).

Теперь 1С будет присылать этот пароль в **десятичном виде** (только цифры, максимальное значение 4294967295, длина до 10 символов). 

Необходимо актуализировать API контракты, JSON схемы и тесты (код `HandlePartnerCreated` пароль сохраняет "как есть", но валидация JSON-схемы не пропустит новый формат).

## Критерии готовности

- [ ] В файле `app/Services/Erp/Schemas/partner.created.json` обновить правила для поля `password`: убрать жесткое ограничение `maxLength: 8`, заменить на `maxLength: 10`, `minLength: 1`, и добавить проверку на формат (только цифры).
- [ ] В файлах спецификации AsyncAPI (`docs/asyncapi/pecado-erp-bundled.yaml` и `docs/asyncapi/pecado-erp-integration.yaml`) найти и изменить описание поля с "CRC32-хеш email (8 hex-символов)" на "Десятичный CRC32-хеш email (только цифры)".
- [ ] Перегенерировать документацию AsyncAPI (HTML/индекс), опирающуюся на YAML скрипты.
- [ ] Проверить все PHPUnit Feature-тесты, работающие с моковым пейлоадом `partner.created` (напр. создающие пользователей) — изменить там передаваемый пароль на цифровой.
- [ ] Убедиться, что ERP-интеграция успешно валидирует новый формат сообщений.
