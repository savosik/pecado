# crm-03 · Профиль клиента: ЛПР, платёжное поведение, интересы, свободные заметки

**Приоритет:** высокий
**Создано:** 2026-08-02
**Эпик:** [crm-00](2026-08-02_crm-00-epic.md)
**Волна:** 2 (карточка клиента)
**Зависимости:** нет (лента из `crm-01` желательна, но не блокирует)

## Описание

Дать менеджеру место, где он записывает всё, что знает о клиенте: кто принимает решения,
как обычно платит, чем интересуется, какое настроение, плюс свободный текст на всё остальное.
Сейчас такого места нет вовсе — карточка клиента `Crm/Pages/Clients/Show.jsx` (63 строки)
показывает контакты и менеджера.

**Формат — гибрид:** структурированные поля для того, что нужно фильтровать и отдавать ИИ-агенту,
плюс большое Markdown-поле «Заметки» для наблюдений, которые в анкету не влезают. Только поля —
менеджер не запишет нестандартное; только свободный текст — нельзя спросить «покажи всех,
кто платит по предоплате».

## Ключевое решение: отдельная таблица, не колонки в `users`

`users` — зона владения 1С: `HandlePartnerCreated` и `HandlePartnerUpdated` собирают `$updateData`
и пишут туда при каждом сообщении о партнёре. Проверено, что `PublishUserToErp` отправляет
партнёра в шину только при первом заполнении `name`, то есть новые колонки не утекли бы в 1С
прямо сейчас — но граница владения должна быть явной, чтобы следующая правка обработчика
не затёрла заметки менеджера.

## Что делаем

**Миграция `crm_client_profiles`** — 1:1 к `users` (комментарии к таблице и всем столбцам):

```php
$table->comment('Профиль клиента в CRM: то, что знает менеджер, но не знает 1С');
$table->id();
$table->foreignId('user_id')->unique()->constrained()->cascadeOnDelete();

// Кто принимает решения
$table->string('decision_maker_name')->nullable()->comment('ЛПР: имя');
$table->string('decision_maker_role')->nullable()->comment('ЛПР: должность или роль в закупке');
$table->string('decision_maker_contact')->nullable()->comment('ЛПР: телефон, почта, мессенджер');
$table->text('decision_process')->nullable()->comment('Как принимается решение: кто согласует, сколько ждать');

// Как платит
$table->string('payment_behavior', 30)->nullable()
      ->comment("Платёжное поведение: 'prepay' — предоплата, 'on_delivery' — по факту, 'deferred' — отсрочка, 'mixed' — по-разному, 'problematic' — задерживает");
$table->string('payment_terms')->nullable()->comment('Условия словами: «отсрочка 14 дней», «только по счёту»');
$table->unsignedSmallInteger('order_cycle_days')->nullable()->comment('Обычная периодичность закупок в днях — для напоминаний');

// Как общаться
$table->string('preferred_channel', 20)->nullable()
      ->comment("Канал связи: 'phone', 'email', 'whatsapp', 'telegram', 'personal'");
$table->string('sentiment', 20)->nullable()
      ->comment("Настроение: 'loyal' — лоялен, 'neutral' — нейтрален, 'irritated' — раздражён, 'at_risk' — на грани ухода");

// Свободная часть
$table->longText('notes_md')->nullable()->comment('Заметки о клиенте в Markdown: всё, что не влезло в поля');
$table->timestamp('notes_updated_at')->nullable()->comment('Когда заметки правились в последний раз');
$table->foreignId('notes_updated_by')->nullable()->constrained('users')->nullOnDelete();

$table->timestamps();
```

Строковые enum-поля, а не `enum`-тип БД: набор значений будет уточняться в работе, а менять
`enum` в MySQL — это `ALTER TABLE` на боевой таблице. Значения валидируются PHP-енумами
(`PaymentBehavior`, `PreferredChannel`, `ClientSentiment` в `App\Enums\Crm\`).

**Миграция `crm_client_profile_revisions`** — история свободных заметок:

```php
$table->comment('История правок свободных заметок о клиенте — кто и что переписал');
$table->foreignId('crm_client_profile_id')->constrained()->cascadeOnDelete();
$table->foreignId('user_id')->nullable()->constrained()->nullOnDelete();
$table->longText('notes_md')->comment('Содержимое заметок ДО правки');
$table->timestamps();
```

Пишем предыдущую версию при каждом сохранении, если текст изменился. Заметки — коллективный
документ отдела; «кто-то переписал и мы не знаем что было» — потеря, история дешевле споров.

**Интересы — теги, а не своё поле.** `spatie/laravel-tags` уже стоит, таблицы `tags`/`taggables`
есть. Подключаем `HasTags` к `User`, используем **тип** `crm-interest`
(`$user->syncTagsWithType($tags, 'crm-interest')`) — так интересы не смешаются с товарными
тегами и не потребуют своей таблицы. В UI — поле с автодополнением по существующим тегам типа.

**Модель `App\Models\CrmClientProfile`** — `belongsTo(User)`, `hasMany(revisions)`,
`profile()` HasOne на `User` с `firstOrNew` в сервисе, чтобы карточка открывалась и без профиля.

**Сервис `App\Services\Crm\ClientProfileService`** — `update(User $client, array $data, User $actor)`:
валидация енумов, запись ревизии при изменении `notes_md`, синк тегов. Одна точка входа,
которой позже воспользуется и ИИ-агент из волны 5.

**Роуты** в `routes/crm.php` под `permission:crm-profile.edit`:

```
PUT /crm/clients/{client}/profile
```

`{client}` резолвится через `User::visibleInCrm($actor)` + `findOrFail` — как в существующем
`ClientController::show()`, чтобы чужой клиент давал 404, а не 403.

**Фронтенд:** карточка клиента получает вкладку «Профиль»:
- структурированные поля — обычная Chakra-форма из `@/components/ui/*`, енумы — селекты
  с русскими подписями;
- интересы — теги с автодополнением;
- заметки — `@uiw/react-md-editor` (уже в зависимостях), с показом «правил такой-то, тогда-то»
  и раскрывающейся историей версий.

**Права**: ресурс `crm-profile`, действия `view, edit`, метка «CRM: Профиль клиента».
Выдать `sales-manager`, `sales-manager-crm`, `sales-head`.

## Границы

- Жизненный статус — карточка `crm-04`, он кладётся в эту же таблицу отдельной миграцией.
- Вложения к карточке клиента — `crm-02`.
- Автозаполнение профиля из истории заказов не делаем: догадка, записанная как факт менеджера,
  хуже пустого поля.

## Критерии готовности

- [ ] Миграции с комментариями к таблицам и всем столбцам, FK — через `->change()`
- [ ] `bi:sync-grants` прогнан
- [ ] Профиль заполняется и сохраняется; карточка открывается и у клиента без профиля
- [ ] Правка заметок пишет ревизию; история видна в UI
- [ ] Интересы сохраняются тегами с типом `crm-interest` и не смешиваются с товарными
- [ ] Чужой клиент → 404 при попытке сохранить профиль
- [ ] Все подписи, значения селектов и ошибки валидации — на русском
- [ ] Feature-тест `tests/Feature/Crm/ClientProfileTest.php` (сохранение, ревизии, изоляция, гейт права)
