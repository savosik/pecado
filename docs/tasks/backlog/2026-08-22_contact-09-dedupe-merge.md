## Описание

Модель «человек + привязки» снимает структурную причину дублей: Мария у двух юрлиц — это одна
карточка. Но остаются человеческие: её заведут дважды из двух разных карточек, а мастер
наполнения даст кандидатов из пяти источников, где пересечения гарантированы.

## Подсказка при создании

Пока менеджер набирает форму, ищем похожих: совпадение `phone_digits`, **или** почты, **или**
нормализованного ФИО у того же партнёра. Найденное показываем прямо в форме: «Похоже, такой
человек уже есть — открыть его?».

Подсказка, а не запрет: однофамильцы бывают, и решать должен человек.

## Слияние

Экран «Возможные дубли» со списком пар. При слиянии на победителя переезжают привязки, письма
(`contact_id`), звонки, комментарии, задачи и файлы. Проигравший получает `deleted_at`
и `merged_into_id` — не удаляется физически, чтобы ссылки не осиротели молча.

Конфликтующие поля (разные телефоны, разные должности) выбираются вручную по одному, а не
«побеждает свежий»: свежий бывает опечаткой.

Мягко удалённый дубль перестаёт резолвиться в `PartnerAddressBook` — иначе письмо ушло бы
на карточку, которой больше нет.

## Критерии готовности

- [ ] Подсказка при создании по телефону, почте и ФИО
- [ ] Экран «Возможные дубли»
- [ ] Слияние переносит все ссылки; ни одна не осиротела — тест
- [ ] Повторное слияние идемпотентно
- [ ] Слитый дубль не резолвится в адресной книге писем
