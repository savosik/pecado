# up-06: закупочный лист и дайджест к дате закупки

**Приоритет:** средний
**Эпик:** [up-00](2026-08-14_up-00-epic.md)
**Зависит от:** up-02, up-03 (менеджерский контур), up-04/up-05 (обкатанные слои)
**Создано:** 2026-08-14

## Описание

Ядро концепции: предзаполненный черновик закупки по одному URL.

### Сборка листа

Планировщик за 2–3 дня до `next_due` даты закупки клиента (медиана
фактических интервалов заказов; фолбэк — `order_cycle_days` профиля)
собирает `upsell_digest`:

1. «Пора пополнить» — просроченные и подходящие к сроку циклы с типовыми
   количествами;
2. «К вашей матрице» — сопутствие из подтверждённых `product_complements`;
3. «Новинки в ваших категориях» — с учётом `novelty_attitude`;
4. «Уценка в ваших категориях» — живые партии `product_defects`;
5. существующие back-in-stock предложения — вливаются сюда же, отдельный
   контур писем не плодим.

Сквозные фильтры эпика; лимит размера листа (конфиг, старт ~15 позиций) —
черновик закупки, а не каталог.

### Доставка — через менеджера (фаза «менеджер отправляет всё»)

Черновик дайджеста попадает менеджеру (паттерн `BackInStockDraftService`):
правит состав/текст → отправляет. Письмо от имени персонального менеджера,
тон «подготовил черновик вашей закупки». Частота — **один дайджест на цикл
клиента**, повторов нет; клиент без цикла и без `order_cycle_days` дайджест
не получает.

### Страница листа

URL по `upsell_digests.uuid` (signed, живёт до следующего цикла), также
доступна из кабинета. Секции слоёв, у каждой позиции причина, количество
редактируемо, вычёркивание строк. Кнопка **«Всё выбранное — в корзину»** →
обычный чекаут (не постинг заказа: контекст плановый, клиент докинет своё).
`orders.upsell_source = digest`, строки связаны с сигналами.

Действия менеджера над черновиком: **Отправить** / **Отложить до следующего
цикла** (лист жидкий или момент неудачный — письмо не уходит, лист остаётся
доступным в кабинете клиента) / **Позвонить вместо письма**.

### Дожим и обратная связь менеджеру

- **Тихие уведомления** (информируют, задач не создают): «клиент открыл лист»,
  «клиент собрал заказ из листа на N ₽».
- **Единственный аврал домена**: лист не открыт за 3 дня **и** предсказанная
  дата закупки прошла → `CrmTask` «‹Клиент› не отреагировал на лист и пропустил
  свой цикл — позвонить». Это ранний сигнал `sleeping`, пойманный на недели
  раньше месячного отчёта; итог звонка менеджер фиксирует, и он же — вход для
  `lifecycle_hint`.
- Повторного письма-напоминания **нет** (в отличие от замен): пропущенный цикл —
  повод для звонка, не для второго письма.

### Кому не шлём

`sentiment = irritated/at_risk`, `lifecycle_status = churned/hopeless`,
клиенты без персонального менеджера (пока не назначен), пустой лист
(< N позиций после фильтров) — дайджест не создаётся.

## Критерии готовности

- [ ] Планировщик собирает дайджесты к дате закупки, один на цикл, стоп-условия работают
- [ ] Черновик у менеджера: правка состава и текста, отправка / отложить / позвонить; без менеджера не уходит
- [ ] Дожим: задача «позвонить» при неоткрытом листе + пропущенном цикле; тихие уведомления об открытии/заказе; повторных писем нет
- [ ] Страница листа: секции, причины, количества, «в корзину» одной кнопкой
- [ ] Back-in-stock влит: старая команда либо переведена на дайджест, либо выключена без потери защиты от повторов
- [ ] Полное замыкание: показ → клик → корзина → заказ прослеживается по `upsell_signals`
- [ ] UI и письма на русском; Mailpit-проверка; signed URL истекает корректно
