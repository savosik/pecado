# res-07 · Кабинет: раздел «Заказы в резерве» с таймерами

**Приоритет:** высокий
**Создано:** 2026-09-02
**Эпик:** [res-00](2026-09-02_res-00-epic.md)
**Зависимости:** res-05, res-04
**Волна:** 2

## Описание

Отдельный пункт меню кабинета «Заказы в резерве» — рабочее место интернетчика.

### Список

- Только заказы в статусе «Резерв»; в строке — **живой таймер обратного отсчёта**
  до `reserved_until` (отсчёт на клиенте, без запросов на каждый тик).
- Бейдж-счётчик резервов на пункте меню — чтобы висящие резервы не забывались.
- Состояние «истекает скоро» визуально акцентировано (порог — например, < 6 ч).
- Действия строк — по стандарту глаз/карандаш/корзина (`RowActions`), без текстовых кнопок.

### Детали резервного заказа

- Тот же таймер + **три полноценные кнопки** (не иконки):
  - **«Отправить в отгрузку»** — подтверждение: заказ переходит в обычный конвейер
    (исходящее сообщение по протоколу res-01/res-02), уходит из раздела в «Заказы»;
  - **«Редактировать»** — правка состава (res-08);
  - **«Отменить»** — снятие резерва целиком (механика res-04, ConfirmDialog).
- После истечения срока заказ не исчезает молча — ясное состояние «резерв снят».

### UX

- Идеально на десктопе и мобильном: основной сценарий — правка с телефона сразу после
  звонка покупателю; операции в один-два тапа.
- Стандарты кабинета: русский язык, карточки с фоном (не «серое на сером»), минимализм
  эффектов, Chakra через `@/components/ui/*`.
- У партнёра с отключённой опцией раздел скрыт (но с живыми резервами — виден, пока они
  не доживут).

## Критерии готовности

- [ ] Раздел в меню с бейджем, список с таймерами, акцент «истекает скоро».
- [ ] Подтверждение переводит заказ в обычный конвейер, сообщение уходит в 1С (интеграционный тест).
- [ ] Кнопки отмены и редактирования подключены к res-04/res-08.
- [ ] Редирект из чекаута (res-06) попадает в раздел/детали.
- [ ] Мобильная вёрстка списка и деталей проверена на реальном экране.
- [ ] Feature-тесты: видимость раздела, состав списка, подтверждение, права владельца.
