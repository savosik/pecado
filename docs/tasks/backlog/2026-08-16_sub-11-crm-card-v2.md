# sub-11: карточка недобора v2 — форма менеджера

**Приоритет:** высокий
**Эпик:** [sub-00](../review/2026-08-14_sub-00-epic.md)
**Зависит от:** sub-10 (группировка по слоям опирается на новое ранжирование)
**Создано:** 2026-08-16

## Описание

Карточка `/crm/shortages/{id}` работает, но менеджеру ей пользоваться тяжело.
Правим конкретные шероховатости, найденные разбором.

### Письмо в карточке

- Правки текста затираются: любое изменение состава кандидатов вызывает
  `refreshDraft()`, который перегенерирует черновик целиком. Сделать: ручные
  правки сохраняются, при изменении состава пересобирается только блок
  кандидатов (или менеджеру предлагается diff «обновить блок замен?»).
- Редактирование сырого HTML в mono-textarea — заменить на нормальный редактор
  (в проекте уже есть Tiptap) поверх шаблона из sub-12.

### Исходы

- «Предложить подождать» сейчас физически идентичен «Отправить подборку»
  (тот же `drafts->send()`): дать исходу собственный текст письма
  («товар будет, зарезервируем по приходу») без блока кандидатов.
- «Позвонить» — фиксировать результат звонка (сейчас только закрывает задачу).

### Данные в карточке

- Поиск ручного кандидата показывает `base_price` — показывать индивидуальную
  цену клиента (как везде в домене, `PriceService`).
- Остаток уценки в `candidatePayload` берётся как `quantity` партии —
  привести к `DefectStockService::available()`, как на клиентской странице
  (сейчас менеджер может предложить уже разобранную уценку).
- Кандидаты сгруппировать по слоям с бейджами и причинами (порядок из sub-10),
  дать менеджеру правку предлагаемого количества.

### Технический долг

- Закрытие `CrmTask` по `title LIKE 'Недобор по заказу%'` — заменить на связь
  (morph/поле на задаче).
- N+1 в очереди связей `/crm/shortages/links` (подсчёт негативных сигналов
  запросом на строку) — одним запросом.
- Точечные перезагрузки вместо `router.reload()` целиком после каждого действия
  (сейчас теряется контекст прокрутки и набранный текст).
- Feature-тесты `ShortageController` — долг DoD sub-03, до сих пор не закрыт.

## Критерии готовности

- [ ] Правки письма переживают изменение состава кандидатов (тест)
- [ ] Исход «подождать» шлёт собственный текст; результат звонка фиксируется
- [ ] Индивидуальные цены в поиске кандидатов; остаток уценки через `DefectStockService::available()` (расхождение с клиентской страницей устранено — тест)
- [ ] Задача закрывается по связи, не по `title LIKE`; N+1 в /links устранён
- [ ] Кандидаты сгруппированы по слоям, количество редактируется
- [ ] UI на Chakra-обёртках `@/components/ui/*`, весь интерфейс на русском, права `crm-shortages.*`
- [ ] Feature-тесты `ShortageController` (очередь, карточка, исходы, кандидаты); браузерная проверка на dev
