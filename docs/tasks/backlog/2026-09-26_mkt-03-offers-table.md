# mkt-03. Приём снимка предложений — надстройка над `product_warehouse`

**Приоритет:** высокий · **Создано:** 2026-09-26 · **Переписано:** 2026-10-03 · **Волна:** 0 · **Эпик:** mkt-00
**Зависит от:** mkt-01
**Оценка (ориентир):** 3–4 дня (включая интеграционные тесты)

## Описание

Таблица предложений (имя — при реализации, например `product_offers`): `product_id`, `warehouse_id`,
`organization_id`, `vat_code`, `quantity`, **`offer_key`** (строка 1С, непрозрачная), `revision`,
`calculated_at`. Комментарии таблицы и столбцов на русском.

**`product_warehouse` остаётся истиной по сумме остатка** — это не замена источника, а надстройка.
Обработчик снимка одной транзакцией:

1. защищается по `revision` (устаревший или повторный снимок игнорируется, как в `project_erp_patterns`);
2. перезаписывает строки предложений товара (снимок полный — отсутствующая строка = 0);
3. пишет сумму по каждому складу снимка в `product_warehouse` и вызывает те же следствия, что
   `HandleStockUpdated` (трекер доступности, сброс кеша выгрузок).

Склад предзаказа в снимке не участвует — по нему по-прежнему работает `stock.updated`. Для складов из снимка
`stock.updated` и снимок **не должны спорить**: один писатель на склад; порядок перехода (когда `stock.updated`
по складу перестаёт приходить) — согласовать с 1С в mkt-01 и зафиксировать здесь.

Неизвестный `organization_uuid` создаёт заглушку организации (как сегодня из документов, `is_stub`);
неизвестный `warehouse_uuid` — по текущим правилам `stock.updated`.

Решение «вариант “виртуальные склады = предложения” отвергнут» (размножение складов ломает потребителей,
читающих конкретный склад) — записано в концепции 02.10, повторно не рассматривать.

## Критерии готовности

- [ ] Миграция таблицы предложений с `->comment()` на таблице и всех столбцах; таблица отмечена для
      `bi:sync-grants`
- [ ] Обработчик снимка: защита по `revision`, полная перезапись строк товара, сумма по складу в
      `product_warehouse` в той же транзакции
- [ ] Тест инварианта: после снимка `sum(quantity)` по складу = `product_warehouse.quantity`
- [ ] Интеграционные тесты приёма: повтор снимка, устаревший `revision`, пустой `offers[]` (все нули),
      неизвестные UUID, склад предзаказа в снимке отсутствует
- [ ] Повторный приём тех же строк не меняет `offer_key` на стороне сайта (ключ хранится как получен)
- [ ] Старое поведение `stock.updated` для складов вне снимка не изменилось
