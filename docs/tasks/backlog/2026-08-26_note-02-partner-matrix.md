# note-02 — матрица в карточке партнёра

**Эпик:** `note-00`
**Зависит от:** `note-01`

## Что делаем

Новая вкладка «Уведомления» в карточке партнёра CRM. Строки — типы уведомлений
из конфига, сгруппированные по семействам:

```
Заказы        Оформлен заказ            [ на логин ] [ + ]
              Смена статуса заказа      [ на логин ] [ бухгалтеру ] [ + ]
              Изменился состав          — не присылать —
Документы     Опубликован документ      [ на логин ] [ + ]
Финансы       Подходит срок оплаты      [ бухгалтеру ] [ + ]
```

Ячейка — набор чипов-адресатов с кнопкой «плюс». «Не присылать» = пустой набор,
и это состояние показывается словами, а не пустотой.

Строка, где настройка отличается от умолчания, помечается; правил ли её клиент —
видно отдельным бейджем (`changed_by_client`).

## Как встраиваем

Механизм готов: `ContactsPanel`, `TaskPanel`, `CommentThread` принимают
`entityType="client" entityId={client.id}` и сами ходят за данными
(`resources/js/Crm/Pages/Clients/Show.jsx:238-341`). Делаем такую же панель:
`Tabs.Trigger` + `Tabs.Content` + право.

Выбор конкретного человека — через `CrmEntitySearch` (`app/Services/Crm/CrmEntitySearch.php`),
он уже отсекает чужих.

## Права

Отдельного ресурса не заводим: настройка уведомлений партнёра — часть карточки
партнёра, живёт под `crm-clients.view` / `crm-clients.edit`. Заводить четвёртый
реестр прав ради одной вкладки — лишнее.

## Проверка

`tests/Feature/Crm/Notifications/NotificationMatrixTest.php`:

- матрица отдаёт все типы с умолчаниями, когда отклонений нет;
- сохранение создаёт строку только для изменённого типа;
- возврат к умолчанию удаляет строку, а не пишет копию умолчания;
- чужой партнёр → **404, не 403**;
- менеджер не может подставить чужой контакт в адресаты.
