# mkt-01. Контракт шины: снимок предложений и `offer_key` в строке заказа

**Приоритет:** высокий · **Создано:** 2026-09-26 · **Переписано:** 2026-10-03 · **Волна:** 0 · **Эпик:** mkt-00
**Блокируется:** переоценкой 1С в топике №14 (seq 4 от 02.10.2026) и утверждением бюджета заказчиком
**Оценка (ориентир):** 2–3 дня

## Описание

Согласовать и опубликовать минимальное изменение протокола 1С ↔ Сайт под тонкую модель. Порядок строго
spec-first: JSON Schema → AsyncAPI → бизнес-правила и тест-план MkDocs → changelog → `npm run asyncapi:build`
→ код. Схему 1С обещано прислать **двумя частями** после их ответа (seq 4): снимок и поле в заказе.

**Часть 1. 1С → сайт: событие-снимок предложений по товару** (имя события — в схеме):
`product_uuid`, `revision`, `calculated_at` (UTC, мс), `offers[]` = `{offer_key, warehouse_uuid,
organization_uuid, vat_code, quantity}`.

- Снимок полный по товару: отсутствующая строка = 0.
- `offer_key` — строка 1С, стабильная между снимками; сайт хранит и возвращает, **не разбирает**.
- Инвариант на переход: сумма строк по складу = сегодняшний `stock.updated` по тому же складу.
- Склад предзаказа («Тюмень») в снимок не входит — по нему остаётся `stock.updated`.
- `vat_code`: предложение 1С `"22" | "5" | "0" | "without_vat"` — формат согласовать между агентами;
  тексты ставок на витрине — ровно те, что присылает 1С.
- Цена в снимок не входит. Если 1С выберет отдавать цену продавца в строке предложения (seq 4 п. 1а) —
  поле добавляется в эту же схему; если полем в файле индивидуальных цен — отдельная поставка.

**Часть 2. Сайт → 1С: `order.created`** — в строке необязательный `offer_key`, количество и цена как сейчас.
Один заказ — один продавец (строки разных `organization_uuid` сайт раскладывает по заказам с общим
признаком покупки, см. mkt-13). Строка без ключа обрабатывается как сегодня.

**Ответ 1С — существующими событиями, без новых схем:** `order.updated` с `items[].cancelled: true` и
`cancel_reason` — перечень открытый (v16.17.0, топик №17), новые коды `no_stock_seller`, `no_stock_vat`
описываем в правилах (`no_stock` 1С = наш `out_of_stock`); организация заказа (`order.updated.organization`);
ставка в `shipment.created`.

**Без изменений:** `price.updated`, `individual_prices.ready`, `shipment.*`. Событие справочника организаций
не нужно (организации есть из документов, хватает UUID в строке).
