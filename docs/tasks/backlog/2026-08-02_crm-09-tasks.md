# crm-09 · Задачи менеджеров: себе и коллегам, с дедлайнами и привязкой к сущностям

**Приоритет:** высокий
**Создано:** 2026-08-02
**Эпик:** [crm-00](2026-08-02_crm-00-epic.md)
**Волна:** 3 (работа менеджера)
**Зависимости:** `crm-01` (комментарии), `crm-02` (вложения)

## Описание

Менеджер ставит задачи себе и другим менеджерам: заголовок, описание, исполнитель, дедлайн,
отметка выполнения.

Три свойства, определяющие модель:

1. **Задача полиморфна, как комментарий** — ставится на любую поддерживаемую сущность,
   а не на фиксированный список из трёх. Привязки может не быть вовсе (задача «просто себе»).
2. **Независимо от этого**, если привязанная сущность принадлежит клиенту, задача попадает
   в **ленту этого клиента** наравне с комментариями и письмами.
3. **Все задачи целиком видны отдельным списком** в разделе «Задачи» — привязка к сущности
   и лента клиента её не подменяют. Раздел — основное место работы с задачами.

Существующий `KanbanTask` не подходит: он про баг-репорты с сайта (поля `page_url`, `browser`,
`scope: 1c|site`), у него **нет исполнителя** (только строковое `user_name`), нет дедлайна
и приоритета, а API к нему публичный и без авторизации. Это другая сущность с другой моделью
доступа — заводим свою.

## Что делаем

**Миграция `crm_tasks`** (комментарии к таблице и всем столбцам):

```php
$table->comment('Задачи менеджеров отдела продаж: себе и коллегам, с дедлайнами');
$table->id();
$table->string('title')->comment('Что сделать — коротко, видно в списках');
$table->text('description')->nullable()->comment('Подробности задачи');
$table->foreignId('author_id')->constrained('users')->cascadeOnDelete();
$table->foreignId('assignee_id')->constrained('users')->cascadeOnDelete();
$table->foreignId('client_user_id')->nullable()->constrained('users')->nullOnDelete();
$table->nullableMorphs('related');   // любая сущность из CrmEntityMap; null — задача без привязки
$table->string('status', 20)->default('open')
      ->comment("Статус: 'open' — открыта, 'in_progress' — в работе, 'done' — выполнена, 'canceled' — отменена");
$table->string('priority', 10)->default('normal')
      ->comment("Приоритет: 'low', 'normal', 'high'");
$table->timestamp('due_at')->nullable()->comment('Дедлайн; null — задача без срока');
$table->timestamp('done_at')->nullable()->comment('Когда фактически выполнена — для отчёта о сроках');
$table->timestamps();
$table->softDeletes();
$table->index(['assignee_id', 'status', 'due_at'], 'crm_tasks_assignee_status_due_idx');
$table->index(['client_user_id', 'created_at'], 'crm_tasks_client_created_idx');
```

**Привязка — тот же механизм, что у комментариев.** `related` резолвится через общий
`App\Support\Crm\CrmEntityMap` (карточка `crm-01`) — карту «строковый тип → класс модели →
как достать клиента». Добавление новой привязываемой сущности = одна строка в карте,
без правок в задачах, комментариях и вложениях по отдельности.

`client_user_id` денормализован по тому же принципу, что и в `crm-01`: лента клиента должна
собираться одним индексированным запросом, а не обходом заказов и отгрузок. Проставляется
из `related` при создании — в сервисе, в одном месте, через `CrmEntityMap::resolveClient()`.
Если сущность к клиенту не сводится (или привязки нет) — `null`, и задача просто не попадает
ни в чью ленту, оставаясь в общем списке.

`done_at` отдельно от `status`: «выполнена вовремя или с опозданием» — это про факт, а не про
момент последней правки записи, и `updated_at` для этого не годится.

**Модель `App\Models\CrmTask`** — `SoftDeletes`, `HasCrmAttachments` (из `crm-02`),
`morphMany` комментариев (из `crm-01`), связи `author()`, `assignee()`, `client()`, `related()`.
Скоупы: `assignedTo($userId)`, `authoredBy($userId)`, `overdue()`, `dueToday()`.

**Enum `App\Enums\Crm\TaskStatus`** и `TaskPriority` — с русскими метками и цветами, по образцу
`App\Enums\OrderStatus`.

**Политика `CrmTaskPolicy`:**
- `view` — автор, исполнитель или обладатель `crm-clients-all.view` (РОП видит все);
- `create` — `crm-tasks.create`; исполнителем можно назначить только сотрудника с CRM-доступом
  (проверка `hasCrmAccess()`), иначе задача уйдёт в никуда;
- `update` — автор или исполнитель (исполнитель может закрыть, но не переназначить на третьего);
- `delete` — автор или РОП.

Если задача привязана к клиенту, доступ дополнительно проверяется по `User::visibleInCrm($actor)`:
задача с привязкой к чужому клиенту не должна раскрывать его существование.

**Роуты** в `routes/crm.php` под `permission:crm-tasks.view`:

```
GET    /crm/tasks              — раздел «Задачи»: полный список с фильтрами
POST   /crm/tasks
GET    /crm/tasks/{task}
PATCH  /crm/tasks/{task}       — правка, смена статуса, закрытие
DELETE /crm/tasks/{task}
```

**Раздел «Задачи» — полный список, а не только «мои».** Показывает все задачи, доступные
актору по политике, независимо от того, к какой сущности они привязаны и привязаны ли вообще.
Быстрые пресеты (`Мне`, `От меня`, `Просрочено`, `Без привязки`, для РОПа — `Все`) переключают
**фильтр** поверх одного списка, а не открывают отдельные его версии — иначе задача без
привязки или поставленная третьим лицом теряется между вкладками.

Фильтры: статус, приоритет, автор, исполнитель, срок (просрочено / сегодня / неделя / без срока),
клиент, тип привязанной сущности, поиск по заголовку и описанию. Сортировка по сроку,
приоритету и дате создания.

Колонка «Привязка» в строке показывает тип и название сущности со ссылкой на неё — так из
общего списка видно, откуда задача выросла.

**Уведомления** — за фича-флагом `MAIL_FEATURE_CRM_TASKS` в `config/notifications.php`
(дефолт `false`, как все почтовые фичи проекта):
- `TaskAssignedNotification` — при назначении задачи не себе;
- `TaskDueSoonNotification` — команда `crm:tasks-remind` по расписанию, за день до дедлайна
  и в день просрочки.

Шаблоны — markdown-письма с темой `pecado`, рядом с существующими в `resources/views/mail/`.

**Фронтенд:**
- `Crm/Pages/Tasks/Index.jsx` — полный список с пресетами и фильтрами (на базе `DataTable`
  и `useResourceIndex`, импорт прямыми путями, не через бочку `@/Admin/Components`);
- `Crm/Pages/Tasks/components/TaskDialog.jsx` — создание и правка, с `CommentThread`
  и `AttachmentPanel` внутри;
- `Crm/Components/TaskPanel.jsx` — врезка «Задачи по этой сущности», переиспользуемая
  в карточке клиента, заказа, реализации и далее везде, где появится привязка;
- виджет «Мои задачи на сегодня» на `Crm/Pages/Dashboard.jsx`, с бейджем просроченных;
- пункт меню в `Crm/config/menuConfig.ts` с правом `crm-tasks.view`;
- кнопка «Поставить задачу» в карточке клиента и в строках других разделов — открывает диалог
  с уже проставленной привязкой.

**Права**: ресурс `crm-tasks`, действия `view, create, edit, delete`, метка «CRM: Задачи».
Выдать `sales-manager`, `sales-manager-crm`, `sales-head`.

## Границы

- Повторяющиеся задачи, подзадачи и зависимости между задачами не делаем.
- Отдельной канбан-доски для задач нет — список с фильтрами. Доска канбана в проекте уже есть
  и она про другое.
- Вложение прикрепляется к **сохранённой** задаче: `MediaService::upload()` не поддерживает
  загрузку «в никуда», поэтому диалог создаёт задачу первым шагом.

## Критерии готовности

- [ ] Миграция с комментариями к таблице и всем столбцам; `bi:sync-grants` прогнан
- [ ] Задача ставится себе и коллеге, с дедлайном, вложением и комментариями
- [ ] Задача ставится на любую сущность из `CrmEntityMap` и **без привязки** вовсе
- [ ] Раздел «Задачи» показывает полный список; задача без привязки и задача, поставленная
      третьим лицом, из него не пропадают
- [ ] Пресеты — это фильтры поверх одного списка, а не отдельные его версии
- [ ] В строке видна привязанная сущность со ссылкой
- [ ] Задача с привязкой к сущности клиента видна в ленте этого клиента
      (`ClientTimelineService` расширен типом `task`), независимо от типа сущности
- [ ] Врезка «Задачи по этой сущности» работает в карточках клиента, заказа и реализации
- [ ] Исполнителем нельзя назначить пользователя без CRM-доступа
- [ ] Задача по чужому клиенту не видна и не создаётся (404)
- [ ] Просроченные подсвечены; виджет «на сегодня» на дашборде работает
- [ ] `done_at` проставляется при закрытии
- [ ] При `MAIL_FEATURE_CRM_TASKS=false` письма не уходят; при `true` приходят в Mailpit
- [ ] Весь UI, статусы и письма — на русском
- [ ] Feature-тесты `tests/Feature/Crm/TasksTest.php` (создание, права, изоляция, лента, просрочка)
