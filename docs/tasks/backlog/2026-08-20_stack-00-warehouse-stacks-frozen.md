# stack-00: стопки складов региона — заморожено

**Приоритет:** низкий (заморожено)
**Создано:** 2026-08-19, заморожено 2026-08-20
**Где код:** `origin/feature/warehouse-stacks`, коммит `1e89788e` — 56 файлов,
в dev не мерджится. Ветка живёт только на GitHub как архив, локально удалена
вместе с worktree. Достать: `git fetch origin feature/warehouse-stacks`.

## Что это было

Приоритетная стопка primary-складов на уровне региона: верхний склад замещает
остатки и цены нижних по позициям, которые на нём в наличии, ниже — фолбэк.
Цель — торговля для отдельных клиентов с отдельных складов по иным ценам.
Сопутствующее: сплит заказов по складам (в 1С отдельными документами),
фиксация склада в `orders.assigned_warehouse_id`, привязка организации к складу
и опциональное `organization_uuid` в `order.created` (спека v16.5.0 → v16.6.0).

Реализовано полностью и покрыто тестами (42 новых, сьют был зелёный), закрыто
тремя выключенными по умолчанию флагами: `regions.stock_stack_enabled`,
`ERP_STACK_WAREHOUSE_PINNING_ENABLED`, `ERP_ORGANIZATION_UUID_ENABLED`.

## Почему заморожено

Бизнес-идея сырая — сама модель «стопки» требует доработки на уровне
постановки, а не кода. Дополнительно включение блокировали ответы 1С
(вопросы 1–3 и 5 в `docs/erp-1c-warehouse-stack-questions.md` на той же ветке):
строгое проведение по одному складу, отключение фолбэка «ОсновнойСклад»,
лимит документов на оформление, безопасность незнакомого опционального поля.

## Что из эпика уже вынесено в dev

Два фикса, к самой идее стопок отношения не имеющих:

1. **Недетерминизм индивидуальных цен** (`IndividualPriceProxy::findPrice` /
   `loadPriceMap`, `IndividualPrice::findPrice`) — карточка товара и каталог
   могли показывать клиенту разные цены на один товар. Общее правило без явного
   склада — минимальный `warehouse_id`. Заодно `$warehouseId` в
   `PriceService::getPriceMapForProducts` перестал молча игнорироваться.
2. **Кабинетные корзины мимо страхового буфера** — `resolveStockMap` считал
   свою SUM по `product_warehouse` и не вычитал буфер (buf-04), из-за чего
   клиент сегмента `stock_buffer_enabled` видел в корзинах больше, чем в
   каталоге и карточке. Переведён на `StockService::getStockMapsByIds`
   (метод заодно поднят в `StockServiceInterface`).

## Что осталось на ветке и может пригодиться отдельно

- Детерминированный порядок «выедания» буфера в экспорте
  (`AppliesStockBufferToWarehouses`) — вне режима стопки даёт лишь стабильный
  порядок по id вместо порядка загрузки связи.
