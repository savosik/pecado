# mkt-13. Заказ в 1С и обратно: `offer_key` в строке, заказ на продавца, причины отмены

**Приоритет:** высокий · **Создано:** 2026-09-26 · **Переписано:** 2026-10-03 · **Волна:** 3 · **Эпик:** mkt-00
**Зависит от:** mkt-01, mkt-12
**Оценка (ориентир):** 3–4 дня (включая тесты)

## Описание

**В 1С.** В строке `order.created` — `offer_key` ровно как получен в снимке, количество и цена как сейчас.
Сайт **не передаёт** продавца, ставку и владельца отдельными полями — всё внутри ключа, разбирает 1С
(решение 02.10: А1/А2, `ownership`, `vat_code` в строке заказа сняты). Строка без ключа — как сегодня
(клиентский API, заказы менеджеров, предзаказ, уценка, промо): 1С выбирает продавца и партию сама.

**Один заказ — один продавец.** Покупка со строками разных `organization_uuid` порождает несколько заказов
с общим признаком покупки (`checkout_uuid`); 1С подтвердила, что несколько заказов на корзину её устраивают,
общий признак сохранит и покажет упаковщику. Группировка — в mkt-12 (вариант В1). Вариант В2 «один заказ,
1С раскладывает сама» предложен 1С на выбор (seq 4) — если выберут его, карточка пересматривается
(оценка не меньше 8–12 дней, зона инцидента 25.09).

**Обратно — существующими событиями.** `order.updated.organization` заполняет продавца заказа (уже работает,
v15.8.0); `items[].cancelled: true` + `cancel_reason` — строка отменена. Новые коды причин
`no_stock_seller` («у этого продавца не хватило») и `no_stock_vat` («по этой ставке не хватило») —
расширение открытого перечня `OrderLineCancelReason`: свой текст клиенту и менеджеру, неизвестный код
по-прежнему читается как `other`. Молча по другой ставке 1С не отгружает (пожелание заказчика, seq 4 п. 5).

**Продавец в строке заказа сразу после оформления** (решение 03.10, п. 10): до прихода `order.updated`
организация заказа известна сайту из группировки — заполнять `orders.organization_id` при создании, а не
ждать 1С; расхождение с ответом 1С — видно в журнале.

Совместная отгрузка заказов разных продавцов — **потом**: `ShipTogetherService` для заказов разных
организаций её не предлагает (1С вернёт `incompatible`).

## Критерии готовности

- [ ] `order.created`: строка с `offer_key` проходит валидацию по схеме mkt-01; строка без ключа — валидна
      и обрабатывается как сегодня
- [ ] Одно оформление → по заказу на продавца с общим `checkout_uuid`; `organization_id` заполнен при создании
- [ ] Коды `no_stock_seller`, `no_stock_vat` имеют русские тексты в кабинете, письме и админке; неизвестный
      код → `other`
- [ ] Отказ 1С по одному заказу не рушит остальные и виден менеджеру
- [ ] Совместная отгрузка не предлагается для заказов разных продавцов
- [ ] Идемпотентность: повторная отправка не создаёт дублей
- [ ] Интеграционные тесты публикации и приёма ответа — в mkt-14
