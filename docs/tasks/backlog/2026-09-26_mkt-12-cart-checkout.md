# mkt-12. Корзина и оформление: строка — предложение, подпись продавца и ставки, «Оформим N заказами»

**Приоритет:** высокий · **Создано:** 2026-09-26 · **Переписано:** 2026-10-03 · **Волна:** 2 · **Эпик:** mkt-00
**Зависит от:** mkt-05
**Оценка (ориентир):** 4–5 дней (ключ в строке, лимит, проверка, группировка; из них корзина 1–1,5 и
оформление 1–1,5 — визуальная часть)

## Описание

Позиция корзины ссылается на предложение: `offer_key` в `cart_items` (по образцу партий уценки
`product_defect_id` в уникальном индексе строки). Один товар у двух продавцов или с двумя ставками — две
строки, показывается открыто.

**Корзина — решение заказчика 03.10.2026 (п. 8): подпись в строке.** Таблица как сейчас (сортировка по
колонкам сохраняется); под названием — «Продавец · НДС 22 %»; под итогом — **«Оформим N заказами: Пекадо —
… ₽, <имя 2> — … ₽. Документы от каждого продавца свои»**. Тот же приём, что сегодня у уценки и предзаказа.
**Без разделов по продавцам и без разбивки сумм НДС** (снято). Цена одна, с налогом.

**Оформление — п. 9: строка в сводке на каждого продавца**, с подписью «отдельный заказ, свои документы»,
рядом с существующими строками «Уценка — отдельный документ», «Предзаказ — отдельный заказ». Письмо
**одно** на всю покупку, в нём все заказы с продавцами (как сегодня для нескольких заказов одного оформления).

Лимит и проверка:

- счётчик строки ограничен остатком предложения; **в предзаказ излишек не перетекает** (п. 6);
- при оформлении повторная проверка по актуальному снимку: предложение исчезло или уменьшилось — понятное
  сообщение и явное действие клиента, без тихой подмены другим предложением; «добрать из другого с согласия»
  (26.09) снято — нехватка к отгрузке решается отменой строки 1С с причиной (mkt-13);
- группировка заказов по продавцу — ещё один ключ группировки в готовом механизме `OrderDraft::$groups` /
  `CheckoutService::checkout()` (вариант В1 концепции; если 1С выберет В2 «один заказ, 1С раскладывает» —
  карточка пересматривается).

## Критерии готовности

- [ ] Строка корзины хранит `offer_key`; при исчезновении предложения корзина не падает, клиент видит сообщение
- [ ] Под названием строки — торговое имя продавца и подпись ставки; под итогом — «Оформим N заказами: …»
- [ ] Разделов по продавцам и сумм НДС нет
- [ ] Ограничение количества остатком предложения работает в карточке, корзине и при оформлении; в предзаказ
      не перетекает
- [ ] Сводка оформления содержит строку на каждого продавца; одно оформление создаёт по заказу на продавца
      с общим `checkout_uuid`
- [ ] Одно письмо на всю покупку, в нём все заказы и их продавцы (тест с `EnablesClientNotifications`)
- [ ] Строки без `offer_key` (предзаказ, уценка, промо) оформляются как сегодня
