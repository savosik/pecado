## Описание

Три расширения модели `CrmTask`, которые не ломают существующее.

### Соисполнители (задача на нескольких людей)

`assignee_id` **остаётся ответственным** — на нём индексы
(`crm_tasks_assignee_status_due_idx`), каунтеры, покрытие клиентов, просрочка.
Поверх — pivot:

```php
Schema::create('crm_task_assignees', function (Blueprint $table) {
    $table->comment('Соисполнители задач CRM (помимо ответственного crm_tasks.assignee_id)');
    $table->id()->comment('Первичный ключ');
    $table->foreignId('task_id')->comment('Задача (crm_tasks.id)')->constrained('crm_tasks')->cascadeOnDelete();
    $table->foreignId('user_id')->comment('Соисполнитель (users.id)')->constrained('users')->cascadeOnDelete();
    $table->timestamps();
    $table->unique(['task_id', 'user_id']);
});
```

Правила:
- Соисполнителем, как и ответственным, может стать только сотрудник с `hasCrmAccess()` —
  то же правило `crmAccessRule()`, что в `StoreCrmTaskRequest`.
- Пресет «Мне» и скоуп `assignedTo()` включают задачи, где актор — соисполнитель.
- Соисполнитель по политике равен исполнителю в чтении и правке статуса/чек-листа,
  но `reassign` — по-прежнему автор или `crm-department.edit`.
- `TaskAssignedNotification` уходит каждому новому соисполнителю (не при каждом
  редактировании — только добавленным, себе не пишем).
- В UI — мультиселект «Соисполнители» в `TaskDialog` под полем ответственного;
  в списке — стопка аватарок/инициалов.

### Личный контроль

Наблюдение, а не исполнение: РОП (или автор) ставит задачу «на контроль»,
менеджер может взять на контроль чужую задачу, которую ему важно не упустить.

```php
Schema::create('crm_task_watchers', function (Blueprint $table) {
    $table->comment('Личный контроль: кто наблюдает за задачей, не будучи исполнителем');
    $table->id()->comment('Первичный ключ');
    $table->foreignId('task_id')->comment('Задача (crm_tasks.id)')->constrained('crm_tasks')->cascadeOnDelete();
    $table->foreignId('user_id')->comment('Контролёр (users.id)')->constrained('users')->cascadeOnDelete();
    $table->timestamps();
    $table->unique(['task_id', 'user_id']);
});
```

- Кнопка «На контроль» / «Снять с контроля» в карточке задачи и в строке списка;
  в списке у контролируемых — значок (глаз).
- Пресет «На контроле» в разделе задач (фильтр поверх общего списка, как остальные).
- Контролёр получает уведомления о закрытии (с исходом), переносе и просрочке
  задачи — тем же контуром, что письма/тосты (см. task-08), за общим флагом.
- Контролёр не появляется в статистике исполнения и в покрытии клиентов.
- Поставить на контроль **другому** пользователю (не себе) может только
  `crm-department.edit` — иначе это способ спамить коллег.

### Трудоёмкость (необязательная)

- `crm_tasks.estimate_minutes` — `unsignedSmallInteger nullable`,
  комментарий «Плановая трудоёмкость в минутах; null — не оценена».
- В UI — выбор из пресетов: 15 мин / 30 мин / 1 ч / 2 ч / 4 ч / день (480),
  с возможностью ввести своё. Показ в списке и карточке («~2 ч»).
- Сумма трудоёмкости пригодится календарю (task-06: нагрузка дня) и отчёту (task-10).
- В шаблон автоповтора (`crm_task_recurrences`) поле тоже добавить — повторяющаяся
  задача наследует оценку.

## Доводка до всех путей

`CrmTaskService::{create,update,payload}`, `StoreCrmTaskRequest`/`UpdateCrmTaskRequest`,
агентское API `TaskOperations` (list/show/create/update), MCP `crm-create-task`,
`TaskPanel`, `TaskFeedEntry`, `ClientRowEnricher` (учёт соисполнителей в `active_count`).

## Критерии готовности

- [ ] Миграции с комментариями; `db:comments:audit --strict` чист; `bi:sync-grants` прогнан
- [ ] Задача с 2+ соисполнителями видна каждому в пресете «Мне»; уведомление уходит каждому добавленному
- [ ] Соисполнителем нельзя назначить пользователя без CRM-доступа
- [ ] Соисполнитель может закрыть чек-пункт и сменить статус, но не переназначить задачу
- [ ] «На контроль» себе — любой видящий задачу; другому — только `crm-department.edit`
- [ ] Пресет «На контроле» работает; контролёр уведомляется о закрытии и переносе
- [ ] Трудоёмкость опциональна, отображается в списке/карточке, наследуется автоповтором
- [ ] Агентское API и MCP принимают и отдают новые поля
- [ ] Feature-тесты (соисполнители, права, контроль, наследование оценки); UI на русском
- [ ] Браузерная проверка на dev
