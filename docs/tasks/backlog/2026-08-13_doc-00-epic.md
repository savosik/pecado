# doc-00 · Эпик: раздел «Документы» — печатные формы из 1С в личном кабинете

**Приоритет:** высокий
**Создано:** 2026-08-13
**Версия протокола:** 16.1.0 (аддитивная — только новые события)
**Зависимости:** нет
**Блокирует:** ничего из текущих эпиков

## Проблема

Клиент не может получить свои документы сам. Счёт на оплату, счёт-фактуру, УПД, акт сверки
он запрашивает письмом или звонком менеджеру, менеджер идёт в 1С, печатает форму, сохраняет
в PDF и отправляет почтой. Поток идёт через отдел продаж целиком и целиком ручной.

На сайте документов нет вообще: есть `orders`, `shipments`, `payments`, `settlement_*` —
то есть данные документов, но не сами документы. Печатных форм нет ни как файлов, ни как
сущности. Договор существует только парой полей `contract_uuid` / `contract_name` внутри
движения регистра.

## Решение

1С формирует печатную форму, кладёт PDF в обменный бакет S3/MinIO и присылает по шине запись
о документе. Сайт забирает файл в собственное приватное хранилище, хранит запись и отдаёт
её клиенту в новом разделе кабинета «Документы» с фильтрами по типу, дате, нашей организации
и его контрагенту.

Приём файла через S3 + уведомление по шине — уже работающий в проекте приём, см.
`individual_prices.ready` (`HandleIndividualPricesReady` → `ProcessIndividualPricesFile`).
Ничего нового в инфраструктуре обмена не изобретается.

## Границы

**Входит:**

- два входящих события `printed_document.published` / `printed_document.deleted`,
  очередь `erp_in.printed_documents`;
- таблица `printed_documents`, приватный диск, перенос файла из обменного бакета;
- раздел «Документы» в личном кабинете: список, фильтры, скачивание, экспорт отбора;
- витрина в CRM для менеджеров — включая диагностику качества обмена;
- промт для ИИ-агента 1С.

**Не входит:**

- уведомления клиенту о новом документе — механизм подписок готов, секция заведена
  выключенной, включение отдельной задачей;
- история версий документа: клиент видит одну актуальную версию, перевыставление
  перезаписывает её (осознанное требование, а не упрощение);
- подписание документов, ЭДО, обратный поток «клиент запросил акт сверки»;
- генерация печатных форм на стороне сайта — сайт форм не рисует.

## Ключевые решения

| Решение | Почему |
|---|---|
| Сущность называется `PrintedDocument`, а не `Document` | Имена `Document` / `ClientDocument` / `ErpDocument` в проекте заняты по смыслу: `Crm\DocumentController` — журналы заказов и реализаций, `SettlementDocument` — регистратор взаиморасчётов, трейт `FiltersClientDocuments`. Совпадение имён в домене денег — прямая дорога к перепутанной сущности. В UI раздел называется «Документы» |
| Файл копируем к себе, а не читаем из обменного бакета | Обменный бакет обязан чиститься (прецедент `app:clean-price-dumps`), а документы нужны годами. Один бакет с двумя ретенциями = уборщик, который однажды снесёт живой счёт-фактуру. Плюс ключи обменного бакета есть у 1С на запись |
| Приём из 1С не гейтится фиче-флагом | Флаг закрывает только показ. Иначе документы, присланные раньше срока, потерялись бы безвозвратно — перезалить их неоткуда. Тот же принцип, что у `erp.organizations.enabled` |
| `revision` обязателен, событие входит в `ErpRevisionGuard` | Перевыставление счёта даёт два сообщения с одинаковым `erp_updated_at` до секунды. Без гарда клиенту достанется старый PDF, и заметить это некому |
| Тип документа — enum на сайте с фолбэком «Прочее» | Неизвестный код из 1С не должен ронять документ. Исходный код и название сохраняются всегда: по ним видно, какой вид формы пора завести в enum |
| Видимость — через контрагентов клиента, не по `user_id` документа | `Company.user_id` перепривязывается 1С, денормализованный `user_id` документа при этом останется старым |

## Порядок выката

1. doc-01..02, оба флага выключены. 1С начинает слать, данные копятся, никто не видит.
2. doc-03, `DOCUMENTS_CRM_ENABLED=true` на dev. Менеджеры сверяют типы, номера, содержимое
   PDF. Метрика качества привязок — доля строк с `company_id IS NULL`.
3. Первичная выгрузка истории из 1С.
4. doc-04, `DOCUMENTS_ENABLED=true` на dev, затем на прод.
5. Отдельной задачей — подписки на новые документы.

## Критерии готовности эпика

- [ ] Контракт согласован со стороной 1С, схемы и AsyncAPI 16.1.0 опубликованы
- [ ] 1С выгружает печатные формы, очередь `erp_dlq.printed_documents` пуста
- [ ] Менеджер видит документы своих клиентов в CRM и может их скачать
- [ ] Клиент видит документы всех своих контрагентов и скачивает их из кабинета
- [ ] Доля документов без контрагента (`company_id IS NULL`) — ноль после `documents:relink`
- [ ] Интеграционные тесты покрывают приём, перевыставление, удаление и обгон ревизий
