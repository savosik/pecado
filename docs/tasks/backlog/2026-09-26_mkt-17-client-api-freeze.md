# mkt-17. Клиентский API и MCP: не трогаем контракт, подтверждаем, что не сломалось

**Приоритет:** средний · **Создано:** 2026-09-26 · **Переписано:** 2026-10-03 · **Волна:** 4 · **Эпик:** mkt-00
**Оценка (ориентир):** 0,5 дня («почти даром» по концепции)

## Описание

Решение заказчика (26.09, подтверждено 03.10): **клиентский API v1 и MCP на первом этапе не меняются**.
При тонкой модели это почти бесплатно: источник истины по остатку и цене не меняется (`product_warehouse`
остаётся суммой, цена — прежними каналами), а строка заказа без `offer_key` обрабатывается 1С как сегодня.

API продолжает отдавать товар с одним остатком (сумма по складам региона) и одной ценой; продавца и ставку
через API не раскрываем. Заказ через API уходит без ключа — продавца и партию выбирает 1С.

Задача — доказать тестами, что поведение не изменилось, и записать в документацию API, что продавец и ставка
в v1 не отдаются (на будущее — отдельная поставка по просьбе клиентов).

## Критерии готовности

- [ ] Контракт `/api/client-api/*` не изменился, OpenAPI прежний
- [ ] Тесты API зелёные без правок ожиданий (или правки объяснены в карточке)
- [ ] Заказ через API создаётся без `offer_key` и уходит в 1С как сегодня
- [ ] Журнал `client_agent_calls` и экран `/crm/agent-usage` работают как прежде
