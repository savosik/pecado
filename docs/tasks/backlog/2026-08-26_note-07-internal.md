# note-07 — внутренние уведомления

**Эпик:** `note-00`

## Задача

«Менеджеру о новом заказе», «вопрос с сайта сотрудникам», «недобор РОПу» —
не свойство партнёра, в матрицу не влезают.

Им нужен **простой список** «событие → сотрудники», а не движок. Разница
принципиальна: список читается глазами, движок требует прогона.

## Как

Раздел настроек с одной таблицей: тип внутреннего уведомления → сотрудники
или роль. Адресаты — те же типизированные объекты, что в матрице
(`{"type":"manager"}`, `{"type":"email"}`), плюс роль сотрудника.

Сегодняшний фолбэк `MAIL_ORDER_FALLBACK_RECIPIENTS` из переменной окружения
переезжает сюда: адресаты внутренних писем не должны требовать релиза.

## Проверка

- вопрос с сайта уходит указанным сотрудникам;
- письмо менеджеру о заказе уходит персональному менеджеру клиента,
  а при его отсутствии — в фолбэк;
- пустой список не роняет отправку, а пишет предупреждение в лог.
