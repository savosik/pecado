# task-08: тосты-напоминания на всех страницах CRM, перенос из тоста

**Приоритет:** средний
**Эпик:** [task-00](2026-08-17_task-00-epic.md)
**Зависит от:** task-03 (перенос), task-05 (общий каунтер-поллинг)
**Создано:** 2026-08-17

## Описание

Задача «выскакивает» тостом на любой странице CRM, когда наступает её срок,
появляется просрочка или задачу назначили/поставили на контроль. Из тоста можно
перенести или открыть. Вебсокетов в проекте нет — polling по образцу присутствия
(`PresenceController`, 45 с).

### Reminder-контур (общий для тостов, писем, push)

```php
Schema::create('crm_task_reminder_logs', function (Blueprint $table) {
    $table->comment('Лог напоминаний по задачам: защита от повторов на всех каналах');
    $table->id()->comment('Первичный ключ');
    $table->foreignId('task_id')->comment('Задача (crm_tasks.id)')->constrained('crm_tasks')->cascadeOnDelete();
    $table->foreignId('user_id')->comment('Получатель (users.id)')->constrained('users')->cascadeOnDelete();
    $table->string('kind', 30)->comment("Повод: 'due' — срок наступил, 'overdue' — просрочена, 'assigned' — назначена, 'watch' — событие по контролю");
    $table->string('channel', 20)->comment("Канал: 'toast', 'push', 'mail'");
    $table->timestamp('sent_at')->comment('Когда отправлено');
    $table->unique(['task_id', 'user_id', 'kind', 'channel'], 'crm_task_reminder_once');
});
```

Уникальный ключ — идемпотентность: один повод — одно напоминание в канал.
Перенос срока (task-03) чистит записи `kind=due/overdue` по задаче — после
переноса напоминание сработает заново к новому сроку. Существующий крон
`crm:tasks-remind` переводится на этот же лог (вместо «окна в сутки»),
поведение писем не меняется.

### Polling-эндпоинт

`GET /crm/notifications/poll` — один запрос на всё «живое»: счётчик меню
(task-05) + порция непоказанных напоминаний актора (задачи с наступившим
`due_at`, свежая просрочка, новые назначения, события контроля). Сервер сразу
пишет лог `channel=toast` — это решает дедупликацию между вкладками: вторая
вкладка уже не получит ту же запись. Интервал — конфиг `config/crm.php`
по образцу `CRM_PRESENCE_POLL` (60 с), без экспоненциальных изысков.

### Тост

Компонент в общем CRM-лейауте (там же, где Toaster уже смонтирован):

- Заголовок «Задача: {title}», подзаголовок — повод («срок наступил»,
  «просрочена», «вам назначена», «закрыта с проблемой» для контролёра).
- Кнопки: **Открыть** (deep-link `?task=ID`) и **Перенести** — меню пресетов
  «+1 час / завтра / выбрать дату», зовёт `postpone` из task-03; «выбрать дату»
  открывает диалог.
- Не автозакрывается для `due`/`overdue` (duration: null) — напоминание, которое
  исчезло за 5 секунд пока менеджер говорил по телефону, не напоминание;
  информационные (`assigned`, `watch`) закрываются сами.
- Максимум 3 тоста разом; если поводов больше — один сводный «И ещё N задач →
  открыть раздел». Утро понедельника не должно засыпать экран.

### Границы

Тосты живут только в CRM-лейауте (админку и кабинет не трогаем). Никаких
настроек частоты в UI в этой карточке — сначала пожить с дефолтами.

## Критерии готовности

- [ ] Миграция лога с комментариями; `db:comments:audit --strict` чист; `bi:sync-grants`
- [ ] Тост появляется на любой странице CRM при наступлении срока (без перезагрузки), повторно — не появляется, во второй вкладке — не дублируется
- [ ] Перенос из тоста двигает срок (счётчик, комментарий) и после нового срока напоминание срабатывает снова
- [ ] Сводный тост при >3 поводах; due/overdue не автозакрываются
- [ ] `crm:tasks-remind` переведён на общий лог, письма не задваиваются (тест двойного прогона)
- [ ] Один polling-запрос обслуживает и счётчик меню, и тосты
- [ ] Feature-тесты (идемпотентность, сброс при переносе, права); UI на русском; браузерная проверка на dev
