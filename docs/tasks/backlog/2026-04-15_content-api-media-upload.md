# Добавление загрузки Media файлов в Content API

**Приоритет:** средний
**Исполнитель:** -
**Создано:** 2026-04-15

## Описание

В Content API (группа роутов `prefix('content')` в `routes/api.php`), которое используется ИИ-агентом (контент-менеджером), отсутствует возможность загружать статичные файлы (картинки, видео). Необходимо добавить новый эндпоинт, который будет принимать файл, сохранять его (с помощью Spatie MediaLibrary или напрямую в Storage) и отдавать `public` URL. 

Этот URL затем должен нормально открываться снаружи, так как он будет вставляться в статьи в формате HTML-тегов (`<img src="...">`).

Кроме того, после добавления логики контроллера необходимо обновить OpenAPI/Swagger документацию проекта (для пакета `dedoc/scramble` и т.д.).

## Критерии готовности

- [ ] Создан новый контроллер `MediaController` (или `UploadController`) в неймспейсе `App\Http\Controllers\Api\Content\`.
- [ ] Добавлен роут (например, `POST /api/content/media`) в `routes/api.php` внутри группы `content` (защищенной `auth:sanctum`).
- [ ] Написана валидация загружаемого файла (проверка на допустимые mimetype (картинки/видео) и размер).
- [ ] Файл обязательно должен сохраняться в S3/MinIO хранилище (диск `s3`), чтобы к нему был сквозной публичный доступ.
- [ ] Ответ контроллера содержит поле с абсолютным публичным URL (например, `{"url": "https://..."}`).
- [ ] Оформлены правильные phpdoc-аннотации для того, чтобы `dedoc/scramble` корректно сгенерировал документацию по API.
- [ ] Swagger/OpenAPI спецификация обновлена (автоматически или посредством команды экспорта), изменения закоммичены.
