# mail-05 · Письма из заказов и документов

**Приоритет:** высокий
**Создано:** 2026-08-21
**Эпик:** [mail-00](2026-08-21_mail-00-epic.md)
**Зависимости:** [mail-03](2026-08-21_mail-03-rules.md)
**Оценка:** ~2 дня

## Описание

Наполняем поток. Система начинает складывать в «Черновики» письма по поводам,
которые уже умеет распознавать.

| Повод | Метки письма |
|---|---|
| Изменился состав заказа | `заказ`, `состав-изменён`, `недобор` если есть выбывшие |
| Смена статуса заказа | `заказ`, `статус:закрыт` и т.п. |
| Оформлен заказ | `заказ`, `новый-заказ` |
| Опубликован документ | `документы`, `акт-сверки` / `упд` / `счёт` … |

Плюс общие метки: ИНН, контрагент, партнёр, поля профиля клиента.

## Что переиспользуется

Сборщики данных из отменённого эпика (`app/Notifications/Pulse/Events/**`) умеют
собрать содержимое — их работа сохраняется. Меняется только результат: вместо записи
в таблицу сигналов создаётся черновик письма.

## Текст письма

Шаблон на каждый повод, менеджер правит перед отправкой. Иначе автоотправка
невозможна в принципе — см. открытый вопрос в эпике.

## Защита от лавины

Два предохранителя из прошлого эпика сохраняются, они себя оправдали:

- **возрастной ценз**: повод старше N минут письма не порождает — первичная выгрузка
  истории из 1С не должна залить «Черновики» тысячами строк;
- **склейка**: 1С правит заказ построчно, поэтому серия правок одного заказа за короткий
  срок даёт одно письмо, а не десять.

## Критерии готовности

- [ ] Письма по четырём поводам падают в «Черновики» с метками
- [ ] Шаблон текста на каждый повод; менеджер может править
- [ ] Возрастной ценз: тест на давнем документе
- [ ] Склейка серии правок одного заказа в одно письмо
- [ ] Пока правил нет, письма просто лежат в «Черновиках» и никуда не уходят
