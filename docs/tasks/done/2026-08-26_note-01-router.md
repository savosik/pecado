## Что делаем

**Таблица `notification_preferences`** — только отклонения от умолчания:

| Колонка | Смысл |
|---|---|
| `user_id` | партнёр (users.id) |
| `occasion_key` | тип уведомления из `config/mail_occasions.php` |
| `is_enabled` | «не присылать это вообще» = false |
| `destinations` json | список типизированных адресатов |
| `options` json | доп. настройки типа (пока только статусы) |
| `changed_by_client` | правил ли клиент сам — в CRM показывается бейджем |
| `updated_by_user_id` | кто менял последним |

UNIQUE `(user_id, occasion_key)`. Комментарии на русском обязательны —
`db:comments:audit --strict`.

**Формат адресата** — объект с полем `type`:

```
{"type":"login"}                              на почту аккаунта
{"type":"contact_role","role":"accountant"}   контактам с ролью
{"type":"contact","contact_id":123}           конкретному человеку
{"type":"email","email":"buh@romashka.ru"}    произвольный адрес
{"type":"manager"}                            персональному менеджеру
```

**Умолчания — в `config/mail_occasions.php`**, рядом с самим уведомлением:
`default_destinations`, `default_enabled`, `client_visible`. Добавил
уведомление — сразу указал умолчание; расхождению неоткуда взяться.

**`app/Services/Notifications/NotificationRouter.php`** — единственная точка
ответа на «кому»:

```php
public function destinationsFor(Occasion $occasion): array
```

Внутри: настройка партнёра или умолчание → раскрытие каждого адресата в адреса.

## Что переносим, а не пишем заново

`MailRuleEngine::resolve()` и `roleEmails()`
(`app/Services/Crm/Mail/MailRuleEngine.php:188-241`) уже умеют четыре из пяти
типов. Переносим целиком, включая `Contact::deliverable()`, который отсекает
отписавшихся.

**Добавляем два**: адресата `contact` по идентификатору и сужение роли
до контрагента письма через `Occasion::$companyId` — сегодня роль ищется
по партнёру, и у партнёра с тремя юрлицами письмо уходит всем бухгалтерам.

Из `MailAutoSender` переносим стоп-лист, ограничение частоты и `LegacySenders`
(защиту от дубля с зашитыми листенерами).

## Проверка

`tests/Feature/Notifications/NotificationRouterTest.php`:

- умолчание применяется, когда строки нет;
- отклонение перекрывает умолчание;
- `is_enabled=false` даёт пустой список;
- каждый из пяти типов адресата раскрывается верно;
- роль сужается до контрагента письма, когда `companyId` задан;
- отписавшийся контакт в выдачу не попадает;
- адрес из стоп-листа отсеивается;
- при живом зашитом листенере того же повода роутер молчит.
