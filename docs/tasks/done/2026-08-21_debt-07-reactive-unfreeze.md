## Описание

Сейчас финансовый контур полностью плановый (`mail:finance-scan` раз в сутки),
обработчики `settlement.posted` / `payment.created` / `balance.updated` Laravel-событий
не бросают. Для принципа «оплата размораживает без менеджера» этого мало.
Погашение приходит в регистр (`settled_amount` строк) — точка, где долг реально
меняется, это `SettlementProjector::projectDocument()`; `balance.updated` —
подтверждение баланса и свежести.

### Асимметрия скоростей (ядро карточки)

- **Вверх (смягчение) — мгновенно**: после записи движений регистра
  (`settlement.posted` → `SettlementProjector`) и `balance.updated` диспатчится
  доменное событие; листенер запускает пересчёт уровня клиента. Пересчёт может **только
  улучшить** уровень — понижение по событию запрещено (планово, debt-02).
- **Вниз (ужесточение) — только планово** — защита от дребезга и от ошибочного
  сообщения шины.

### Условие снятия (решение 21.08)

Просрочка упала **ниже отсечки 5 000 ₽** → ограничения сняты. Не требуем нуля:
копеечные хвосты не держат клиента в блоке. Гистерезис уровней (debt-02)
применяется и здесь.

### Удержанные заказы

Тот же событийный пересчёт отпускает заказы `awaiting_prepayment` (debt-06):
оплата по контрагенту ≥ суммы заказа или снятие уровня → заказ уходит в 1С
штатным `order.created`. Ровно один раз — идемпотентность по статусу заказа,
а не по факту события.

### «Деньги в пути»

Генерация платёжки (debt-04) открывает окно `payment_pending_days`
(стартово 2 банковских дня): в этом окне плановый пересчёт не ужесточает уровень
клиента. Ложь («сгенерировал и не оплатил») истекает сама.

### Письмо о восстановлении

Переход вверх шлёт уведомление `finance.debt_level_cleared` через `MailStream`: «Оплата получена,
ограничения сняты» — позитивное закрытие цикла, тем же клиентским контактам,
что получали предупреждения.

## Критерии готовности

- [ ] Доменные события из ERP-хендлеров платежей/балансов; сами хендлеры остаются идемпотентными (повторная доставка сообщения не дублирует пересчёт) — интеграционные тесты шины обязательны
- [ ] Пересчёт по событию улучшает уровень ≤ чем за секунды после `balance.updated`, никогда не ухудшает — тест
- [ ] Порог снятия ниже отсечки + гистерезис — юнит-тесты граничных сумм
- [ ] Окно «деньги в пути» блокирует плановое ужесточение — тест
- [ ] `finance.debt_level_cleared` уходит один раз на переход (без дублей при серии платежей)
- [ ] Ручная проверка на dev: `settlement.posted` с погашением из эмулятора 1С снимает `prepay_only` без участия людей
