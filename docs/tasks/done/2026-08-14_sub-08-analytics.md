# sub-08: аналитика недоборов и отчёт закупкам

**Приоритет:** средний
**Эпик:** [sub-00](2026-08-14_sub-00-epic.md)
**Зависит от:** волна 1 (данные копятся с неё)
**Создано:** 2026-08-14

## Описание

### Срез в /crm/analytics (для руководителя отдела, ежемесячно)

- **Скорость реакции**: медиана «отмена в 1С (`updated_at` строки) → письмо
  клиенту (`CrmEmail.sent_at`)». Целевой SLA — до конца рабочего дня.
- **Покрытие**: % отменённых строк, по которым отправлен оффер.
- **Конверсия**: офферы → согласованные; % строк, закрытых заменой;
  **спасённая сумма** — сумма заказов с `replacement_for_order_id` (точно, без
  эвристик — ради этого поле и заводилось).
- **Распределение по слоям**: какие слои реально принимаются клиентами
  (вход для тюнинга sub-06 и решения об автоотправке — фаза 3).
- **Удержание**: повторные заказы клиентов с недобором против без — ответ на
  исходный «удар по репутации» цифрой.
- Разрез по менеджерам — как в остальной CRM-аналитике (`AnalyticsContext`).

### Отчёт закупкам (еженедельно, автоматически)

Топ повторных недоборов за 90 дней (товар, число отмен, потерянная сумма,
текущий остаток, остаток поставщика) — письмом закупщику. Менеджер продаж
его не собирает и не видит как задачу; лечит запас, а не симптом.

### Витрина для ИИ-агентов

Вьюха(и) в схеме analytics по недоборам/офферам + гранты (`bi:sync-grants`) —
чтобы агент менеджеров отвечал на «какие недоборы у моего клиента».

## Критерии готовности

- [ ] Бизнес-даты — по `erp_created_at`, не `created_at` (правило аналитики проекта)
- [ ] Агрегаты проверены на локальной MySQL (only_full_group_by)
- [ ] Еженедельное письмо закупщику формируется и уходит по расписанию
- [ ] Вьюхи analytics + гранты
- [ ] UI на русском

## Заметки реализации (2026-08-15)

- Срез живёт на `/crm/analytics/shortages` (право `crm-analytics.view`), ссылки — из
  очереди недоборов и на страницу отчётов продаж. Скоуп клиентов и разрез по
  менеджерам — как в остальной CRM-аналитике (`visibleInCrm` + `crm-clients-all.view`).
- Агрегаты проверены на локальной MySQL (only_full_group_by): 87 отменённых строк за
  июнь–август, 13 повторных недоборов, топ — «Андрогерон» ×6 (сходится с данными эпика).
- **Отдельные вьюхи `v_*` для BI сознательно не заводились**: `bi:sync-grants`
  генерирует `v_*` только для таблиц с секретными колонками и **удаляет** незнакомые
  ему `v_*`-вьюхи как устаревшие. У таблиц замен секретных колонок нет — ИИ-агент
  менеджеров получает прямой SELECT на них после прогона `bi:sync-grants` (проверено:
  4 таблицы substitution_* попали в гранты, применены локально). После деплоя на dev —
  обязательный прогон `bi:sync-grants` (критерий sub-01).
- «Остаток поставщика» в отчёте закупкам заменён на «Ожидается» (preorder-склады):
  поля external_quantity в кодовой базе не существует — внешние остатки вливаются в
  общий product_warehouse (см. HandleExternalProductQuantityUpdated).
