## Описание

Сейчас `organizations` ведётся вручную: админ вбивает UUID из 1С. В модели маркетплейса
организация становится **продавцом витрины**, и ручной справочник превращается в источник ошибок.

- Приём справочника из шины, если 1С сможет отдавать (mkt-01); иначе — ручной ввод, но с
  обязательными полями и проверкой, что UUID встречался в сообщениях.
- **Торговое имя** продавца для витрины — отдельное поле, не совпадает с юрлицом
  (решение заказчика). Юрлицо видно только в документах.
- Признак «участвует в витрине» и ставка по умолчанию.
- Логотип/подпись продавца — по минимуму, без «вау-эффектов».

## Критерии готовности

- [ ] Миграция: торговое имя, признак витрины, ставка по умолчанию, комментарии на русском
