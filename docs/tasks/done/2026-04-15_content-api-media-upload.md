# Добавление загрузки Media файлов в Content API

**Приоритет:** средний
**Исполнитель:** -
**Создано:** 2026-04-15

## Описание

В Content API (группа роутов `prefix('content')` в `routes/api.php`), которое используется ИИ-агентом (контент-менеджером), отсутствует возможность загружать статичные файлы (картинки, видео). Необходимо добавить новый эндпоинт, который будет принимать файл, сохранять его (с помощью Spatie MediaLibrary или напрямую в Storage) и отдавать `public` URL. 

Этот URL затем должен нормально открываться снаружи, так как он будет вставляться в статьи в формате HTML-тегов (`<img src="...">`).

Кроме того, после добавления логики контроллера необходимо обновить OpenAPI/Swagger документацию проекта (для пакета `dedoc/scramble` и т.д.).

## Критерии готовности

- [x] Создан новый контроллер `MediaUploadController` в неймспейсе `App\Http\Controllers\Api\Content\`.
- [x] Добавлен роут `POST /api/content/media` в `routes/api.php` внутри группы `content` (защищенной `auth:sanctum`).
- [x] Написана валидация загружаемого файла (проверка на допустимые mimetype (картинки/видео) и размер).
- [x] Файл сохраняется в S3/MinIO хранилище (диск `s3`) в директорию `content-uploads/`, с уникальным именем (ULID).
- [x] Ответ контроллера содержит поле с абсолютным публичным URL (`{"url": "https://...", "file_name": "...", "mime_type": "...", "size": ...}`).
- [x] Оформлены правильные phpdoc-аннотации для того, чтобы `dedoc/scramble` корректно сгенерировал документацию по API.
- [x] Swagger/OpenAPI спецификация обновлена (`api.json`), изменения готовы к коммиту.
