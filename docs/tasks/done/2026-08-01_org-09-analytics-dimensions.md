## Описание

Финальная карточка ценности эпика: организация должна быть **видна везде, где считают
и выгружают**. Точечное отображение в карточках документов делают `org-03`, `org-04`,
`org-06`, `org-08`; здесь — агрегаты, разрезы и выгрузки.

Отложенная карточка промо-отгрузок прямо этого и ждёт: «в отгрузках появится информация
по складу и организации, и разрезы в отчёте по продажам будут строиться уже с их учётом,
вместе с фильтрами и исключениями».

## Что делаем

**Аналитика продаж** (`ShipmentAnalyticsService`, `AnalyticsContext` — считает по
`shipment_items`, поэтому организация приходит с реализации):
- фильтр по организациям (мультивыбор, как у товаров в `/crm/analytics`);
- фильтр по складам;
- разрез «по организациям» рядом с существующим разрезом по менеджерам;
- исключения — убрать организацию из расчёта (например, «Реклама» с образцами).

**Табличные выгрузки** — организация как колонка везде, где выгружается список:
- заказы (админка, CRM), реализации, возвраты, взаиморасчёты;
- выгрузка результатов отчёта продаж;
- колонка попадает и в заголовок, и в данные; пустое значение — «не указана»,
  не пустая ячейка (в Excel пустая ячейка читается как потеря данных).

**Отчёты по взаиморасчётам** — разрез «сколько кому должны» по организациям,
с итогом по каждой.

**Списки с фильтрами** — фильтр по организации в списках заказов, реализаций,
возвратов в админке и CRM (частично делается в `org-03`/`org-04`/`org-08`, здесь
сводится к единому виду).

**Аналитические вьюхи** `analytics` для MCP-агента менеджеров расширяются полем
организации, после миграций — `bi:sync-grants`.

**Кабинет клиента.** Разрез продаж по нашим юрлицам клиенту не нужен — ему важен долг
(`org-06`). По умолчанию **не добавляем**.

## Edge-кейсы

1. **Документы без организации** — весь исторический массив. Отдельная группа
   «Организация не указана», которую **не прячем**: иначе итог разреза не сойдётся
   с общим итогом, а это классический источник недоверия к отчёту.
2. **Сравнение периодов через границу внедрения**: в старом периоде организаций нет,
   в новом есть. Отчёт обязан это подсветить, иначе выглядит как обвал по организации.
3. **Бизнес-дата** — считать по `erp_created_at` / `shipments.date`, а не `created_at`
   (`project_analytics_business_date`). Новое измерение этого не меняет.
4. **Stub-организации в разрезе** — выводить не голым UUID, а «Организация {UUID…}»
   с подсказкой «не заведена в справочнике».
5. **Промо-реализации.** С явной организацией вопрос отложенной карточки закрывается
   почти сам: `promo_sample` идёт по «Рекламе» и исключается из выручки, `promo`
   остаётся в основной организации. Продуктовое решение всё равно фиксируется там.
6. **Права.** Разрез виден админке и CRM; менеджеру отдела продаж — да, он ведёт
   клиента по всем юрлицам.
7. **Размер выгрузки** — добавление колонки не должно превращать выгрузку в N+1
   по организациям; грузить `with('organization')`.

### Решения, принятые по ходу

**«Не указана» — не заглушка, а полноценный элемент мультиселекта** (`AnalyticsFilters::UNASSIGNED`).
Документов без организации весь исторический массив, и отобрать именно их — рабочий
сценарий переходного периода. В разрезе группа **не прячется**: без неё итог не сойдётся
с общим, и отчёту перестанут верить. На это есть тест.

**Исключение организации не выкидывает документы без организации.** У них нечего
исключать, а молчаливая потеря половины истории при включении фильтра — худшее, что
может сделать отчёт. Отдельный тест.

**Вкладки разрезов появляются, только когда данные есть.** Пока 1С не присылает
организацию, вкладка с единственной строкой «Организация не указана» выглядела бы
как поломка.

**Пустое значение в выгрузке — слово «Не указана», а не пустая ячейка.** В Excel пустая
ячейка читается как потеря данных.

**Вьюхи `analytics` расширять руками не понадобилось.** `bi:sync-grants` генерирует
их из схемы: вьюха создаётся только для таблиц с секретными колонками, остальным
выдаётся прямой `GRANT SELECT`. Обе новые таблицы попали в вывод автоматически.

⚠️ Существующий тест `PermissionNamingTest` поймал реальный пробел: право
`organizations.*` было заведено в сидере, но не в группах `RoleController` — то есть
выдать его через интерфейс ролей было нельзя. Исправлено.

## Что осталось

**Сравнение периодов через границу внедрения — отменено 2026-08-11: границы не существует.**

Карточка писалась 01.08, когда 1С только начала присылать организации, и предполагала,
что исторические документы останутся без них. Замер прода показал обратное — 1С отдала
организации сразу за всю историю:

| Месяц | Реализации | Заказы |
|---|---|---|
| 2026-01 … 2026-05 | 100 % | 100 % / 99,8 % |
| 2026-06 | 100 % | 81 % |
| 2026-07 | 100 % | 98 % |
| 2026-08 | 100 % | 100 % |

Документов раньше 2026-01 в системе нет вовсе, и ни одного без `erp_created_at`.
Сравнивать «через границу» не с чем: до января данных нет, после — покрытие полное.

Провал июня (223 заказа) — не артефакт внедрения, а те самые непокрытые заказы;
это реальные данные, честно помеченные группой «не указана», и лечится вопросом
к 1С, а не предупреждением в интерфейсе.

**Колонка «Организация» в выгрузках заказов, возвратов и взаиморасчётов.** XLSX-выгрузки
есть только у отчёта продаж, реализаций ЛК и товаров; у списков заказов, возвратов
и балансов в админке выгрузки нет вообще — добавлять её было бы не «колонкой», а новой
функциональностью. Фильтр по организации в этих списках при этом есть.
