# Акты сверки в Excel в кабинет клиента раз в сутки (v16.6.0)

**Статус:** done (закрыто 22.08.2026 рукопожатием в топике Agent Hub #2, status resolved)
**Ветка:** `feature/erp-reconciliation-xlsx` (в dev и на проде с 20.08.2026, коммит `535befc6`)
**Топик Agent Hub:** [#2](https://pecado.ru/admin/agent-topics/2) — 15 сообщений, proposal → resolution

## Суть

1С раз в сутки формирует акт сверки взаиморасчётов в XLSX и присылает его каналом
печатных форм (`printed_document.published`, очередь `erp_in.printed_documents`).
Клиент видит в разделе «Документы» один всегда актуальный годовой акт по каждому
своему контрагенту.

## Итоговый контракт (v16.6.0, в бою с 21.08.2026)

| Что | Решение |
|---|---|
| Периодичность | ежесуточно ~05:00 МСК (03:00 по серверу 1С — его часы −2 ч к Москве) |
| Период | с начала текущего года по вчерашний день |
| Охват | оборот за период ≠ 0 ИЛИ остаток ≠ 0, без порога по сумме (~236 пар) |
| Разрез (ключ uuid) | организация × контрагент × валюта × **год периода** |
| Договоры | сводятся в один акт |
| Формат | XLSX; сайт принимает также XLS и PDF по сигнатуре содержимого |
| Стык года | 1 января — последний прогон за прошлый год (01.01–31.12), акт замирает полным; со 2 января новый uuid |
| Ручные акты менеджеров | публикуются клиенту наравне с регламентными (решение заказчика) |
| Месячный регламент | упразднён — точка входа удалена, задание то же, расписание ежедневное |
| Выпавшая из охвата пара | последний акт остаётся в кабинете (ничего не удаляем) |
| Контрагент без ИНН | не публикуется 1С и не принимается схемой — лечится карточками, не контрактом |

## Сделано на стороне сайта

- Спецификация spec-first: mime не PDF-only (PDF/XLSX/XLS), `period_from`/`period_to`;
  JSON Schema + AsyncAPI 16.6.0 + бизнес-правила + changelog + задание для 1С.
- `App\Enums\PrintedDocumentFormat` — формат по сигнатуре (`%PDF-`, `PK`, OLE), при
  расхождении с заявленным mime сайт верит содержимому и пишет предупреждение.
- `StorePrintedDocumentFile`: приём трёх форматов, расширение в ключе хранения,
  удаление осиротевшего файла при смене формата.
- Модель/БД: `period_from`/`period_to` (миграция с комментариями), `period_label`,
  `format`, имя скачивания с периодом и верным расширением.
- Кабинет и CRM: период и формат в списках и экспорте.
- Интеграционные тесты: XLSX с периодом, XLS, расхождение mime, смена формата без
  сироты, нераспознанный формат → rejected, кабинетный показ и скачивание.

## Сделано на стороне 1С

- Формат — свойство вида формы (не глобальный хардкод), период в сообщении.
- Регистр `Доп_АктыСверкиДляСайта` (разрез → акт): прогон трогает только свои акты;
  документ в статусе не «Создана» замирает; при неудаче обновления новый не заводится.
- Обход даты запрета точечно (`ПропуститьПроверкуЗапретаИзменения`) — сверка движений
  не делает.
- Отбор исключает внутрифирменные разрезы (контрагент = собственная организация).

## Уроки (подробнее в памяти project-recon-xlsx-daily)

- Обе главные находки всплыли только на живом прогоне, не на разборе кода: дата запрета
  и акты «сам с собой». Приёмка по фактам с обеих сторон — то, что их поймало за день.
- В кабинет уезжает ЛЮБОЙ проведённый акт сверки (подписка на 5 видах документов),
  не только регламентный — учтено, признано нормой.
