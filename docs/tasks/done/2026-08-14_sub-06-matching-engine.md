# sub-06: движок автоподбора кандидатов (слои с объяснениями)

**Приоритет:** средний (после волны 1)
**Эпик:** [sub-00](2026-08-14_sub-00-epic.md)
**Зависит от:** sub-01; потребители — sub-02 (наполнение оффера) и sub-03 (пересбор в карточке)
**Создано:** 2026-08-14

## Описание

`SubstitutionCandidateService::forOrderItem(OrderItem $cancelled): CandidateSet` —
проходит слои сверху вниз, копит до N кандидатов (старт: 4 на строку), каждый
кандидат несёт `kind`, `reason`, цену клиента, остаток.

### Сквозные условия каждого слоя

- `hidden = 0`;
- остаток (региональный, как в каталоге) ≥ недостающего количества;
  частичный кандидат допустим только у слоя 0.5 (уценка) — с пометкой «k из n»;
- **индивидуальная** цена клиента (`PriceService`) в коридоре **[−25 %; +10 %]**
  от цены отменённой строки (`final_price`); границы — конфиг.

### Слои (детально — таблица в эпике)

0. **Тот же товар вернётся**: остаток появился / `external_quantity` поставщика > 0 —
   отдаётся не как замена, а как отдельный ответ «подождать прихода».
1. **0.5 Уценка того же товара**: открытая партия `product_defects`
   (`is_published`, `price ≠ NULL`, не closed), доступность через
   `DefectStockService::available()`. Причина = «идентичный товар, уценка:
   ‹defect_description›».
2. **Подтверждённые связи** `product_substitutions` (`confirmed_at ≠ NULL`,
   `rejected_at IS NULL`), по направлению `from → to`.
3. **Варианты модели** (`model_id`), исключая generic-группы (> 10 товаров —
   слипание однословных «моделей» из 1С, см. память проекта).
4. **Линейка бренда**: общий значимый префикс названия + тот же бренд + та же
   категория (кейс Lush 3 → Lush 4 / Mini / 2 — у них `model_id IS NULL`,
   слой 3 их не ловит).
5. **Функциональный тип**: листовая категория + нормализованное головное слово
   названия («Стропа» ≠ «Ошейник» — ключевая защита от ловушки паспортных
   атрибутов); ранжирование внутри — различающими атрибутами
   (материал, основной цвет, объём, размер, питание) и близостью цены.
6. **Категория + коридор цены**, ранжирование по продажам за 90 дней.
7. **Семантика Meilisearch** (`HybridSearchOptions`, в пределах родительской
   категории) — последний фолбэк для пустых категорий (6 из 25 живых кейсов).

### Нормализация головного слова

Словарь синонимов/лемм головных слов названий (у нас их немного: топ-30 покрывает
основную массу каталога). Заводится таблицей/конфигом; ИИ-агенту можно поручить
первичное заполнение, человек подтверждает (склейка с очередью sub-07).

### Требования

- Причина (`reason`) обязательна у каждого кандидата — генерируется шаблоном слоя.
- Сервис детерминирован и быстр (вызывается при создании оффера и при пересборе
  на `InsufficientStockException`); тяжёлые куски кешируются по товару, кеш
  сбрасывается событиями остатков.
- Отладочная команда `php artisan substitutions:preview {order_item_id|product_id}` —
  показать слои и кандидатов для ручной проверки качества до включения.

### Валидация качества перед включением

Прогон по **всем историческим отменённым строкам** (93 шт.):
доля строк хотя бы с одним кандидатом, распределение по слоям, глазами проверить
топ-кейсы (Lush, стропа, лубриканты, «Андрогерон»). Результат — в карточку ревью.
Ловушка «ошейник вместо стропы» — обязательный регресс-тест.

## Критерии готовности

- [ ] Все слои реализованы, порядок и лимиты конфигурируемы
- [ ] Ценовой коридор от индивидуальной цены клиента, не от базовой
- [ ] Generic-группы model_id исключены; регресс-тест «стропа не получает ошейник первым кандидатом»
- [ ] `substitutions:preview` работает
- [ ] Отчёт прогона по 93 историческим отменам приложен к ревью
- [ ] Юнит-тесты слоёв + агрегатные запросы проверены на локальной MySQL (SQLite прячет only_full_group_by)

## Отчёт прогона по историческим отменам (2026-08-15, локальная копия прода)

Прогон `substitutions:preview --historical` по **всем 93 отменённым строкам**
(реальные остатки, индивидуальные цены клиентов заказа, локальная MySQL):

| Показатель | Значение |
|---|---|
| Всего отменённых строк | 93 |
| Без привязки к товару (рассинхрон) | 0 |
| **Есть кандидаты** | **55 (59 %)** |
| Только «подождать прихода» | 15 (16 %) |
| Пусто → ручной подбор | 23 (25 %) |

Кандидаты по слоям: functional 75, line 52, category_price 25, variant 7.
Слои linked/defect дадут вклад после наполнения справочника (sub-07) и появления партий уценки.

### Проверка топ-кейсов глазами

- **Стропа TOYFA Theatre (600 ₽)** → первым кандидатом «Стропа Anonymo #0701, 600 ₽»
  (слой functional). Ошейник в кандидаты не попал — ловушка паспортных атрибутов обойдена
  (регресс-тест `a_strap_never_gets_a_collar_as_the_first_candidate` зелёный).
- **Lush 4 (9 104 ₽)** → Lush 2 / Lush 3 / Lush Mini / Vulse линейкой (слой line),
  плюс «подождать прихода» — остаток вернулся. Эталонный кейс эпика воспроизведён.
- **JO Premium WARMING (357 ₽)** → анальные лубриканты Erotist 375 ₽ и INTIM ANAL 270 ₽ в коридоре.

### Строки без кандидатов — дефицитное ядро для sub-07

23 пустых строки концентрированы: «Андрогерон» ×8, концентраты-возбудители ×2 (уникальные
позиции без аналогов в категории и коридоре), зарядные кабели LOVENSE ×2, гели ESKA/INTIM HOT.
Это ровно тот случай, под который заведена ИИ-предразметка дефицитного ядра и ручные связи менеджера.
