## Описание

Прогон sub-06 дал 59 % строк с кандидатами, но качество подбора признано сырым.
Разбор `SubstitutionCandidateService` выявил конкретные дефекты механики —
исправляем их, не переизобретая слои.

### Лимиты и порядок слоёв

- Сейчас единственный лимит — `max_candidates_per_line = 4` **суммарно**, и цикл
  обрывается на первом наполнившемся слое: нижние слои не выполняются почти никогда,
  а уценка (`defectCandidates`) добавляется до цикла безусловно и при 4+ партиях
  выедает весь лимит.
- Сделать: квоты по слоям (конфиг, например уценка ≤ 2, верхние слои ≤ 2, нижние
  добирают до общего капа), общий кап поднять до 5–6. Слои проходятся все,
  результат собирается по квотам.
- Дедуп по `product_defect_id` (сейчас есть только по `product_id`).

### Детерминизм пулов

- `functionalPool()` и `categoryPool()` берут `limit(300)` **без ORDER BY** —
  недетерминированная выборка: два прогона дают разных кандидатов. Добавить
  устойчивую сортировку (продажи за окно, затем `id`).
- `linePool()`: `LIKE %token%` по каждому токену — проверить план запроса на
  каталоге прода; при необходимости ограничить категорией до LIKE.

### Ранжирование

- Шкалы rank между слоями несопоставимы (variant — константа 100, line — счётчик
  токенов, semantic — `1000 − index`). Внутри слоя оставить свои шкалы, но порядок
  показа определять слоем (позиционный приоритет), а rank нормировать в пределах
  слоя — чтобы UI и письмо могли честно сортировать «лучшие сверху».

### Конфиг и мелочи

- Ключ `matching.distinguishing_attributes` реально добавить в
  `config/substitutions.php` (сейчас работает только дефолт в коде).
- Тексты `waitOption()` — в конфиг/локаль, не хардкод.

### Валидация качества

Повторить прогон по историческим отменам копии прода (инструмент
`substitutions:preview` уже есть): покрытие строк кандидатами — с 59 % вверх,
глазами проверить топ-кейсы из sub-06 («Андрогерон», Lush, стропа Theatre);
отчёт таблицей в карточку. Автоотправка офферов сегменту не включается,
пока заказчик не примет качество по этому отчёту.

## Критерии готовности

- [ ] Квоты по слоям в конфиге; уценка не вытесняет остальные слои; дедуп по партии уценки
- [ ] Пулы детерминированы (повторный прогон даёт тот же список) — тест
- [ ] `matching.distinguishing_attributes` в конфиге и применяется
- [ ] Существующие тесты `SubstitutionCandidateServiceTest` зелёные + новые на квоты/детерминизм
- [ ] Отчёт прогона по копии прода в карточке; покрытие ≥ прежних 59 % и качество топ-кейсов подтверждено заказчиком
