# task-09: браузерные push-уведомления по задачам

**Приоритет:** низкий
**Эпик:** [task-00](2026-08-17_task-00-epic.md)
**Зависит от:** task-08 (reminder-контур)
**Создано:** 2026-08-17

## Описание

Web Push — чтобы напоминание догнало менеджера и с закрытой вкладкой CRM.
Дополнение к тостам, не замена: те же поводы, тот же лог
`crm_task_reminder_logs` (`channel=push`).

### Инфраструктура (в проекте её нет совсем)

- VAPID-ключи: `artisan`-команда генерации, env `VAPID_PUBLIC_KEY` /
  `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT`; фича-флаг `CRM_PUSH_ENABLED`
  (дефолт false — как все нотификационные флаги проекта).
- Пакет `laravel-notification-channels/webpush` (стандарт де-факто; проверить
  совместимость с Laravel 12 — иначе `minishlink/web-push` напрямую).
- Таблица `push_subscriptions` от пакета — миграцию опубликовать и **дописать
  комментарии** к таблице/столбцам (аудит строгий).
- `public/sw.js` — дописать обработчики `push` (showNotification: title, body,
  иконка, `data.url`) и `notificationclick` (фокус существующей вкладки CRM или
  открытие `data.url`). SW уже регистрируется в `bootstrap.js` — не дублировать.

### Подписка в UI

- Диалог «Уведомления» в разделе задач (рядом с подпиской на календарь task-07):
  тумблер «Push-уведомления в этом браузере» → `Notification.requestPermission()`
  → подписка → POST на сервер. Состояния «разрешено/заблокировано в браузере»
  показывать честно, с подсказкой как разблокировать.
- Подписка привязана к пользователю; несколько браузеров = несколько подписок.
  Протухшие (410 Gone при отправке) удаляются автоматически.
- Запрашивать разрешение **только по клику на тумблер** — никаких авто-запросов
  при входе (мгновенный «Блокировать» навсегда).

### Отправка

Крон-контур task-08 при записи повода в лог дополнительно шлёт push подписчикам
(queued notification, канал WebPush). Поводы: `due`, `overdue`, `assigned`,
`watch`. Клик по уведомлению ведёт на `?task=ID`.

### Деградация

Нет ключей/флаг выключен/браузер без поддержки — фича молчит, тумблер скрыт или
задизейблен с пояснением. Никаких ошибок в консоль на Safari старых версий.

## Критерии готовности

- [ ] Миграция подписок с комментариями; `db:comments:audit --strict`; `bi:sync-grants`
- [ ] Тумблер подписки: включение спрашивает разрешение, подписка сохраняется; выключение удаляет
- [ ] Push приходит при закрытой вкладке CRM (проверка на dev по HTTPS), клик открывает задачу
- [ ] Повод не дублируется между тостом и push у пользователя без вкладки/с вкладкой (лог един, каналы независимы)
- [ ] Протухшая подписка удаляется после 410
- [ ] `CRM_PUSH_ENABLED=false` — ничего не шлётся и UI не предлагает
- [ ] Feature-тесты отправки (мок транспорта); UI на русском; браузерная проверка на dev
