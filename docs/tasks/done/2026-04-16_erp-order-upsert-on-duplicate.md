# ERP: Upsert при повторной доставке order.created

**Приоритет:** высокий (P0)
**Исполнитель:** -
**Создано:** 2026-04-16

## Описание

При повторной доставке сообщения `order.created` (RabbitMQ retry, реконнект) обработчик падает с ошибкой дублирующегося номера заказа:

```
SQLSTATE[23000]: Duplicate entry '30??-000054' for key 'orders.orders_number_unique'
```

**Причина:** 1С при retry может генерировать новый `uuid` для того же заказа — тогда проверка по `uuid` (строка 36 `HandleOrderCreated`) пропускает её, но уникальный индекс на `number` блокирует INSERT.

**Масштаб:** 1 975 failed-сообщений в очереди.

## Требования

- [ ] Новая миграция: снять `unique` с поля `orders.number` (не редактировать существующую миграцию — на dev есть данные)
- [ ] В `HandleOrderCreated` заменить логику "пропустить если uuid существует" на идемпотентный upsert по `uuid`: при повторной доставке существующий заказ обновляется
- [ ] Покрыть интеграционным тестом: отправить одно и то же сообщение дважды → заказ один, без ошибки

## Критерии готовности

- Повторная доставка `order.created` с тем же `uuid` не приводит к ошибке и обновляет заказ
- Повторная доставка с разным `uuid` но тем же `number` не приводит к ошибке
- Интеграционный тест проходит
