# note-03 — матрица в кабинете клиента

**Эпик:** `note-00`
**Статус:** сделано 2026-08-26
**Зависит от:** `note-02`

## Что делаем

Тот же экран, что у менеджера, — в кабинете партнёра. Клиент настраивает себе
почту сам: это **главный критерий приёмки всего эпика**.

Показываем только типы с `client_visible=true`: внутренние уведомления
(вопрос с сайта, письмо менеджеру о заказе) клиенту не показываются.

Любая правка клиента ставит `changed_by_client`, в CRM это бейдж.

Образец компонента — `resources/js/components/cabinet/SubscriptionPanel.jsx`;
меню кабинета статическое (`CabinetLayout.jsx:16-73`), пункт добавляется одной
записью.

## Починка мины

`SubscriptionController::unsubscribe($token)`
(`app/Http/Controllers/User/SubscriptionController.php:194`) при отписке
от **одного** раздела пишет адрес в `NotificationSuppression` со `SCOPE_ALL` —
глушит клиенту всю почту разом.

Гущина не отказывается от актов сверки, а такая отписка отрезала бы и их.
Отписка по ссылке из письма должна выключать **тот тип уведомления**, из письма
которого пришли, а не всё подряд.

## Перенос кабинетных подписок

`EntitySubscription` (4 активные записи на проде) переносится в
`notification_preferences`: `section` → соответствующие `occasion_key`,
`destination` → `{"type":"email"}`. Сама таблица и листенер сносятся в `note-10`.

## Проверка

`tests/Feature/User/CabinetNotificationsTest.php`:

- клиент видит только `client_visible` типы;
- клиент правит только своё, чужое → 404;
- правка ставит `changed_by_client`;
- отписка по ссылке гасит один тип, остальные продолжают приходить;
- перенос 4 записей воспроизводит прежнее поведение.
