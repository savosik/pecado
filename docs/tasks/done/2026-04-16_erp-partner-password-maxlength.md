# ERP: Увеличить maxLength пароля в схеме partner.created

**Приоритет:** высокий (P1)
**Исполнитель:** -
**Создано:** 2026-04-16

## Описание

JSON Schema события `partner.created` ограничивает пароль до 8 символов (`maxLength: 8`), а 1С генерирует пароли длиной 9-10 символов. В результате 97% всех ошибок `partner.created` — это ошибка валидации пароля:

```
/password: Maximum string length is 8, found 10  →  1 230 случаев
/password: Maximum string length is 8, found 9   →    390 случаев
```

**Масштаб:** 1 620 failed-сообщений в очереди.

## Требования

- [x] В JSON Schema `partner.created` увеличить `maxLength` для поля `password` с 8 до 32
- [x] Обновить AsyncAPI-документацию
- [x] Обновить тест-план в MkDocs (если есть проверка максимальной длины пароля)
- [x] Убедиться, что на стороне сайта пароль корректно сохраняется при длине до 32 символов

## Критерии готовности

- Сообщения `partner.created` с паролем длиной 9-32 символа проходят валидацию
- Схема, AsyncAPI и документация обновлены
