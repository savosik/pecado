# sub-03: CRM-раздел «Недоборы» — очередь и карточка

**Приоритет:** высокий
**Эпик:** [sub-00](2026-08-14_sub-00-epic.md)
**Зависит от:** sub-02
**Создано:** 2026-08-14

## Описание

`/crm/shortages` в существующем CRM-домене (права по префиксу `crm-`,
роль менеджера/руководителя). Нагрузка 3–4 события в неделю — интерфейс
затачивается на «зашёл по задаче, решил за 5 минут, ушёл».

### Очередь

Список офферов со статусами, фильтр «мои клиенты» (по умолчанию) / «все».
Бейдж с числом необработанных (`pending`) — в меню CRM.
Сортировка: срочные (сумма > порога) сверху, затем по дедлайну задачи.

### Карточка недобора — всё решение на одном экране

- **Шапка**: клиент (оборот, менеджер), заказ, время отмены в 1С; предупреждение
  «посылка собрана, отгрузка скоро — письмо лучше сегодня»; история недоборов
  клиента («2-й за квартал» — повод звонить, а не писать).
- **Строки недобора**: название, количество, сумма потери.
- **Кандидаты** под каждой строкой (волна 1 — пусто, добавляются руками; волна 2 —
  предзаполнены слоями): чекбокс, цена клиента, остаток, причина. Снятие галочки
  пишет `removed_by_manager_at` + событие `manager_removed`.
- **Ручной подбор**: поиск по каталогу прямо в карточке (name/code/sku), добавленный
  кандидат получает `kind = manual` и **создаёт связь** `product_substitutions`
  (`source = manual`, `created_by` = менеджер).
- **Прогноз возврата**: остаток у поставщика (`external_quantity`) и своя дата
  прихода, если есть — для исхода «предложить подождать».
- **Черновик письма** (генерируется в sub-05) с возможностью правки.
- **Четыре исхода одной кнопкой**: Отправить подборку / Предложить подождать /
  Позвонить (фиксация итога через `CrmCall`) / Закрыть без замены (обязательная
  причина → `dismissed`).

### Статусы и «дожим» на очереди

Колонки «отправлено, не открыто», «открыто, не согласовано» — видимость воронки.
Сами напоминания и задачи дожима — sub-05.

## Критерии готовности

- [ ] Очередь + карточка на Chakra-обёртках `@/components/ui/*`, весь UI на русском
- [ ] Права: менеджер видит своих клиентов, sales-head — всех
- [ ] Ручное добавление кандидата создаёт `manual`-связь в справочнике
- [ ] Снятие галочки фиксирует негативный сигнал
- [ ] Все четыре исхода работают и переводят статус оффера
- [ ] Закрытие задачи `CrmTask` при любом исходе
- [ ] Feature-тесты контроллеров; браузерная проверка на dev
