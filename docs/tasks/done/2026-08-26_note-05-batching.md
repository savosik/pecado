# note-05 — склейка партии

**Эпик:** `note-00`
**Статус:** сделано 2026-08-26
**Зависит от:** `note-04`
**Мотив:** боевой кейс Гущиной

## Задача

1С правит заказы построчно. 24 августа в 11:22–11:23 ушло **восемь писем
за две минуты**: разом сменился статус у восьми заказов, каждый выслал своё.
25 августа поток собрал **семь писем «Готов к закрытию» за две секунды**.

С точки зрения клиента это **одно** событие — «провели партию», — а не восемь.

## Чем это не дайджест

Заказчик от дайджеста отказался осознанно, и решение не пересматривается.
Разница:

| | Дайджест | Склейка партии |
|---|---|---|
| Что собирает | разнородные события за период | одно событие, присланное построчно |
| Задержка | час, сутки | минуты |
| Читается как | «сводка за день» | «по восьми заказам сменился статус» |

## Как

Существующая склейка (`coalesce_minutes`) ключуется по заказу и пачек не видит.
Ключ расширяется до `(партнёр, тип уведомления)`: события в окне дописываются
в одно письмо со списком заказов.

Окно короткое — единицы минут. Партия 1С проходит за секунды, а ждать полчаса
с письмом о смене статуса нельзя.

## Проверка

`tests/Feature/Notifications/BatchCoalescingTest.php`:

- семь поводов одного типа за две секунды → одно письмо с семью строками;
- поводы разных типов не склеиваются;
- поводы разных партнёров не склеиваются;
- событие вне окна даёт новое письмо;
- письмо, уже отправленное, не дописывается.
