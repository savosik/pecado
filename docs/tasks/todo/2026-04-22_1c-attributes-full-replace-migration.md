# ЗАДАЧА: 1С — переход на full-replace семантику `attributes` в `product.created` / `product.updated`

**Приоритет:** высокий
**Исполнитель:** команда 1С
**Создано:** 2026-04-22
**Связано:** docs-erp changelog [13.0.0] — 2026-04-22

---

## Контекст

Сайт перешёл с merge-семантики на **full-replace** для поля `attributes` в событиях
`product.created` и `product.updated`. До v13 атрибут, пропавший из payload, оставался
у товара на сайте навсегда — это копило тихое рассогласование каталога без видимых
ошибок. С v13 сайт синхронизирует состав атрибутов товара строго по тому, что пришло
в payload.

**Источники правды:**

- Спецификация: `/docs/erp/spec.yaml` (AsyncAPI), `/docs/erp/schemas/product.{created,updated}.json`
- Бизнес-правила: `/docs/erp-guide/rules/catalog/`
- Changelog: `/docs/erp-guide/changelog/` → запись `[13.0.0] — 2026-04-22`

---

## Новая семантика

| Что в payload | Что сделает сайт |
|---|---|
| поле `attributes` **отсутствует** | состав атрибутов товара **не трогаем** (обычное частичное обновление без смены атрибутов) |
| `attributes: []` | **удалить все** атрибуты товара |
| `attributes: [a, b, c]` | синхронизировать: `a`, `b`, `c` остаются/создаются; всё остальное у товара **удаляется** |

---

## Что нужно сделать на стороне 1С

### 1. `product.created`

При создании товара передавать в `attributes[]` **полный список всех атрибутов**
номенклатуры, а не подмножество.

### 2. `product.updated` — если обновление **не затрагивает** состав атрибутов

Поле `attributes` **не передавать** (не добавлять в JSON).
Передача пустого массива `[]` теперь удалит все атрибуты товара — это не то, что
нужно при обычном обновлении `name`/`description`/и т.п.

### 3. `product.updated` — если обновление **затрагивает** атрибуты

Передавать **полный актуальный список** атрибутов товара, а не только изменённые.
Если у номенклатуры было 5 атрибутов, а изменились значения у двух, в `attributes[]`
должны быть все 5, с актуальными значениями.

### 4. Удаление атрибута у товара

Отправить `product.updated` с полным списком без удалённого атрибута. Сайт удалит
связь в `product_attribute_values`.
Массовое удаление всех атрибутов у товара — `attributes: []`.

## Критерии готовности

- [ ] 1С: при записи номенклатуры во всех случаях, когда затрагиваются атрибуты, в `product.created/updated` уходит **полный актуальный список** атрибутов товара
- [ ] 1С: при обновлении номенклатуры, не затрагивающем состав атрибутов, поле `attributes` в `product.updated` **не передаётся**
- [ ] Проверка в тестовом контуре: номенклатура с атрибутами А, Б, В. В 1С удаляем атрибут Б, записываем номенклатуру → на сайте у товара остаются только А и В
- [ ] Проверка в тестовом контуре: повторная запись номенклатуры без изменения атрибутов → на сайте состав атрибутов товара не меняется (не затирается)
- [ ] Выгрузка большого прайса (несколько тысяч номенклатур) проходит без падений с `Duplicate entry` / deadlock на стороне сайта (6 параллельных воркеров `erp_in.catalog`)

## Риски и совместимость

- **BREAKING для 1С**: если релиз 13.0.0 раскатан на сайте, а 1С продолжает слать
  merge-стиль (только изменённые атрибуты), сайт начнёт удалять непереданные —
  это приведёт к массовой потере атрибутов у товаров. Координируем релизы.
- **Порядок раскатки**:
  1. Сайт — 13.0.0 уже на dev. Прод — после подтверждения 1С.
  2. 1С — перестраивает формирование `attributes[]` по новой семантике.
  3. Синхронный релиз на прод-контур или обратная совместимость на 1С (всегда полный список) до выката сайта.
