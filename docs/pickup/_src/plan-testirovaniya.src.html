Pecado · эпик pick-00 · приёмочное тестирование

Самовывоз 9–21:
план тестирования по ролям

Проверяем весь путь заказа глазами каждого участника: магазин ставит резерв и выпускает пропуск, курьер приезжает с QR-кодом, кладовщик выдаёт, менеджер и руководитель утром видят, что произошло без них.

Как пользоваться

  • У каждой роли свой раздел. Тестировщик проходит строки по порядку и ставит отметку: да или нет.
  • Не получилось — коротко пишет в колонке «Замечание», что увидел на экране. Снимок экрана — в общий чат.
  • Строки с пометкой ★ — критичные: без них включать нельзя.
  • Роли идут в порядке жизни заказа. Клиент, курьер и кладовщик тестируют одновременно на одних и тех же заказах.

Кто тестирует

0. Ведущийготовит стенд, имитирует 1С
1. Клиентсотрудник в роли магазина
2. Курьерлюбой человек с телефоном
3. Кладовщикнастоящий кладовщик, с телефона
4. Начальник складаотмены и разбор
5. Менеджеркарточка заказа, сводка
6. Руководитель ОПсводка отдела, настройки
7. ИнтеграторAPI и ИИ-агент клиента

Где тестируем

Стенд dev.pecado.ru после слияния ветки feature/pick-pickup. На бою до приёмки ничего не включается. Телефоны — настоящие: Android и iPhone, мобильный интернет, не офисный Wi-Fi.

Что считается успехом

  • Все строки со ★ пройдены у всех ролей.
  • Кладовщик выдаёт заказ по QR не дольше чем за минуту и не больше чем в три нажатия после скана.
  • Ни на одном экране нет английских слов, обрезанного текста и горизонтальной прокрутки на телефоне.
  • Клиент ни разу не захотел позвонить менеджеру, чтобы понять, что с заказом.
Роль 0

Ведущий тестирования: подготовка стенда

Ведущий делает то, чего на стенде не делает 1С: «собирает» заказы, сдвигает время, запускает рассылки. Команды выполняются на сервере стенда в каталоге проекта.

Включить функции

PICKUP_ENABLED=true PICKUP_WMS_ENABLED=true PICKUP_HANDOVER_SINCE="2026-09-18 00:00" # дата начала тестирования ORDER_RESERVE_ENABLED=true MAIL_STREAM_ENABLED=true # иначе писем клиенту не будет

После правки .env: docker compose exec app php artisan config:cache. Права склада приходят сидером при выкладке; если роли пустые — php artisan db:seed --class=RolesAndPermissionsSeeder --force.

Имитация склада в 1С

Команда создаёт по заказу демо-ордер «ДЕМО-id» и двигает его по статусам так же, как это делает шина. На проде она отключена.

php artisan pickup:demo-step ORD-2026-0001 to_pick # склад начал сборку → у клиента «Собирается» php artisan pickup:demo-step ORD-2026-0001 shipped # собран → «Собран, ждёт выдачи» + письмо php artisan pickup:demo-step ORD-2026-0001 to_pick # откат после «собран» php artisan pickup:demo-step ORD-2026-0001 cancelled # ордер удалён в 1С php artisan pickup:demo-step ORD-2026-0001 shipped --packages=3

При создании ордера команда печатает штрихкод расходного листа — длинное число. Его кладовщик вводит вручную в поле «Лист», чтобы проверить сценарий «коробка проверена». Настоящий лист из 1С сканируется отдельно (строка С-14).

Рассылки и время

php artisan pickup:offhours-digest --dry-run # кому и сколько ушло бы в утренней сводке php artisan pickup:offhours-digest # отправить (один раз в день) php artisan pickup:remind-waiting --dry-run # кандидаты на напоминание «давно не забирают»

Письма клиенту видны в журнале /crm/emails. Чтобы проверить напоминание и «зависшие», не дожидаясь трёх дней, ведущий сдвигает у демо-ордера дату сборки:

php artisan tinker --execute="App\Models\GoodsIssue::where('number','ДЕМО-123')->update(['status_changed_at'=>now()->subDays(4)]);"

Имитация недобора

На стенде строку заказа отменяет не 1С, а ведущий — той же точкой, которую вызывает синхронизатор строк:

php artisan tinker --execute="event(new App\Events\Order\OrderItemsCancelled(App\Models\Order::find(123), [['name'=>'Массажное масло','quantity'=>2.0]]));"
