# Материалы к запуску графика склада 9–21 (эпик pick-00, карточка pick-01)

| Файл | Для кого |
|---|---|
| `buklet-klientam.pdf` | Клиенты — интернет-магазины. Страница 7 «Памятка курьеру» самостоятельная, её можно пересылать отдельно |
| `instrukciya-sklad.pdf` | Кладовщики и заведующий складом |
| `instrukciya-otdel-prodazh.pdf` | Менеджеры и РОП |
| `plan-testirovaniya.pdf` | Приёмочное тестирование по ролям: ведущий, клиент, курьер, кладовщик, начальник склада, менеджер, руководитель ОП, интегратор. 83 проверки, 32 критичные, сводный лист приёмки |

Исходники — `_src/*.src.html` с общим `_src/style.css` (A4, шрифт Jost из `public/fonts/jost/`,
фирменный бордовый). Пересборка: `bash docs/pickup/build.sh` (все) или
`bash docs/pickup/build.sh buklet-klientam` (один). Нужен системный Chrome.

## Скриншоты

Экраны резервов (`_src/img/*.jpg`) сняты с локального стенда под демо-клиентом
`pickup-demo@demo.pecado.ru` (ИП Соколова А. В., заказы ORD-2026-9019/9020) — реальных клиентских
данных в материалах нет. Пересъёмка: `npm i puppeteer-core` во временной папке, затем
`SHOTS_DIR=… node docs/pickup/_src/tools/screenshots.mjs <id резервного заказа>`.
Локально нужен `ORDER_RESERVE_ENABLED=true`.

Новые экраны (стадии, «Самовывоз», пропуск, страница курьера, экран склада) сняты 18.09.2026 на `dev.pecado.ru`
под тем же демо-клиентом и кладовщиком `wms-demo@demo.pecado.ru` после включения самовывоза на стенде;
сценарий — `_src/tools/screenshots.mjs` (переменная `BASE`). Единственный оставшийся макет — экран камеры
в инструкции склада: в безголовом браузере камеры нет.

## Что сверить перед рассылкой

- Часы, отсечка 20:00 и SLA — с `config/warehouse.php` (pick-02).
- Адрес и телефон склада — со страницей «Контакты» (сейчас: ул. Дубнинская, 75с1А; +7 (991) 584-33-90).
- Что курьер подписывает при получении — открытый вопрос эпика № 5.
- Поведение при недоборе вечером — открытый вопрос эпика № 2 (в буклете и инструкциях описан предлагаемый вариант).

## Тестирование на стенде

Склад в 1С на стенде имитирует команда `php artisan pickup:demo-step <заказ> <статус>` (на проде отключена):
создаёт демо-ордер «ДЕМО-<id>» и ведёт его по статусам так же, как шина. Порядок и команды ведущего — в `plan-testirovaniya.pdf`.
