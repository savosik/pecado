**Дата:** 17.08.2026
**Основание:** жалоба клиента на «Просрочено при нуле к оплате» + сплошная сверка
лента ↔ checkpoint ↔ график по всем 254 парам «организация × контрагент»

## Кейс, с которого началось: РУЧЕЁК ООО (ИНН 4707055724)

Клиент (личный кабинет Афониной, id 188) видит по юрлицу РУЧЕЁК ООО
«Просрочено 37 418,35 ₽» при «к оплате 0,00 ₽». Разобрали по регистру:

| Что | Данные |
|---|---|
| Реализации 08.07.2026 | 29УТ-006104 (30 838,50) + 29УТ-006105 (2 325,60) + 29УТ-006106 (4 254,25), срок оплаты 07.08 |
| Оплата 13.08.2026 | 29УТ-002661, пришла к нам **разбитой ровно по этим трём реализациям** — суммы совпадают копейка в копейку |
| Баланс по ленте | 0,00 — и ваш checkpoint по паре тоже 0,00 |
| График | все три строки так и висят с `settled_amount = 0`, на 17.08 — «просрочены» |

То есть сам платёж вы по документам разнесли (видно по разбивке оплаты), но
**погашение строк графика к нам не пришло** — ни в момент оплаты, ни за
следующие четыре дня.

**Вопрос 1.** В какой момент и каким событием 1С отправляет погашение строки
графика (`payment.schedule.updated` / `settled_amount`)? Мы ожидали его сразу
после распределения оплаты. Это разовый недосыл или в этом сценарии событие
не формируется вовсе?

**Вопрос 2.** Можно ли дослать погашения по этим трём строкам — и по остальным
аналогичным (реестр в приложении)?
